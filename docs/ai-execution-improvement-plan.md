# AI 실행 안정화 계획 — 2026-09-07

모바일·설치 경험의 후속 범위는 [공통 모바일 웹앱과 기존 단말 전환 계획](onboarding-qr-device-migration-plan.md)에 정리한다. 기존 단말 보존, 공통 PWA, QR 등록 인증, 설치 마법사·매뉴얼 및 공개판 검증을 다루며 아래 AI 실행 구현의 완료 상태와 구분한다.

후속 [실행·자동 기억 상세 계약](design/mac-runtime-saving-contract.md)은 완료 턴 관찰, AI 정리의 별도 opt-in, 통합 저장 영수증·복구, 자원 예산과 원격 실행 권한의 수명을 정의한다. [전체 구현 순서](design/README.md)에 각 작업의 선행 조건과 모델 권유가 있다. 이 추가 설계는 아래 기존 로컬 구현과 구분한다.

## 목표와 현재 증거

사용자가 프로젝트별 AI 작업을 시작·종료·재개하고, 세션 기억의 실제 저장 결과와 복구가 필요한 원인을 확인할 수 있게 한다. 작업량이 늘어도 반복 AI 호출과 메모리 사용이 불필요하게 증가하지 않게 한다.

- 현재 설치본 v396은 ad-hoc 서명이다. Developer ID 인증서와 실제 private-key 서명 canary는 검증됐다. 앱 전체 서명·공증·설치 후 실행 격리는 아직 검증되지 않았다.
- 자동 체크포인트 공정 배정·실패 기록 SQLite·비동기 세션 발견은 로컬 커밋에 있다.
- 종료된 소유자의 manual supervisor/workspace lock이 AI 실행과 일부 프로젝트 저장을 막는다. PID 종료만으로 분리된 자식 프로세스 종료를 증명할 수 없으므로 파일 삭제로 풀지 않는다.
- 터미널 저장 대기열은 WORKSPACE_LEASE_BUSY까지 영구 실패로 처리한다. 반대로 복구 필요 원인은 표시하지 못한다.
- 실패한 런타임 초기화에서 readiness 경로까지 사라져, 사용자에게 실제 복구 원인이 전달되지 않는다.
- 이 Mac CLT의 오래된 Swift 5.10 private interface와 현재 Swift 6.3.1 라이브러리 충돌이 native 빌드를 막는다. 복구 절차는 준비됐고 관리자 인증 대기다.

## 1. 원인 진단과 저장 재시도 — 로컬 구현 완료

- supervisor 준비됨/확인 불가/종료된 소유자 복구 필요를 명시한다. 초기화 실패 중에도 읽기 전용 readiness를 제공하고 원본 경로·PID·오류 문자열을 응답에 내보내지 않는다.
- 단순 앱 재시작으로 해결되지 않는 manual lock에는 관련 작업 종료 확인과 잠금 복구가 필요하다고 안내한다. lock을 자동 삭제하지 않는다.
- 터미널 자동 저장에서 일시적인 workspace 사용 중은 대기 후 재시도한다. 다른 세션의 저장 순서를 막지 않는다. 영구 실패와 복구 필요는 자동 AI 재실행을 멈추고 구분해 표시한다.
- 단일 tick 실행, 재시작 후 상태 보존, 저장 전/후 디스크 실패, 서로 다른 프로젝트의 공정성을 회귀 검증한다.

완료 조건: 실제 오류 코드가 UI까지 전달되고, busy 해제 후 저장은 한 번 완료되며 recovery-required/일반 실패는 다음 tick과 앱 재시작에서 모델을 반복 호출하지 않는다.

## 2. 대기열과 장기 자원 예산 — 로컬 구현 완료

- 원본 세션·미완료 작업을 삭제하지 않는다. 오래된 미해결 대기열은 디스크의 색인 저장소에서 필요한 행만 읽는다.
- 상태 조회는 제한된 페이지와 전체 건수를 제공한다. UI가 모든 이력을 주기적으로 내려받지 않게 한다.
- 기존 JSON은 검증·트랜잭션 기반으로 이전하며 오류·미지원 버전·심볼릭 링크는 덮어쓰지 않는다.
- 새 전역 폴러나 추가 AI 모델 호출 없이 기존 주기를 사용한다.

완료 조건: 미해결 수천 건을 보존하면서 tick은 한 건, 상태 조회는 고정 상한 내에서 처리되고, 재시작·이전 실패 시 원본 기록이 보존된다.

## 3. 실제 서명 실행과 복구 — 기기 인증 후 진행

- CLT·서명 canary 복구 → 버전·소스 검증 및 승인된 원격 반영 → 불변 소스로 native·전체 앱 production 빌드/서명 → Apple 공증/staple → 설치 검증. 구체적인 모드와 공개 snapshot 출처 계약은 [Mac 배포 상세 설계](design/mac-distribution-migration.md)를 따른다.
- 전용 계정·상호 인증 XPC·프로세스 종료 증거와 관리자 승인을 실제 설치본으로 검증한다.
- crash/reboot/승인 취소/분리된 자식 프로세스/여러 프로젝트 충돌을 재현한다. 증거 없는 task는 unknown으로 유지하고 재실행하지 않는다.
- 종료 작업을 안전하게 확인한 뒤에만 lease를 반환한다. 업데이트는 작업 drain 후 앱 번들 단위 교체로 한다.

완료 조건: 서명·공증·설치 증거와 종료/재시작 E2E가 모두 있고, 기존 production 실행 차단을 해제할 근거가 마련된다. canary 성공만으로 준비 완료를 표시하지 않는다.

## 4. 모델·추론 수준 권유 — 에이전트 지침 1차 구현 완료

`docs/model-effort-advisor-proposal.md`를 실행 정책으로 구체화한다. 관측 또는 사용자 제공 설정만 사용하고, 권유와 자동 변경을 분리한다. 장기기억 에이전트가 현재 작업 문맥으로 유지/상향/하향을 판단하며, 출처·이유·적용 단계·재평가 조건을 짧게 설명한다. 동일 단계 반복 권유와 매 턴 추가 AI 호출을 만들지 않는다.

완료 조건: 확인 불가 설정을 추측하지 않고, 일상 작업·검증된 반복 편집에는 과도한 상향을 피하며, 권한 격리·동시성 설계에는 이유 있는 검토 수준을 권유한다. 사용자 거절 뒤 같은 권유를 반복하지 않는다.

## 검증과 배포

변경 영역의 동작 테스트 후 `bun run verify`를 통과시킨다. 실제 설치본과 로컬 소스를 구분해 보고한다. GitHub Push는 요청한 승인 범위 안에서 진행하고, 공증 암호와 관리자 암호는 사용자 기기의 보안 입력란에서만 받는다. 관리자 인증 또는 배포 승인이 필요한 단계가 대기 중이어도 독립적인 구현과 검증은 계속한다.

## 이번 구현의 적용 범위

1·2단계와 4단계의 생성 지침을 로컬에 구현했다. 모델 권유는 장기기억 에이전트 v20 초기화/업데이트에 포함되며, 현재 설치된 v396 앱이나 기존 v19 스킬을 자동 교체한 것은 아니다. 3단계의 실제 privileged 실행 활성화, 기존 manual 잠금 해제, 공증·설치는 아직 대기 중이다.

독립적인 8,001행 대기열을 200회 저장 순회+128건 상태 조회한 실측은 평균 1.90ms, p95 4.32ms였다. 별도 프로세스 RSS는 워밍업 전 24.0MiB에서 후 35.8MiB였으며, 이는 수개월 실행의 무누수 증명이 아니다. 실제 프로젝트·AI를 사용하지 않는 Workroom 화면 회귀 12개 그룹과 frontend production 빌드를 통과했다.

최종 `bun run verify`: TypeScript 오류 0, Bun 3,210 pass / 0 fail, Rust 54 pass. 실제 설치본 검증과 구분해 로컬 검증으로 기록한다.
