# 작업 단계별 모델·에포트 추천

장기기억 에이전트 v29. 추천과 자동 조정 판단은 실행 중인 에이전트가 이미 가진 작업 문맥으로 작성한다. 별도 AI 평가 호출이나 백그라운드 감시는 없다.

등록 프로젝트의 **CLI는 자동(기본)·추천·OFF**, **외부 앱은 추천(기본)·OFF**를 제공한다.
실행 도구에서 두 설정을 따로 저장한다. 워크룸·cmux·Orca·iTerm·Terminal의 CLI 자동 모드는
검증된 현재 세션의 제어로만 실제 강도를 바꾸고 결과를 다시 확인한다. 앱은 지침·장기기억을
읽은 활성 에이전트가 추천하며, 실제 모델·에포트 설정을 바꾸지 않는다.
에포트 변경은 자동 ON의 허용 범위이며, 수동 선택도 다음 요청·단계 판단에서 다시 조절할 수 있다. 고정 강도는 OFF로 선택하고 모델·제공자·계정은 보존한다. 외부 호스트는 `createProjectAgentTerminal` 또는
`ProjectAgentEffortController`로 연동한다. SDK의 `surface: 'desktop'`은 네이티브 제어가 있더라도
추천·OFF만 허용하고 별도 `desktopMode()`를 읽는다. 기존 CLI 설정 파일 이름은 유지한다.

Hermes 워크룸에서 시작 에포트를 전달할 때는 `chat --cli --reasoning`을 사용한다. 사용자의 `display.interface=tui`를 그대로 물려받으면 현재 Hermes가 `--reasoning`을 거절해 시작 전에 종료하기 때문이다. 이 실행만 classic CLI로 열고, 저장된 인터페이스·모델·제공자·계정은 바꾸지 않는다. 시작 에포트가 없으면 기존 인터페이스 선택을 그대로 따른다.

CLI 설정은 `workroom-effort-auto.json`, 앱 추천 설정은 `desktop-effort-advice.json` v1의
`mode: recommend | off`다. CLI의 legacy boolean 저장도 앱 선택을 덮어쓰지 않는다.
일반 기억 회상에 `includeEffortAdvice: true`를 함께 요청하면 이 실행 호스트의
`effortAdvice.cliMode`, `desktopMode`, `desktopControl: advice-only`를 제공한다.
기존 회상 응답 형식은 그대로 유지한다. 읽기 도구가 있는 에이전트는 작업 시작·단계 전환 때
해당 작은 설정 파일만 최대 4096 bytes 읽는다. 별도 감시·추가 AI 호출·설정 파일 쓰기는 없다.
다른 호스트에서 실행한다면 그 호스트의 값을 사용한다. 연결 정보·파일 접근이 없으면 앱은
추천을 기본으로 삼되 설정을 확인했다거나 자동 적용했다고 말하지 않는다.

공통 지침이나 프롬프트 훅은 네이티브 설정 API가 아니다. 외부 앱과 연동되지 않은 CLI에는 추천만 전달되며,
실제 자동 변경 완료로 표시하지 않는다. Codex의 UserPromptSubmit은 추가 developer 문맥을 지원하지만
에포트 변경 필드는 제공하지 않는다([공식 문서](https://learn.chatgpt.com/docs/hooks#userpromptsubmit)).

## 언제 말하는가

미선택 모드에서는 아래 추천 안내를 생략한다. 연동되지 않은 환경의 추천은 설정 변경을 뜻하지 않는다.

- 중요한 계획·설계·작업을 시작할 때 한 번: 이번 작업의 추천 방향과 이유를 짧게 안내한다. 여러 단계면 어려운 구간과 에포트를 낮출 조건을 함께 적는다.
- 계획 → 구현 → 검증 → 인계 전환, 새로운 불확실성이나 반복 실패가 생겼을 때 다시 판단한다. 추천이 그대로면 매 답변마다 반복하지 않는다.
- 대표 검사가 통과하고 반복 확인만 남으면 낮출 시점을 안내한다. 사용자가 현재 설정을 유지하면 그대로 작업한다.
- 간단한 질문·사소한 편집에는 추천 머리말을 붙이지 않는다. 로그인 창, 의존성 누락, 네트워크 장애, 큰 토큰 수만으로 상향을 권하지 않는다.

예: 지원 환경이 확인된 경우 “지금은 medium을 권합니다. 핵심 연결 검증은 끝났고 반복 UI 점검이 남았습니다. 인증 복귀 문제가 새로 나오면 다시 검토하겠습니다.”

## 에이전트별 전달

| 표면 | 생성·갱신 위치 |
|---|---|
| Claude | 기기 `~/.claude/CLAUDE.md`, 프로젝트 `CLAUDE.md`와 `project-memory` 스킬 |
| Codex | 기기 `~/.codex/AGENTS.md`, 프로젝트 `AGENTS.md`와 `project-memory` 스킬 |
| Antigravity(agy) | 기기 `~/.gemini/GEMINI.md`, 프로젝트 `.agents/rules/agentstoz-output-style.md` |
| Hermes | 실제 설치가 감지된 경우 기기 `SOUL.md`; 장기기억 어댑터 설치·갱신에서도 같은 규칙 적용 |
| 앱 없는 환경 | 복사하는 장기기억 초기화 프롬프트에 같은 규칙 포함 |

기기 공통 지침은 새 앱 API 시작 시 갱신한다. 프로젝트 지침·스킬은 초기화 또는 ‘장기기억 에이전트 업데이트’로 갱신한다. 관리 마커 안의 규칙만 바꾸고 기존 사용자 지침·persona·장기기억 본문은 보존한다. 이미 열린 대화가 파일 변경을 언제 다시 읽는지는 각 도구에 달려 있으므로 새 대화 또는 해당 도구의 지침 재로딩 이후 적용을 확인한다.

## 추천의 한계와 기억

앱별 조사 근거와 채택 범위는 [외부 앱 에포트 조사](external-app-effort-research.md)에 정리했다.

Claude·Codex·Antigravity·Hermes에서 모델, 제공자, 실행 화면에 따라 조절 가능한 항목이 다르다. 특정 도구의 `medium`·`high` 등 이름을 다른 도구에 그대로 적용하지 않는다. 현재 모델·에포트는 런타임 메타데이터 또는 사용자가 알려준 값만 신뢰한다. 미확인 설정을 읽었다고 말하지 않으며 지원 옵션을 모르면 높이기/낮추기 방향으로만 안내한다.

이 기능은 에이전트 지침이며 앱이 모든 답변에 추천을 강제로 삽입하는 제어기가 아니다. 실제 추천 이행은 각 에이전트가 지침을 읽고 따르는 데 달려 있다. 회귀검사는 모든 전달 표면의 동일 규칙, 업그레이드·반복 실행 시 중복 없음, 기존 지침·기억 보존을 확인한다.

세션 기억에는 검증된 작업·검사·결과의 재사용 가능한 교훈만 남긴다. 매 턴 추천 로그·대화 원문을 쌓거나 지금의 설정을 영구 취향으로 고정하지 않고, 측정 없이 비용 절감이나 특정 모델 덕분의 성공을 주장하지 않는다.
