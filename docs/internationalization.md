# 앱 언어

앱의 공통 화면은 `src/i18n.ts`의 한국어·영어·일본어·중국어 간체·스페인어·프랑스어·독일어 카탈로그를 사용한다. 첫 실행은 한국어이며 브라우저 언어를 보고 사용자의 명시적 선택을 바꾸지 않는다.

`useAppLanguage()`는 동일 창과 다른 창의 변경을 구독한다. 저장소 쓰기 실패 시 현재 창의 선택을 유지하며, 나중에 열린 패널과 음성 요청도 같은 언어를 읽는다. 저장 실패는 언어 선택기에 표시한다. 새로고침 뒤 유지할 수 있다는 보장은 쓰기 성공 때만 한다. 다른 창에서 설정을 지우면 한국어로 돌아가며 `sessionStorage`의 같은 이름은 무시한다.

UI 문구에는 `t(language, key, {query, count})`를 사용한다. 각 언어의 키는 TypeScript로 검사하고, 자리표시자 일치는 테스트로 검사한다. 번역 결과를 React 상태에 저장하지 않고 키와 데이터를 저장한 뒤 렌더링 때 번역한다. 프로젝트명·경로·사용자가 입력한 기억·호스트가 반환한 진단 원문은 번역하지 않는다.

숫자·날짜는 `appLocale()`, `formatProjectCount()`, `formatLastRun()`을 사용한다. 새로운 화면에 `language === 'ko' ? ... : ...`를 추가하면 나머지 다섯 언어가 영어로 표시되므로 카탈로그 키를 추가한다.

## 현재 검증 범위

공통 탐색 메뉴·프로젝트 종류·검색 안내·시간/개수·앱 외형/브라우저/저장소 설정 안내·기기 기억 화면의 문구와 언어 상태를 검증한다. 실행 옵션의 CLI/외부 앱 에포트 안내, 작업 루트의 순서·새 폴더·목록 제거, 모바일 화면 테마도 7개 언어를 사용한다. 프로젝트 상태 묶음·브라우저 문맥·조회 묶음·근무 모드 문구도 7개 언어이고, 블록마다 한국어 키 집합을 타입으로 강제한다(`CopyShape`, `tests/feature-copy-language.test.ts`). 조회 묶음이 가리키는 「자주 쓰는 프롬프트」 패널 자체는 아직 한국어다. 언어 변경은 에포트 모드·테마·루트 연결을 변경하지 않는다. 기존 상세 기능 전체의 번역 완료를 뜻하지 않는다. 프로젝트 생성·편집, 초기 설치 마법사, 워크룸 세부 도구, CLI 계정의 고급 설정, 원격 포털의 세부 관리 화면 등에는 기존 고정 문구가 남아 있다. 서버 진단의 구조화된 오류 코드와 사용자용 번역도 별도 확장이 필요하다.

## 검사

- `bun run typecheck`
- `python3 scripts/agentstoz-maintainer.py run --root . --profile quick`
- `python3 scripts/agentstoz-maintainer.py personas run --root .`

언어 관련 검사는 타입 검사, 카탈로그·저장 실패·로캘 단위 검사, Chromium/WebKit의 실제 프로젝트 shell 및 설정 창, 1280/390/320px 기기 기억 화면을 실행한다. 격리 호스트를 사용하며 설치 앱·실제 iPhone·실제 음성 제공자 연결은 증명하지 않는다. 워크스페이스 도구는 Chromium/WebKit과 1000/390/320px에서 긴 안내의 줄바꿈, 에포트/테마 보존, 원래 루트 ID로 전달되는 동작을 검사한다. 일반 `quick`에도 공통 shell 언어 검사가 포함된다.
