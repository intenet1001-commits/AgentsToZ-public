# Codex 앱 첫 대화 실패 — 조사 및 수정 범위

2026-09-13. Control의 `테스트 요청 확인` 작업 기록에서 신규 actionfollow 프로젝트의 MCP 앱 열기 실패와 데스크톱 ‘처음 열기’ 실패가 별도로 확인됐다. 이후 Codex 앱 도구로 별도 대화를 생성한 것은 우회 성공이며 원래 기능의 수정 증거가 아니다.

## 확인된 두 단계

1. `agentstoz_use_open_code_app`에는 첫 실행 mode가 없었다. 호스트가 `/api/open-code-app`에 mode 없이 전달하므로 기존 대화가 없는 프로젝트는 거부된다.
2. UI의 `prepare` 경로는 프로젝트 선택 뒤 `CODEX_DESKTOP_COMPOSER_NOT_READY`로 실패했다. 고정 연결 확인 문구가 들어 있는 포커스된 AXTextArea를 찾는 자동화 단계다. 어느 조건이 실제 Codex 버전과 맞지 않는지는 아직 실기 확인하지 못했다.

## 소스 변경

- MCP에 Codex 전용 선택형 `mode: reopen | prepare`를 추가했다. 기본값은 기존 동작이며 메시지를 자동 전송하지 않는다. `prepare`는 사용자가 첫 대화를 요청한 경우에만 사용하며, 기존 대화가 없을 때 고정된 도구 없는 연결 테스트 메시지를 보낸다. 임의 첫 프롬프트 전송 기능은 아니다.
- MCP와 호스트 양쪽에서 mode를 검증하고 다른 에이전트의 prepare를 거부한다. 첫 대화 확인의 대기 시간보다 짧았던 MCP 기본 제한 대신 prepare에는 150초를 적용한다.
- 기존 prepare의 중복 방지·정확한 프로젝트 검증을 그대로 사용한다. Codex 오류 코드를 보존하고 실제 준비/재열기 모드 및 표시 확인 여부를 반환한다.
- 회귀 테스트에서 mode가 유실되던 실패를 확인한 뒤 수정했다. 기존 열기에는 첫 메시지 권한을 추가하지 않는다.

## 남은 검증

컴퓨터 사용 도구가 `com.openai.codex` 접근을 안전상의 이유로 거부했다. 다른 UI 자동화 수단으로 이를 우회하지 않는다. 입력창 조건을 추측해 완화하거나 Enter를 무조건 보내지 않았다.

Codex UI 접근이 허용되는 환경에서 전용 시험 프로젝트로 프로젝트 선택 → 고정 초안 표시 → 해당 초안 전송 → 정확한 새 대화 및 응답 → 실패 후 중복 없는 재시도를 실증해야 한다. 별도 `create_thread` 성공, CLI/워크룸 응답, 단위 테스트 통과는 이 실증을 대체하지 않는다. 설치 앱과 MCP 재시작 반영도 별도이며 이 소스 변경만으로 설치 완료를 주장하지 않는다.

## 공식 계약 확인

[OpenAI 명령·딥링크 문서](https://learn.chatgpt.com/docs/reference/commands#chats)는 `path`가 작업 폴더를, `prompt`가 입력창의 초기 문구를 지정하며 딥링크가 문구를 자동 전송하지 않는다고 명시한다. 따라서 URL 열기 성공만으로 첫 메시지 전송을 완료 처리할 수 없다. 입력창 감지 실패 안내에 정확한 프로젝트와 문구 확인, 직접 전송 후 연결 상태 재조회 절차를 추가했다. 자동 전송 자체가 복구됐다는 뜻은 아니다.
