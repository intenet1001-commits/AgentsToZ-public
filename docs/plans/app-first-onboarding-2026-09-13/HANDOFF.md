# 클릭과 AI 인계문으로 개인 환경을 만드는 순서

상태: UX·실행 계약 제안. 현재 앱에 아래 버튼과 자동화가 모두 있다는 뜻이 아니다.
1차 대상은 사용자 소유 Supabase + Google OAuth + Vercel + Mac/iPhone 조합이다.
대화에 제시된 개발자의 실제 프로젝트 식별자는 여기에 쓰지 않는다. 신규 사용자는 본인의 대상을 고른다.

## 1. 화면은 다음 한 단계와 같은 작업의 진행을 보여준다

```text
내 작업 공간 준비                           3 / 7
AI 도우미 연결                              확인됨
자료를 보관할 Supabase 프로젝트 선택         지금 할 일

기존 프로젝트가 있으면 그대로 사용할 수 있어요.
[기존 프로젝트 선택] [새로 만들기]

AI에게 이 단계를 맡기려면
[안내문 복사] [ChatGPT 열기] [Claude 열기]

진행 내용은 이 앱에 저장됩니다. 나중에 돌아와도 이어집니다.
[나중에 이어 하기] [상세 상태]
```

완료 버튼을 사람이 누르는 방식 대신 앱이 지원되는 사후 검사를 한다.
외부 서비스에 API가 없는 상태는 `화면에서 확인됨`으로만 보관하고 실제 로그인/조회로 결과를 다시 검증한다.
모든 목록이 비어 있어도 `아직 연결하지 않음`, `조회 중`, `조회 실패`, `연결됐지만 프로젝트 없음`을 구분한다.

## 2. S0~S9 — 설치부터 휴대폰 첫 작업까지

| 순서 | 사람의 동작 | 앱/AI가 처리할 일 | 통과 증거 |
|---|---|---|---|
| S0 배포 앱 받기 | 검증된 Mac 배포 채널에서 설치·열기 | 버전·CPU·현재 OS 계정·로컬 실행 확인 | 소스 Clone 없이 앱이 실행됨 |
| S1 AI 도우미 준비 | ChatGPT 또는 Claude 선택·공식 로그인·필요한 도구 연결 승인 | 공식 설치 안내, 이미 설치된 앱 재사용, 로컬 bridge 확인 | 앱 존재/로그인/bridge 결과가 따로 표시됨 |
| S2 목표·설치 목록 | `현재와 같은 개인 작업 공간 만들기` 선택, 필요한 AI/클라우드 도구 준비 승인 | 하나의 run/설치 계획 저장, 누락 도구만 순차 준비, 인계문 생성 | 재부팅 후 같은 단계·대상으로 재개 |
| S3 GitHub | 계정 로그인, 필요한 경우 저장소 소유/이름/공개 여부 선택 | CLI/API 인증 확인, 필요한 코드 사본/Control 저장소 작업 | 정확한 계정/저장소 ID·권한과 작업 결과 확인 |
| S4 Supabase | 계정/조직 로그인, 기존 프로젝트 선택 또는 생성 조건 확인 | 지원 API/브라우저로 준비, 정본 DB 스키마·owner membership·연결 검사 | 올바른 고객 DB, 스키마, 익명 차단, 허용 owner 접근 확인 |
| S5 Google 로그인 연결 | Google 계정·Cloud 프로젝트 선택, 동의 화면 정보·필요한 보안 입력 | OAuth web client 준비 안내, callback 산출, Supabase provider 설정 지원 | 아래 세 구간을 검증한 뒤 실제 로그인 성공 |
| S6 Vercel 포털 | 계정/팀·프로젝트 선택, 배포 확인 | 공개 배포 패키지에 본인의 공개 연결값 바인딩, 배포, callback 등록 지원 | 선택 팀의 Production Ready + 실제 페이지 응답 |
| S7 이 실행 환경 등록 | `이 Mac · 사용자 계정` 표시 이름 확인 | 새 UUID·로컬 인증·DB 등록, 기존 ID 보존, 확인용 동기화 | 다른 실행 환경과 분리된 행, 실제 read/write 성공 |
| S8 프로젝트·Control·CLI | 작업 루트 선택, 첫 프로젝트 또는 Control 선택, 첫 작업 시작 | 등록·기억 초기화·선택 AI 실행·결과 읽기·저장 상태 표시 | 실제 응답·다시 열기, 선택한 기억 저장 결과 확인 |
| S9 iPhone 연결 | TestFlight 설치, QR 스캔, 필요한 Google 로그인, Mac 코드·권한 승인 | 연결 origin/공간/호스트 확인, 목록 자동 갱신, 재연결 | 외부망에서 해당 프로젝트 조회·CLI 입력/응답·종료/저장 |

이미 준비된 S3~S6은 readback 후 건너뛴다. 로컬 목표는 S3~S7을 필요할 때만 진행한다.
GitHub 계정은 비공개 저장소/Push/소스 연결 배포를 선택할 때 필요하다. 모든 설치의 필수 계정으로 만들지 않는다.
추가 Mac/OS 계정은 S4~S6의 기존 공간을 재사용하고 S7에서 새 실행 환경을 등록한다.
새 사용자는 개발자 계정을 재사용하지 않는다. 같은 Google 이메일이라는 이유로 다른 서비스의 인증을 추정하지 않는다.

## 3. Google OAuth의 세 연결을 화면에서 구분

```text
1. Google Cloud의 OAuth 웹 클라이언트
   승인된 redirect URI = 선택 Supabase의 /auth/v1/callback
                   ↓
2. Supabase Authentication의 Google Provider
   Client ID·Client Secret 설정 + provider 활성화
                   ↓
3. Supabase의 앱 복귀 주소
   실제 Vercel Production origin/지원되는 앱 callback 등록
                   ↓
실제 Google 로그인 → 원래 앱/포털로 복귀 → 회원 권한 → 프로젝트 조회
```

Google Cloud 프로젝트 ID/프로젝트 번호는 OAuth Client ID가 아니다.
앱은 선택한 Supabase에서 정확한 callback을 만들고 공식 화면의 값과 비교한다.
Vercel URL을 Google의 Supabase callback 대신 넣도록 안내하지 않는다.
Google 계정 로그인, Cloud 프로젝트에 대한 편집 권한, Google Provider 설정 완료도 별도 상태다.
동의 화면의 audience/test-user 상태, 요청 scope, 승인/검증이 필요한 경우의 안내를 공식 현재 절차에 맞춰 보여준다.
Supabase Redirect URL과 native OAuth의 정확한 state/callback 검증을 유지한다. 로그인 실패를 wildcard 확대나 RLS 해제로 해결하지 않는다.

공식 Google/Supabase 설정에는 Client Secret 전달이 포함된다.
검증된 API를 통한 비밀 전달은 로컬 인증 도우미에서만 처리하고 UI/AI에는 `설정됨` 결과만 제공한다.
지원 API가 없어 사람이 공식 설정 화면의 보안 입력을 해야 하면 그 단계만 안내한다.
이 경우 사용자의 '인계문 외 복붙 0회' 기준은 아직 통과하지 못한 것으로 기록한다.

## 4. 복사되는 인계문 예시

앱이 현재 상태에 맞춰 생성하는 템플릿이다. 아래 참조는 예시이며 실행 가능한 token/도구 호출이 아니다.
지원되는 로컬 bridge를 준비하지 못한 AI에는 설정 방법 안내만 요청한다.

```text
AgentsToZ의 개인 작업 공간 설정을 이어서 도와줘.

목표: 내 Mac에서 AI 작업을 하고, 내 Supabase와 Google 로그인 및 Vercel 포털로
iPhone에서도 프로젝트를 보고 원격으로 이어서 작업하기.

환경: 설치 앱. AgentsToZ 소스 Clone·Bun·Rust 설치는 기본 조건이 아님.
진행 참조: 앱이 생성한 비밀 없는 설정 작업 참조
현재 단계: Google 로그인 연결 준비
확인된 단계: AI 도우미 연결, Supabase 프로젝트 선택
대기 단계: Google 로그인 실제 검증, Vercel 배포, 모바일 연결

먼저 AgentsToZ의 로컬 연결 도구로 같은 실행 환경과 최신 준비 상태를 확인해 줘.
기존 프로젝트와 계정을 우선 사용하고, 내가 승인한 설치 목록의 남은 단계만 진행해 줘.
로그인·2FA는 공식 화면에서 내가 처리하게 하고, 비밀번호·토큰·Client Secret은
채팅에 복사하거나 읽어 달라고 요청하지 마.
새 리소스/비용/공개 여부 등 결정이 필요하면 실제 대상과 영향을 보여줘.
외부 작업이 중간에 끊겼으면 먼저 결과를 조회하고 중복 생성하지 마.
단계별 결과는 앱이 재검사할 수 있게 알려줘. 도구 연결이 없으면 앱의 다음 버튼을 안내해 줘.
```

run 참조에는 명령/비밀을 포함하지 않는다. 환경·공간·recipe·revision이 맞는 호스트의 기존 승인만 사용할 수 있다.
프로젝트 ID 같은 비밀이 아닌 정보도 외부 AI 전달 전 미리보기에 나타내고 불필요하면 생략한다.
AI 대화가 길어지거나 제공자를 바꾸면 앱에서 `이어서 진행할 안내문 복사`를 다시 생성한다.
이전 대화 전문을 복사하지 않고 완료 단계·미확정 작업·다음 단계만 넘긴다.

## 5. 설치 이후 관리 인계

| 사용자 요청 | 연결 센터의 처리 |
|---|---|
| 다른 Mac 추가 | 기존 공간의 공개 연결 정보 발급, 새 OS 환경에서 인증·새 ID·단일 등록 확인 |
| CLI가 안 됨 | 설치 경로/버전·인증·권한·작업 오류 분리, 실패 단계만 재검사 |
| 계정을 바꾸고 싶음 | 현재 팀/프로젝트와 변경 대상을 비교, 동작 중 작업 영향 표시, 인증 세대 갱신 |
| 포털 업데이트 | 검증된 새 artifact와 현재 공간을 결속, 배포 결과 확인, 로그인/모바일 회귀 검사 |
| 모바일 목록이 안 뜸 | auth/회원/목록 캐시/원격 승인 단계를 분리하고 read만 재시도 |
| 잠시 멈춤/재부팅 | 진행 영수증 보존, 다음 실행 시 상태 확인부터. 로그인/생성 자동 반복 없음 |
| 기억 저장 | 현재 모델/동의/Keychain/저장 결과 확인, 로컬 저장과 백업을 따로 표시 |

## 6. 지원·배포 문구의 조건

`누구나 TestFlight에서 다운로드`는 App Store 공개 검색과 다르다. 외부 테스터 초대/공개 링크,
Beta App Review, 지원 OS/기기와 현재 빌드 사용 가능 상태를 갖춘 뒤 안내한다.
내부 테스트 계정에만 배포된 것을 외부 신규 사용자 배포 완료로 설명하지 않는다.
실기에서 확인된 경로만 `클릭으로 준비`로 표시하고 미지원 자동화에는 다음 행동을 명시한다.

근거: [Supabase Google 로그인 설정](https://supabase.com/docs/guides/auth/social-login/auth-google),
[Apple 외부 테스터 초대](https://developer.apple.com/help/app-store-connect/test-a-beta-version/invite-external-testers).
