# 모바일 작업 공간 구현 기록

2026-09-11. 기준 소스 v434 이후 변경. 설계 전체의 운영 검증 완료를 뜻하지 않는다.

v438 이후 네이티브 진입 개선과 이 Mac의 실제 시뮬레이터 검증은 [NATIVE-EXECUTION.md](NATIVE-EXECUTION.md)에 별도로 기록한다. 아래 ‘다른 Xcode 단말의 후속 작업’은 최초 구현 당시의 환경 판정이다.

## 구현한 범위

- 기존 포털과 외부 원격 화면의 진입점을 새 작업 홈으로 통일했다. 홈·프로젝트·워크룸·북마크·기록 탭은 같은 연결 객체 안에서 이동한다. 기존 포털 자료와 장기기억 화면도 내부에 유지한다.
- 테마는 헤더의 아이콘 메뉴에서 기기 설정·밝은 화면·어두운 화면을 선택한다. 모바일 하단 탐색과 데스크톱 탐색 배치를 구분한다.
- 프로젝트의 주 동작은 워크룸 이어 하기다. 실행 중인 같은 프로젝트 세션을 먼저 찾는다. Mac 앱·폴더 열기는 보조 메뉴로 이동했다. 기존 프로젝트 생성, Git pull/push/merge, 워크트리 생성 동작을 재사용한다.
- 내가 한 말은 등록한 프로젝트의 기존 수집·조회 경로를 사용한다. 외부 feed 발급이나 외부 공유 활성화가 필요하지 않다. 긴 기록은 동일 내용 해시를 확인하며 나누어 읽고, 워크룸 입력 초안으로 가져온다. 자동 전송하지 않는다.
- 실제 세션 기억 저장을 기존 수동/자동 저장 dispatcher와 lease에 연결했다. 승인된 접수 후 휴대폰 연결이 끊겨도 호스트 작업은 계속하며, 프로젝트의 등록·디렉터리 identity는 실행 전에 다시 검증한다. 로컬 저장과 백업 결과를 분리한다.
- 설치 Mac에 이미 설정된 프로젝트별 카톡 연결을 조회·진단하고, 자료 revision과 대화방을 확인한 뒤 대직을 켜거나 끈다. 대화방·자료의 최초 구성 편집 전체는 이번 모바일 범위에 포함하지 않는다.
- 워크트리 삭제는 실행 중 작업, 미커밋 파일, 기본 브랜치 및 마지막 조회 upstream과의 합병 상태를 확인한다. 5분짜리 검토 토큰을 정확한 디렉터리와 Git 상태에 결속하고 삭제 직전에 다시 확인한다. 강제 삭제나 브랜치 삭제는 하지 않는다.
- `workspace-v1`을 지원하는 호스트에만 관리 기능을 연다. 기록 읽기·기억 저장·대직 관리·워크트리 관리의 네 권한은 기존 연결 권한과 별도다. Mac의 워크룸 연결 설정에서 프로젝트와 권한을 선택해 적용한다. 기존 등록 기기에 자동 확대하지 않는다.
- iOS WK 화면은 같은 다섯 탭을 선택하고 연결 설명을 접는다. 등록된 HTTPS 주 프레임에 한해 카메라 권한 요청을 허용하도록 구현했다.

## 검증 근거

- 최종 `bun run verify`: TypeScript 오류 0, Bun 4,064 pass / 0 fail, Rust 56 pass / 0 fail. 이 Mac의 활성 Xcode가 미초기화되어 `DEVELOPER_DIR=/Library/Developer/CommandLineTools`를 지정했다. 격리 테스트 두 곳도 명시된 개발 도구 경로만 전달하도록 수정했다. 시스템 Xcode 선택이나 라이선스 동의는 변경하지 않았다.
- 설치 빌드의 네이티브 도구 환경도 명시된 `DEVELOPER_DIR`만 전달하도록 보완했다. `build:macos-runtime-native` 실제 컴파일과 harmless fixture가 통과했다. 이 결과는 개발용 ad-hoc 보조 도구 검증이며 Developer ID 공증이나 특권 서비스 설치의 완료를 의미하지 않는다.
- Chromium/WebKit에서 모바일 390px, 20회 내부 탭 이동 중 document 요청 1회, 세 가지 테마, 기존 장기기억 링크, 가로 넘침을 확인했다.
- 별도 UI fixture로 긴 발언 전체 읽기, 초안만 생성, 저장 요청 1회, 로컬 저장/백업 구분, 확인 후 대직 켜기를 검증했다. 실제 AI 호출이나 카카오톡 전송 시험이 아니다.
- 독립 Git 임시 저장소에서 한글 경로, 변경 파일·미합병·실행 중·Git 상태 변경·다른 요청자 거부, 정상 정리와 브랜치 보존을 검증했다.
- 권한 누락·다른 프로젝트·읽는 도중 권한 회수, 저장 재전송·재시작 중복 방지와 휴대폰 연결 종료 후 저장 완료를 검증한다.
- iOS Foundation 기반 핵심 검증과 Bun/URLSession 연결 검증은 이 Mac에서 실행했다. SwiftUI/WKWebView 카메라·수명·실제 단말 화면 검증과 앱 서명은 다른 Xcode 단말의 후속 작업이다.

## 후속 검증 및 현재 한계

- 실제 승인된 휴대폰과 설치 앱에서 원격 기록 조회 → 기존 세션 이어 하기 → 기억 저장 → Git 반영의 통합 시험이 남아 있다. 실제 카카오톡 수신·응답도 별도 실기기 시험이 필요하다.
- LAN 서버는 새 보호된 작업 프로토콜을 지원하지만 기존 LAN 전용 정적 화면은 새 외부 포털 홈과 완전히 통합하지 않았다.
- 저장 상태는 이 모바일 연결에서 요청한 저장의 영수증이다. 프로젝트 전체 자동 저장 이력 대시보드를 대체하지 않는다. 미확정 저장은 자동 재실행하지 않으며 Mac의 기존 복구 절차로 확인한다. 모바일 전용 영수증 복구/정리 UI는 후속 작업이다.
- 저장 영수증 최대 128개, 실행 중 모바일 저장 1개다. 한도에서는 새 요청을 거부하며 원본 기억이나 미확정 영수증을 삭제하지 않는다.
- 원격 기본 브랜치 조회를 포함한 기존 Git merge와 별도 push를 유지한다. GitHub PR 심사/머지의 전체 모바일 화면을 새로 구현한 것은 아니다.
- 이미 등록된 동일 호스트의 새 QR을 스캔하면 기존 연결을 선택한다. 만료된 연결의 QR 교체 흐름은 기존 연결 해제 후 재등록으로 처리한다.
- 호스트가 꺼졌을 때 전체 로컬 기록 읽기, Windows 대직 지원, 모바일 최초 자료/RAG 설정 편집은 후속 범위다.
