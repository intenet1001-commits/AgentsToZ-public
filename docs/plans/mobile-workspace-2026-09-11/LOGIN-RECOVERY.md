# 모바일 로그인 복구와 상단 여백

v436 휴대폰 화면에 나타난 오류는 저장된 세션 확인이 아니라 Google 로그인 전
`/auth/v1/settings` 사전 요청의 8초 제한이었다. 점검 시 실제 서버는 정상 응답했으므로
사진만으로 휴대폰 네트워크, 서버 지연, 브라우저 문제 중 하나를 원인으로 확정하지 않는다.

## 수정

- 로그인 실패의 `로그인 다시 시도`는 OAuth 사전 요청부터 다시 실행한다. 기존 버튼은
  저장된 세션만 확인해 오류를 지우므로 실제 실패한 단계를 재시도하지 않았다.
- 연결 확인의 시간 초과/네트워크 오류에서만 사용자가 `Google 로그인 페이지로 이동`을
  선택할 수 있다. 사전 확인만 생략하며, 정확한 Supabase authorize URL·PKCE·Google 인증·
  DB 회원 권한 검사는 그대로 적용한다. 비활성 Google provider, 잘못된 설정/응답에는
  이 선택을 제공하지 않는다. 자동 페이지 이동이나 자동 로그인 초기화는 하지 않는다.
- 사전 확인 제한은 응답 헤더뿐 아니라 JSON 본문 읽기까지 포함한다. 중복 클릭은
  같은 화면의 PKCE 흐름을 겹쳐 시작하지 않는다.
- 계정 자료 탭도 네이티브 인증 bridge가 있으면 기존 시스템 인증 창을 사용한다.
  QR 워크룸과 같은 원칙으로 WKWebView를 유지한다.
- 상단은 safe-area에 추가 여백을 더하고, standalone 세로 화면의 0 inset 복원에도
  최소 여백을 둔다. 고정 배경이 스크롤되는 내용을 상태 표시줄 아래에서 가린다.
  내부 로그인 카드의 전체 화면 높이·중복 안전 여백을 제거하고 버전 배지를 일반 흐름에 둔다.

## 검증 범위

- Chromium/WebKit: 사전 요청 시간 초과 → 실제 재시도 성공, 네트워크 실패 → 명시적
  직접 이동, Google 비활성 → 직접 이동 없음, 네이티브 인증 창 취소 → 같은 문서 유지.
  모든 실패에서 자료·세션 보조 키 보존, 중복 클릭 시 요청 한 번을 확인한다.
- 320/390px에서 가로 넘침 없음. 44px inset fixture의 추가 여백, 스크롤 중 고정 배경,
  버전 배지 배치를 확인한다. headless WebKit의 inset fixture는 실제 iPhone 상태
  표시줄이나 설치 웹앱 재개를 재현했다는 뜻이 아니다.
- 기존 인증된 프로젝트 현황과 기기 전환·공통/레거시 북마크 회귀를 유지한다.
- 실제 Google 계정 입력·동의 완료, 사용자의 휴대폰 네트워크와 설치 웹앱 복귀는
  별도 실기기 확인 대상이다.
- 최종 `bun run verify`: TypeScript 오류 0, Bun 4,069 pass / 0 fail, Rust 56 pass / 0 fail.
  첫 전체 실행에서 기존 대용량 prompt-guide HTTP 테스트가 5초 제한을 넘었으며,
  코드·테스트 조건을 바꾸지 않은 단독 실행과 전체 재실행은 통과했다.
