# 프로젝트 현황과 원격 작업 분리 제안

2026-09-11 · v435 사용 화면 피드백 반영 · 승인 후 구현 · 소스 검증 완료

사용자 확정 요구: 북마크는 기기에 종속되지 않는다. 원격 연결이 없어도 기존처럼 기기를 선택해 동기화된 프로젝트 현황을 볼 수 있어야 한다. 아래 명칭·탭 재배치는 사용자의 진행 승인에 따라 구현하며, 기존 DESIGN.md의 탐색 구조를 보완한다.

## 명칭과 탐색 구조

권장 명칭은 **프로젝트 현황 / 원격 작업**이다. ‘프로젝트(뷰어)’는 읽는 도구라는 표현에 치우치고, 현재 제공하는 메모·링크 등 계정 정보 관리까지 설명하기 어렵다. ‘프로젝트 현황’은 확인 목적을, ‘원격 작업’은 연결한 Mac·PC에서 실제 개발·관리를 수행하는 목적을 드러낸다. 워크룸은 원격 작업 안의 AI 세션 화면 이름으로 유지한다.

하단 탭은 `홈 | 프로젝트 | 원격 작업 | 북마크 | 기록`의 다섯 개를 제안한다. 프로젝트 탭의 화면 제목은 ‘프로젝트 현황’이다. 기존 ‘워크룸’ 탭을 ‘원격 작업’으로 확장하고, 기존 프로젝트 탭 안에서 섞였던 계정 목록과 연결된 호스트 작업을 두 탭으로 분리한다. 여섯 번째 하단 탭을 추가하지 않는다.

| 화면 | 범위와 기기 선택 | 원격 연결이 없을 때 |
|---|---|---|
| 홈 | 전체 작업의 진입점. 현황 확인과 원격 작업 이어 하기를 구분 | 동기화 자료와 마지막 확인 결과를 표시. 원격 등록 안내는 해당 카드 안에만 표시 |
| 프로젝트 현황 | ‘조회 기기’를 선택해 저장된 프로젝트·폴더·링크·메모·확인 가능한 상태 조회 | 계정 인증과 데이터 조회가 가능하면 사용. QR 등록을 요구하지 않음 |
| 원격 작업 | ‘작업 기기’를 선택해 해당 호스트의 프로젝트·워크트리·Git·대직·워크룸 실행 | 기존 조회 결과는 마지막 확인 시각과 함께 유지. 실행에는 연결 필요를 명시 |
| 북마크 | 본인이 접근 가능한 공통 북마크·분류·검색·관리 | 호스트 연결과 무관하게 사용. 계정 데이터 오류와 원격 연결 오류를 혼동하지 않음 |
| 기록 | 장기기억은 기존 계정 조회 범위, 내가 한 말은 현재 지원하는 등록 호스트 조회 범위 | 장기기억 조회는 원격 연결 상태로 막지 않음. 내가 한 말의 호스트 의존성은 해당 화면 안에서 안내 |

원격 연결 불필요는 휴대폰의 인터넷·로그인까지 불필요하다는 의미가 아니다. 동기화하지 않은 로컬 변경을 볼 수 있다고 약속하지 않는다. 오프라인 캐시가 있는 범위만 시각과 출처를 표시해 제공한다.

## 화면 변경

### 공통 헤더와 북마크

- 공통 헤더는 앱 이름·현재 화면 제목·화면 설정을 중심으로 한다. 기기명과 연결 상태가 모든 화면의 제목을 대신하지 않는다.
- 북마크에서 ‘연결 준비’, 연결 호스트 칩, ‘기기 추가·QR 스캔’, 프로젝트 기기 선택기를 제거한다. 검색·분류·추가가 본문 상단에 바로 나온다.
- QR 스캔과 연결 관리는 원격 작업에 둔다. 홈에서는 ‘작업 기기 연결’ 카드로 진입한다.
- 북마크의 ‘계정 자료 설정’은 역할에 맞게 ‘북마크 설정’으로 정리한다. 계정·기기 관리 기능이 필요하면 공통 설정으로 연결한다. 북마크 설정에 조회 기기와 브라우저 기기 ID를 함께 설명하는 구조는 해소한다.
- 로컬 폴더·파일 바로가기가 있다면 북마크 목록 소속과 여는 위치를 구분한다. 목록은 공통으로 유지하고, 필요한 항목의 열기 동작에서만 실행할 기기를 확인한다.

### 프로젝트 현황

- 현재 ‘계정에 저장된 목록’을 이 탭의 기본 본문으로 사용한다. 현재 탭 내부의 ‘연결한 기기 / 계정에 저장된 목록’ 선택은 제거한다.
- 제목 아래에 `조회 기기 [회사 Mac ▾]`와 `마지막 동기화 …`를 둔다. 조회 기기 선택과 검색·스크롤은 기억한다.
- 프로젝트명, 폴더/워크트리 구분, 저장소·배포 링크, 메모와 이미 동기화된 장기기억/Git 정보 중 실제 확인 가능한 항목을 보여준다. 없는 필드를 임의로 채우지 않는다.
- 실행 중 여부나 Git 상태가 과거 관측이면 ‘마지막 확인 당시’로 표시한다. 실시간 제어 상태처럼 녹색 온라인 표시를 붙이지 않는다. 새로고침은 저장된 최신 자료 조회이며, 꺼진 Mac에 강제 동기화했다고 표현하지 않는다.
- 기존 이름·메모·링크 수정 등 계정 목록 기능은 유지한다. ‘목록에 등록’과 ‘기기에 프로젝트 만들기’, ‘목록에서 제거’와 ‘실제 폴더 삭제’를 구분해 원격 작업 완료로 오해하지 않게 한다.
- 프로젝트 카드의 ‘이 프로젝트에서 작업’은 검증된 기기·프로젝트 매핑이 있을 때 해당 원격 작업으로 이동한다. 이름만 같은 항목은 자동 연결하지 않는다. 매핑이 없으면 대상을 확인하게 하고 현재 현황 화면은 그대로 이용할 수 있게 한다.
- 기본은 기존 기기 선택 방식을 재사용한다. 전체 기기 통합 보기는 전체 페이지 조회·동일 프로젝트의 여러 기기 사본 구분이 갖춰진 뒤 확장하며 이번 분리의 선행 조건으로 삼지 않는다.

### 원격 작업과 워크룸

- 이 탭에 작업 기기 선택, QR 등록·복원, 실시간 프로젝트 목록·생성, 워크트리·Git·대직·기억 저장을 모은다.
- 워크룸은 선택한 프로젝트의 작업 화면으로 유지한다. 홈의 진행 중 세션과 프로젝트의 ‘이어서 작업’에서 직접 진입할 수 있어야 한다.
- 최근 사용한 원격 작업의 프로젝트/워크룸 화면을 복원한다. 매번 원격 작업 목록부터 다시 선택하게 하지 않는다.
- 조회 기기를 바꾸는 것은 작업 기기나 실행 중 세션을 바꾸지 않는다. 현황에서 명시적으로 ‘작업’으로 넘어갈 때만 대상 전환을 검토한다.
- 탭을 숨겨도 실행 중 작업·연결 소유자·입력 초안을 유지한다. 현황이나 북마크를 여는 행위 자체로 새 원격 등록이나 제어 요청을 시작하지 않는다.

## 데이터와 구현 근거

현재 소스에서 확인한 사항:

- `remote-control-portal-main.tsx`는 연결 상태·호스트 칩·QR 버튼을 공통 헤더에 렌더링한다. `catalogProjects`로 프로젝트 탭 안에 원격 목록과 계정 목록을 섞고 있다.
- `portal-main.tsx`의 공통 `portal-catalog-toolbar`가 북마크에도 프로젝트 기기 선택기를 보여준다. `PortsView`와 `RemoteProjectsView`는 이미 계정 데이터로 기기별 프로젝트를 조회하므로 재사용한다.
- `PortalManager.tsx`의 북마크·분류 저장은 `__shared__`를 사용하지만 Pull에는 선택 기기와 공유 항목을 함께 읽는 호환 경로가 남아 있다. 설정에는 프로젝트 조회 기기 정보도 전달된다.

수정 순서:

1. 탐색 상태를 ‘프로젝트 현황 / 원격 작업 / 워크룸 상세’로 정리하고, 공통 연결 소유자는 계속 상위에 유지한다.
2. 조회 기기와 작업 기기의 상태·저장 키·이름을 분리한다. 기존 실제 기기 identity와 별칭 연결 정보는 보존한다.
3. 북마크의 기기 UI를 걷어내고 조회·동기화도 프로젝트 선택에 영향받지 않게 한다. 내부 브라우저 identity나 삭제 tombstone을 UI 정리 때문에 제거하지 않는다.
4. 과거 기기별 북마크 행의 존재를 읽기 전용으로 확인한다. 존재하면 ID·수정 내용·분류·고정 상태를 보존하는 공유 전환/호환 처리를 설계한다. 단순히 조회 조건을 `__shared__`로 바꿔 기존 항목을 숨기거나, URL만 같다는 이유로 합치거나 삭제하지 않는다. 일반 화면 전환은 데이터를 이관하지 않는다.
5. 기존 프로젝트 현황 조회를 독립 탭으로 옮기고 마지막 동기화/관측 시각과 계정 메타데이터 동작을 정리한다.
6. 원격 프로젝트 관리와 워크룸을 연결하고, 기존 링크·history·네이티브 탭 선택을 호환한다. 기존 `?tab=ports`/북마크/기억 링크와 워크룸 진입 의도를 보존한다.
7. 웹 브라우저에서 검증 후 같은 구조를 네이티브 화면 연결에 적용한다. 실제 iPhone/Xcode 검증은 별도로 기록한다.

## 완료 판단

- QR를 등록하지 않은 로그인 사용자도 북마크와 기기별 프로젝트 현황을 사용할 수 있다.
- 호스트가 꺼져도 마지막 동기화 자료가 남고, 최신 상태라고 오인할 표시가 없다.
- 조회 기기를 A→B로 바꿔도 북마크 개수·분류·검색과 원격 작업 기기·실행 중 세션은 변하지 않는다.
- 북마크 화면에 원격 연결 배너·QR 버튼·기기 선택기가 보이지 않는다. 320/390px와 큰 글씨에서도 탐색·검색·추가가 잘리지 않는다.
- 현황→원격 작업→워크룸 이동의 기기·프로젝트가 정확히 일치하고, 기존 세션을 의도치 않게 새로 만들거나 입력을 덮어쓰지 않는다.
- 뒤로 가기, 새로고침, 탭 이동, 휴대폰 잠금/복귀 후 선택·초안·연결 수명 계약을 유지한다.
- 레거시 기기별 북마크가 있는 fixture에서도 항목 누락·자동 삭제·다른 접근 범위 자료의 혼입이 없다.
- 원래 검토안은 진행 승인 후 구현했다. 실제 데이터는 읽기 전용으로 확인했으며 공유 웹 북마크 75개와 예전 폴더 바로가기 6개가 있었다. 데이터 이관이나 삭제는 실행하지 않았다. 웹 공통 조회는 기존 authenticated 클라이언트/RLS 안에서 ID 순으로 최대 10,000개·8 MiB까지 페이지를 끝까지 읽고, 실패하면 기존 목록을 보존한다. 워크룸의 기존 내부 탭 키를 유지해 네이티브 탭 선택을 호환한다.
- 현황에서 작업으로 넘어갈 때 검증된 프로젝트-호스트 매핑이 없는 현재 경로는 프로젝트명을 안내하고 작업 기기/프로젝트를 직접 선택하게 한다. 이름만으로 자동 실행하지 않는다.

## 실행 검증

- 인증된 Supabase 응답 fixture를 사용하는 Chromium/WebKit에서 원격 QR 없이 프로젝트 A/B 조회, 늦은 A 응답 거부, 북마크 유지, 원격 제어 요청 0건을 검증했다. 실제 계정 자료의 쓰기나 카카오톡 전송 시험은 아니다.
- 공유/레거시 ID를 함께 포함한 1,001개 항목의 페이지 조회, 중간 페이지 실패·중복 ID·크기 초과의 보존 동작을 테스트했다.
- 320px/390px 화면, 20회 탭 전환 중 document 요청 1회, 기존 기억 링크, 시스템/밝은/어두운 테마를 검증했다.
- 네이티브는 동일 웹 화면과 기존 탭 선택 키를 재사용한다. 실제 iPhone 카메라·잠금/복귀 검증을 새로 완료했다고 주장하지 않는다.

- 최종 `bun run verify`: TypeScript 오류 0, Bun 4,067 pass / 0 fail, Rust 56 pass / 0 fail.
