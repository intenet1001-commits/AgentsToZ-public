## 구현

- 워크룸 `실행 옵션 · Bypass ON` 버튼과 기본 체크. OFF는 CLI 추가 우회 인자를 생략한다. 데스크톱은 부모 앱의 선택값, 독립 모바일 화면은 해당 브라우저 세션 선택값을 유지한다.
- 빈 프로젝트 카드 진입, 프롬프트가 있는 카드 진입, 워크룸 내부 두 시작 경로 모두 선택값을 실제 요청으로 전달한다. 실행 중 세션을 다시 여는 동작은 새 프로세스를 만들지 않는다.
- 네 CLI의 고정 인자 builder. legacy 요청의 필드 생략은 이전 동작을 유지한다. boolean 외 값과 start 이외 권한 필드는 거부한다. 시작 응답 유실 시 재시도는 최초 요청 ID와 권한 payload를 그대로 사용한다.
- 새 UI와 구버전 호스트 혼합은 strict request 오류로 멈춘다. 권한 필드를 빼고 자동 재시도하지 않는다. 응답 summary에는 필드를 추가하지 않아 구버전 응답 decoder를 유지한다. 시작 영수증 metadata 협상은 후속 범위다.
- iPhone 같은 Wi-Fi(LAN)의 별도 `remoteControlMobilePage.ts`에도 Bypass 기본 ON/OFF와 선택값 보존·실제 시작 요청 전달을 적용했다. 터미널 높이에 맞춰 PTY 행 수를 조절하고 버튼 사이에 6px 간격을 둔다.
- 모바일 visualViewport resize를 사용해 키보드가 차지한 공간을 반영한다. 기존 flex-grow가 높이 지정을 덮어쓰던 문제도 수정했다. 44px 컨트롤, 16px 입력·선택, 가로 스크롤 단축키, 하단 safe area를 적용한다.
