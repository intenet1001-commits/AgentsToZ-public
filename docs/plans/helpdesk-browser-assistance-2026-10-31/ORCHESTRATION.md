6. Codex가 변경·검사·실기 근거를 검토한 뒤 이 작업 브랜치에 통합한다. 원격 push와 설치 앱 교체는 포함하지 않는다.

## 역할과 파일 소유

**Claude Code — 구현 및 시험 조작자**

- 헬프데스크 브라우저 지원 기능, 레시피, 진행/영수증, 드라이버, gws 및 공통 온보딩 진입점, 그 회귀 검사를 맡는다.
- `helpdeskAssist*`, `HelpdeskBrowserAssist*`, Google 설정/플랫폼 CLI 계정 추가 연결, 관련 API/Tauri allowlist와 필요한 Workroom 브라우저 코어 분리를 담당한다.
- 기존 컴퓨터유즈 엔진의 `computerUse*`·`native/computer-use/` 변경은 먼저 Codex에 결함과 필요한 인터페이스를 보고한다.
- 구현은 할당된 작업 폴더/브랜치에서 한다. 혼자 작업하는 저장소가 아니므로 다른 에이전트의 변경을 되돌리지 말고 현재 변경에 맞춘다.
- 파일·기능을 임의로 줄이거나 테스트 문자열만 바꿔 통과시키지 않는다. 구현되지 않은 단계는 명시적으로 보고한다.
- 실기 조작은 실제 연결된 `agentstoz_use_computer` 또는 `agentstoz_use_computer_session`을 사용한다.
  shell·Playwright·ego API로 대신 조작한 결과를 아젠투지 컴퓨터유즈 성공이라고 보고하지 않는다.
  구현 제품의 브라우저 드라이버 시험과, 컴퓨터유즈 자체 시험은 별도 근거로 남긴다.

**현재 Codex — 관찰·검토·컴퓨터유즈 결함 개선**

- Claude의 지시 수신·실제 작업·변경 내용·검사 결과를 확인하고 구체적인 후속 지시를 전달한다.
- Claude가 조작하는 동안 `cua_repl`의 AX/화면 읽기만 사용한다. 포커스·클릭·입력은 보내지 않는다.
- 헬프데스크 기능 결함은 Claude에게 돌려주고, 컴퓨터유즈 런타임/네이티브 결함은 소유 파일을 나눈 뒤 수정한다.
- 재현된 결함만 고친다. 관찰 도구의 로컬 바인딩 오류나 지원하지 않는 접근을 앱 결함으로 기록하지 않는다.
- 통합 및 최종 검증은 실제 변경 커밋/소스와 같은 것을 대상으로 한다.

## 실기에서 무엇을 대조하는가

| 아젠투지 쪽 근거 | Codex가 보는 결과 |
|---|---|
| 선택한 앱/창, 실제 전면 앱, 디스플레이·관찰 epoch | 요청한 시험 대상이 화면에 있고 다른 사용자 창을 건드리지 않는가 |
| 관찰된 버튼·입력 요소 또는 캡처 좌표 | 화면에서 실제로 같은 대상을 가리키는가 |
| 한 requestId의 입력/클릭 | 한 번만 반영되고 중복 제출하지 않는가 |
| `confirmed` / `dispatched-unverified` / `refused` / `unknown` | 실제 화면 효과·거절·미확정과 일치하는가 |
| 사람 인수·취소·권한 철회 | 이후 입력이 멈추고 늦은 응답이 새 제어를 덮지 않는가 |
| 새 관찰·다른 창·앱 재시작·배율/좌표 변화 | 오래된 요소/권한으로 잘못 조작하지 않는가 |
| 지원 단계·로그인 작업·검사 상태 | 파일 준비/승인/실제 CLI 성공을 구분하고 같은 작업을 이어가는가 |

단계별 기록에는 시각, 소스 커밋, 시험 환경/버전, 대상, 비밀 없는 requestId와 관찰/영수증 상태,
기대 결과, Codex가 본 결과, 결함 여부, 재검사 결과를 남긴다. 토큰·JSON·인증 URL query·OTP·비밀번호는 남기지 않는다.
AI의 눈으로 본 실기 관찰은 `exploratory/observed`이며 결정적 테스트의 PASS와 구분한다.

## 실기 대상과 권한

- 아젠투지/Control 자체·자기 호스트·시스템 인증 화면은 현재 엔진의 보호 대상이다. 시험을 위해 거절을 해제하지 않는다.
- 아젠투지 UI 자체의 확인은 Codex의 별도 컴퓨터유즈에서 수행할 수 있다. Claude 조작 중에는 관찰만 한다.
- 아젠투지 컴퓨터유즈는 허용된 브라우저/시험 앱을 대상으로 확인한다. 사람 승인 전에는 입력하지 않는다.
- 2026-10-31 사전 상태: 접근성/화면 기록은 사용 가능, 컴퓨터유즈 스위치는 꺼짐, 활성 grant·대기 요청 없음.
  이는 Codex MCP 연결에서 읽은 상태이며 Claude 연결에 대한 승인 증거가 아니다.
- 실제 시험 대상과 준비된 화면을 정한 다음, 필요한 범위를 사람이 앱에서 켜고 해당 연결의 Control 승인을 직접 완료한다.
- 비밀번호·2FA·최종 OAuth 권한 승인·JSON 생성/다운로드·OS 인증은 사람에게 넘기고 관찰을 멈춘다.
- 기존 작업 세션/프로필을 로그아웃시키거나 기존 OAuth client를 지우지 않는다. 과금·외부 발송·배포는 이 시험에 포함하지 않는다.
- 다른 에이전트가 이미 제어 중이면 기다린다. 동시에 두 입력기를 사용하지 않는다.

## 개발·검사·실행 환경

- 먼저 현재 폴더의 AGENTS/CLAUDE와 관련 `docs/claude/`를 읽는다. canonical 기억만 primary worktree에서 읽는다.
- codebase-memory 그래프는 2026-10-30 생성분이다. 1619 신규 계정 전환 파일의 그래프 기록이 없으므로 coverage와 실제 소스를 확인한다.
- 현재 Codex가 프로젝트 테스터 ensure를 호출했고 결과는 `ready`였다. 같은 세션에서 중복 호출하지 않는다.
  새 Claude 실행 세션은 자기 지침의 세션당 한 번 규칙을 따른다.
- 검사는 Claude의 실제 작업 폴더에서 실행한다. 기존 테스트 실행이 진행 중이면 같은 ID 결과를 읽고 중복 러너를 시작하지 않는다.
- 정상 프로필과 구성된 persona set을 사용하고, 구현 뒤 새 여정의 체크와 후보를 기존 카탈로그에 연결한다.
- 커밋 전 저장소 필수 verify, UI 서버 import 경계용 build, 브라우저/계정/헬프데스크 집중 회귀를 수행한다.
- 최초 설치 기준은1619다. 이후 다른 작업에 의한 설치1621·1624 변경을 관찰했다(REVIEW.md). 개발 서버를 고쳐도 설치 앱의 구현이 바뀌었다고 주장하지 않는다.
- native 시험이 필요하면 작업 소스의 별도 로컬 시험 환경을 명시한다. 출하 소스 가드·서명·승인 경계를 지킨다.
  미공개 시험 패키지를 `/Applications`에 설치하거나 기존 앱/사이드카를 임의 교체·종료하지 않는다.
