# 구현 순서와 수용 검사

2026-09-14 · [설계](PLAN.md) · [계약](CONTRACTS.md)

아래 항목은 목표 수용 검사다. 실제로 실행한 검사와 미완료 범위는 [EXECUTION.md](EXECUTION.md)에 구분한다. 기존 maintainer 테스트 통과만으로 체크하지 않는다.

## 1. 순서와 완료 산출물

| 단계 | 구현 내용 | 단계 완료 조건 |
|---|---|---|
| P0 실행 연결 실증 | 새 JSON 계약, 같은 runtime 안의 테스트 호출, 독립 실행/취소/실행 ID | 중첩 lease 교착 없음. UI/MCP timeout 후 동일 run 조회. 기존 CLI 회귀 유지 |
| P1 설치·채택 | discovery, 템플릿 번들, 트랜잭션, 기존 v1.0.0 채택, Python 준비 상태 | 빈 임시 프로젝트·기존 테스트 프로젝트·소스 없는 설치 앱에서 설치/복구 확인 |
| P2 Mac 사용자 흐름 | 작은 상태 줄, 설정 화면, 프로필 선택, 실행·결과·취소 | 클릭으로 첫 검사와 실패 안내까지 완료. 카드/목록/워크트리 동작 일치 |
| P3 AI와 기억 연결 | 프로젝트 AI 어댑터, MCP, 구성·개선 핸드오프, 기억 저장 연결 | 지원 AI에서 실제 요청→검사→결과 확인. 실제 수정→재검증→기억 회상 |
| P4 업데이트·이동 | runner 업데이트, 맞춤 설정 보존, clone/Pull 채택, CI 사용 안내 | 변경된 사용자 파일 보존, 다른 Mac의 동일 테스트 구성 실행, 환경 차이는 정확히 표시 |
| P5 모바일·Control | tester capability/grant, 재연결·결과 요약, 프로젝트별 현황 | 실제 iPhone→선택 Mac→같은 run 결과. 구버전/오프라인·계정 전환 정상 |

P0~P4를 첫 출하 단위로 한다. P5가 끝나기 전 모바일에서도 tester 기능이 완성됐다고 보고하지 않는다.
작업 중에는 변경한 범위의 회귀 검사를 사용하고, 출하/커밋 전에 저장소 필수 `bun run verify`를 완료한다.
각 수용 항목은 대응하는 실제 증거가 있을 때만 완료로 표시한다.

## 2. 핵심 수용 시나리오

| T04 | 기존 maintainer v1.0.0 / 기존 사용자 AGENTS·CLAUDE 지침 | 설정 채택 및 관리 블록만 연결. 사용자 내용 바이트 보존 |

## 3. 검사 계층과 구현 파일 제안

Python 행동 회귀는 `tests/maintainer/test_maintainer.py`에 프로토콜·run ID·원자적 상태·부분 설치·호환을 추가한다.
호스트는 `tests/tester-agent-{discovery,installer,host,handoff,contract}.test.ts` 계열에서 격리 임시 프로젝트와 소유 프로세스를 사용한다.
MCP는 기존 `tests/agentstoz-use-control.test.ts` 및 신규 tester 도구 계약 회귀에서 DTO·권한·멱등성을 검사한다.
프런트는 실제 `ProjectTesterPanel`을 fixture API에 연결해 클릭·키보드·오류 복귀·접근성·좁은 화면을 검사한다.
대표 프로젝트는 Bun/npm, Python unittest, 검사 없음, monorepo/worktree, macOS/iOS 검사 보유 프로젝트를 포함한다.

fixture 테스트는 운영 API 3001, 개인 `.env`, 실제 프로젝트 내용 변경, 인증 정보 복사를 사용하지 않는다.
실제 AI 수용 검사는 격리된 등록 프로젝트에서 짧은 테스트 요청을 보내고 run ID와 결과 파일로 확인한다. 인증 상태 조회만으로 성공 처리하지 않는다.
실기기는 사용자가 연결한 기기를 inventory로 확인하며 별도 테스트 앱을 사용한다. 운영 앱을 삭제·초기화하지 않는다.

## 4. 성능과 반복 운영

- 초기 설정/검사 실행/실패 후 AI 인계의 클릭 수와 사용자가 직접 입력한 항목 수를 기록한다. 정상 상태에서 검사 실행은 한 번 클릭이다.
- status/start p50/p95, 100개/1,000개 목록 열기, 연속 100회 패널 열기·닫기 뒤 타이머/메모리 회수를 측정한다.
- 검사 시간 비교는 동일 프로필·설정·도구·환경의 성공 3회 이후 중앙값 기준으로 한다. AI 응답 속도와 분리한다.
- 성능 최적화 뒤에도 실제 검사를 생략하거나 이전 성공을 재사용하지 않았는지 확인한다.
- 발견한 결함은 재현 회귀를 남긴다. 테스터 자체 업데이트도 이 회귀와 기존 전체 verify를 통과시킨다.

## 5. 출하 기록 형식

최종 기록에는 구현 commit, 설치 앱 버전/채널, Python·테스트 도구 버전, target/worktree, 실제 run ID, 검사 범위와 생략 항목을 남긴다.
지원 표면은 `소스 회귀`, `브라우저 fixture`, `설치 Mac`, `실제 AI`, `실기 iPhone`, `실제 외부망`을 따로 판정한다.
사용자에게 다음 행동이 남아 있으면 로그인/환경 준비/미지원 배포 채널 중 확인된 이유를 적고 전체 완료로 묶지 않는다.
