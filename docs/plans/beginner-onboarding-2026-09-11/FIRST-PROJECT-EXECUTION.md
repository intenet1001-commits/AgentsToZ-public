# 첫 프로젝트 진입 구현

2026-09-11. O2의 로컬 시작 진입을 구현했다. 전체 O2 완료나 신규 고객 출시를 뜻하지 않는다.

- 실제 첫 실행/설정 메뉴의 같은 SetupWizard에 새 프로젝트, 기존 폴더, AI 준비, 등록 프로젝트
  이어 열기를 제공한다. 클라우드 상태 조회 실패나 미등록 신원은 로컬 프로젝트 시작을 막지 않는다.
- App의 기존 프로젝트 등록 화면으로 명시적으로 이동한다. Supabase onComplete를 호출하거나
  단말 ID·클라우드 설정을 만들지 않는다. 독립 setup.html은 프로젝트 콜백을 가장하지 않고
  같은 origin의 앱 작업 공간으로 돌아가는 링크를 제공하며 건너뛰기도 실제 이동한다.
- 온보딩으로 연 프로젝트 화면은 Git 초기화·새 장기기억·등록 후 서버 실행이 기본 꺼짐이다.
  기존 폴더의 지연 Git 검사도 Git 없는 선택을 다시 create로 바꾸지 않는다. 기존 Git은 유지한다.
  선택값은 사용자가 바꿀 수 있으며 일반 프로젝트 추가의 기존 기본값은 유지한다.
- 새 프로젝트 이름·GitHub URL·기억 합류 ID 등 이전 폼 값을 비우고 시작한다. 열기/닫기/새로고침은
  폴더 생성이나 AI 호출의 완료 증거가 아니다. 프로젝트 등록은 기존 ports 저장 경로가 담당한다.
- AI 준비는 앞서 구현한 영구 준비 목록으로 연결된다. AI 자동 설치·로그인 및 첫 실제 AI 작업과
  결과 영수증 연결은 후속 작업이다. 사용자 프로젝트에 시험용 AI 작업을 자동 제출하지 않는다.

검증: TypeScript, Vite 빌드, 실제 SetupWizard를 탑재한 StrictMode Chromium에서 오프라인
로컬 진입 3경로와 AI 준비 연결, 클라우드 쓰기 없음 확인. 390px 밝은/어두운 화면과 가로 넘침 확인.
실제 빌드의 App 화면을 쓰는 별도 시험은 모든 외부/API 요청을 격리한 mock으로 대체한다.
실제 파일 시스템 등록·공식 설치 앱·신규 Mac의 첫 AI 결과 검증을 대신하지 않는다.

시험 명령:
- `bun tests/onboarding-first-project-ui.mjs`
- `bun tests/onboarding-first-project-app-ui.mjs <격리 Vite 빌드 경로>`

다음: 실제 저장된 프로젝트/워크룸 작업 ID를 durable 첫 작업 증거로 연결하고, 첫 AI 설치·로그인과
실제 결과 열기까지 확장한다. 신규 OS 계정의 GitHub/Keychain 실증은 계속 출하 전 별도 조건이다.

최종 결과: 전체 verify 통과(TypeScript, Bun 4,095 pass/0 fail, Rust 57 pass/0 fail),
Vite 빌드와 두 Chromium 시험 통과. 실제 App 시험에서 폴더 등록 뒤 다시 로드한 프로젝트 ID가
같고 중복 행이 없음을 확인했다. 격리 fixture는 기존 프로젝트 숨김 안전 lease 계약도 모의하며
안전 검사를 우회하도록 제품 코드를 변경하지 않았다. 앱 설치·배포는 아직 수행하지 않았다.
