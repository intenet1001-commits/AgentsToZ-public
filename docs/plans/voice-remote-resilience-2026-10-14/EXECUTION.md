# 음성·원격제어 안정성 실행 기록

2026-10-14 · `codex/voice-remote-resilience` · 기준 `d06c23934a450ebddb7b2636db8b97b2efe1b454`

사용자 목표: AgentsToZ의 음성을 Codex보다 탁월하게 하고, 원격제어를 더 쉽고 안정적으로 완성한다.
현재 범위는 재현된 실패 경로의 구현·회귀 검사이며 제품 간 우위나 설치·배포 완료가 아니다.
[연구와 비교 기준](../../research/rea-voice-resilience-2026-10-14.md)

## 확인한 결과

- 늦은 음성 응답·caption 지원 상태 오염, Gemini 종료 이후 소비, 마지막 입력 조각 유실,
  조용한 queue 포화, 원격 사용자 입력의 배경 조회 대기와 host token 교체 시 자동 전달을
  수정 전 실패로 재현했다.
- 음성의 재개·종료 경합, 짧은 연결 복귀, 네트워크 오류 재시도 상한, 권한 거절의 즉시 종료,
  원격 입력 우선순위·조회 양보를 회귀에 포함했다.
- Gemini append/end 접수와 출력 long poll을 분리했다. 사용자 입력·명령의 자동 재시도는 추가하지 않았다.
- 관련 초기 회귀 78개, provider·host 추가 검사 48개가 통과했다. 최종 판정은 별도 로컬 영수증에 보관한다.
- 필수 `bun run verify`는 Python 119개, typecheck, Bun 6,353 pass / 10 skip / 0 fail,
  Rust 76개를 통과했다. 이후 화면 fixture의 선택자 보정은 별도 화면 검사와 최종 Quick·페르소나로 검사한다.
- 현재 설치 Codex 음성 모듈 5개의 해시 검증과 REA 정적 분석 완료. 원시 코드·대형 graph는 저장소에 포함하지 않는다.
- 프로젝트 기억 Pull은 conflict로 거절됐고 로컬 기억을 덮어쓰지 않았다. 공통기억 조회는 ready/0 hits다.
- 테스터 ensure는 프로젝트 runner가 설치 앱보다 새 버전이라 skipped. 저장소 runner로 진행한다.

최종 현재 소스 판정은 로컬 영수증에서 구분한다.

## 최종 검증

검증 명령은 Quick, `bun run verify`, 프로젝트 페르소나 검사다. Quick 안에 포함된 공통기억
4개 페르소나를 다시 실행하지 않고 나머지 12개를 같은 설정으로 검사한다. 결과 영수증은 로컬
`.agentstoz/maintainer/voice-remote-20261014/RESULT.md`에 보관하며, 이 문서 자체를 검사 중 갱신하지 않는다.

초기 Quick은 검사 중 문서 추가로 source 지문이 바뀌어 최종 통과로 인정하지 않았다.
OPS cold-start 화면 검사도 단독 재현했다. 새 테스트 구성 버튼이 프로젝트 행의 가운데를 차지해
기존 fixture의 행 중앙 클릭이 그 버튼을 누르고 있었다. 이름을 클릭해 실제 프로젝트 선택을
검증하도록 수정했고 원래 역할·기억·OPS·읽기 전용·외부 트래픽 단정은 그대로 유지했다.
SDK 화면의 같은 행 중앙 클릭도 같은 방법으로 고쳤다. SDK·CS 대직 패널의 전환·빈 화면·모바일
되돌아가기 검사는 그대로 유지한다.

실제 유료 음성, 물리 iPhone, 개인 인터넷 relay, 상대 Codex의 비교·설치본 반영은 이 로그의 통과로
주장하지 않는다. 기존 대화 복원의 C/D/E 후속 범위와 실측 완료 기준은 연구 문서를 따른다.
