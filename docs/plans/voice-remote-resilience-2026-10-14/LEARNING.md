# 교정·실패를 다음 작업에 반영하기

2026-10-14 · 사용자가 선택한 우선순위는 사용자 교정과 실패 원인의 재발 방지다.
음성·원격 안정성 작업에 이어 같은 변경 집합에서 구현한다.

## 동작

등록 프로젝트의 장기기억 화면에서 `교정·실패 기억하기`를 열고 기존 항목을 검색한다.
사용자가 실패 원인과 다음 처리 방법을 제출하면 현재 memoryId·명시적 entryKey·본문 버전에
묶인 교정을 기존 append-only feedback 원본에 저장한다. 동일 내용 재전송은 같은 영수증을
복구한다. 현재 본문이 달라진 새 교정 요청은 거절하며, 이미 저장한 요청의 영수증은 복구한다.

다음 `/api/project-memory/recall`은 해당 버전의 원래 주장을 `hits`에서 제외하고 `corrections`에
보고된 원인·다음 처리를 반환한다. 교정 원인에만 있는 단어로도 검색할 수 있다. 정상 기억과
교정 검색의 결과 상한을 별도로 유지하므로 교정 때문에 정상 항목의 제한을 소비하지 않는다.
교정 파일을 읽을 수 없으면 현재 지침 회상을 보류하고 `correctionSearch.complete=false`와 경고를 반환한다.
별도로 검증된 과거 일지는 계속 조회할 수 있으며 원래 지침을 확정 사실로 재사용하지 않는다.
음성 프로젝트 회상에도 같은 경고가 전달된다. 버전 27의 생성 project-memory 지침은 직접 읽은
이전 노트보다 해당 경고를 우선 확인하도록 안내한다. 앱 없는 환경의 복사 지침도 교정 원인·대안과
검증된 지식을 구분한다. 새 앱과 지침의 설치·업그레이드는 별도다.

## 매시간 점검

실행 중인 API의 기존 60초 유지보수 tick에서 등록된 프로젝트를 한 번에 최대 8개씩 순환한다.
대상 ID·등록 경로·부모 프로젝트가 같은 성공 대상은 1시간 내 재점검하지 않고, 읽기 실패는 다음 순환에서 재시도한다. 동시 tick은 하나로
합치고 종료 시 새 점검을 중단한다. 기억이 없는 대상은 생성을 시도하지 않는다. 공유 OPS 정본은
기존 사람 검토 경계를 유지한다. 점검 결과는 현재 본문의 재사용 보류, 본문 변경 후 검증 필요,
버전 결속이 없는 과거 기록의 수를 구분하며 장기기억 화면에서 조회할 수 있다.

프로젝트 원본·교정 근거를 지우거나 자동으로 바꾸지 않는다. 최대 128개 점검 결과만 버릴 수 있는
메모리 캐시에 둔다. 재시작 후에는 첫 순환부터 다시 점검한다. 대규모 대상·절전·앱 종료 시 정확한
정시 실행을 보장하지 않는다. 새 근거가 없으면 새 지식을 만들어 내지 않는다. 유료 AI 호출, 원문
대화 수집, 모델 가중치 학습, 자동 저장 V2의 동의·호출 상한 변경은 이 기능에 없다.

## 검증 기준과 한계

교정 이후 회상, 실패 원인 검색, 동일 요청 재전송, 본문 변경, 다른 memoryId 격리,
긍정 자기평가 차단, 공유 OPS 우회 거절, 시간·배치·동시 tick·읽기 실패를 계약 검사로 확인한다.
Chromium/WebKit에서 실제 컴포넌트의 제출·응답 유실·대상 전환·이전 API·모바일 입력 크기를 검사한다.

교정 보고는 독립적인 성공 증거가 아니다. 수정된 본문도 작업 결과 검증 전에는 해결로 간주하지
않는다. 현재 UI는 기존 기억 항목의 교정을 기록하며, 기억에 없는 신규 실패를 자동 발굴하거나
교정 대안을 확정 지식으로 자동 승격하는 기능은 아니다. 매시간 반드시 더 똑똑해졌다는 주장과
Codex 대비 실측 우위는 실제 결과·기기 비교가 있어야 한다. 최종 현재 소스 검사 결과는 로컬
`.agentstoz/maintainer/voice-remote-20261014/RESULT.md`에 기록한다.
