# 기기별 총괄 선택과 원격 워크룸 실행

상태: 기기별 세션 소유 표시 구현. Mac 음성 창의 다른 기기 총괄 선택과 원격 실행 전송은 미구현. 기기 간 대화의 `endpointId`와 메시지 공개 동의만으로 워크룸 실행 권한을 부여하지 않는다.

## 사용자 흐름

1. 접힌 `아젠투지 호출` 버튼은 단일 진입점으로 유지한다. 펼친 창의 대화 상대에서 `총괄(아젠투지 1호)`처럼 기기 별명을 보여 준다.
2. 같은 계정에 등록되고 현재 연결된 다른 기기가 원격 워크룸 사용을 승인하면, 그 총괄을 별도 항목으로 보여 준다. 선택 즉시 `@` 프로젝트 후보, 작업 세션 목록, 음성 대상, 입력 전송 대상을 선택한 기기로 전환한다. 다른 기기의 동명 프로젝트는 합치지 않는다.
3. 작업 세션 목록에는 소유 기기 별명을 표시한다. OPS 프로젝트의 세션만 `총괄(기기 별명)`, 일반 프로젝트의 세션은 기기 별명으로 구분한다. 기기를 바꿀 때 목록·선택 세션·미완성 입력·전송 영수증을 기기별로 분리한다. 원래 기기의 세션은 그대로 실행하며, 돌아오면 해당 기기의 상태를 다시 조회한다.
4. 상대 기기가 오프라인, 승인 철회, 버전 불일치 상태이면 선택은 보이되 입력을 막고 원인을 표시한다. 로컬 총괄로 조용히 전송 방향을 바꾸지 않는다.

## 실행 권한과 식별자

- 기기 간 대화의 공개 대상 일괄 선택은 **메시지 교환** 승인이다. 원격 워크룸의 터미널 입출력·음성 지시·프로젝트 실행은 별도의 기기 간 실행 grant를 필요로 한다. 사용자가 한 번 승인한 grant는 명시 철회·기기 퇴역·프로필 변경 전까지 재사용할 수 있다.
- grant는 표시 이름이 아닌 공유 Control `profileId`, 발신 기기 ID, 수신 기기 ID, 수신 OPS 또는 등록 프로젝트 대상, 허용 동작, 계약 버전에 묶는다. 수신 호스트가 매 전송 직전에 등록 상태와 grant를 재검증한다. 비밀·로컬 경로·임의 명령은 Supabase나 UI 선택 DTO에 싣지 않는다.
- 원격 호스트가 발급한 불투명 세션 ID와 호스트 ID의 쌍으로 세션을 식별한다. 세션 ID만을 현재 기기의 세션으로 해석하지 않는다. 전송은 `hostId + targetId + sessionId + requestId`를 원자적으로 검증하고 영수증에 같은 결속을 되돌린다.
- 현재 모바일 원격제어의 QR/SAS 연결과 승인된 호스트별 터미널 프로토콜을 실행 전송 경로의 기준으로 삼는다. 데스크톱 음성 창에서 동일한 호스트 결속·권한 검사를 재사용할 수 있는 어댑터가 먼저 필요하다. DB 대화 메시지를 수신 AI가 알아서 실행하는 방식은 사용하지 않는다.

## 구현 순서와 완료 조건

1. 공통 조회 계약: 승인된 호스트의 접속 상태, 기기 별명, 지원 버전, 프로젝트와 세션을 호스트별로 반환한다. 오프라인·철회·동명·기기 변경 회귀를 검증한다.
2. 실행 grant와 전송 계약: 기존 모바일 원격제어의 인증된 transport를 데스크톱에서 사용할 수 있게 연결한다. 수신 호스트에서 범위·세션 소유·멱등 `requestId`를 검사한다. 승인 없는 요청·취소된 세션·이전 기기 응답을 거절한다.
3. 음성 창: `총괄(별명)` 선택 후 그 기기의 프로젝트와 세션만 보여 준다. `@`와 음성 지시도 선택한 호스트로만 간다. 전송 도중 기기를 바꿔도 영수증이 다른 기기의 화면에 섞이지 않는다.
4. 설치 앱과 실기: Mac 1호↔Windows 2호에서 각 방향으로 프로젝트 목록, 기존 세션 입력, 새 세션 생성, 음성 입력, 거부·오프라인·재연결을 시험한다. 지원 버전이 다른 기기에서는 업데이트 안내를 보이고 실행을 보류한다.

현재 Mac/모바일 화면은 로컬 또는 이미 연결된 원격 호스트의 세션에 소유 기기를 표시한다. OPS 프로젝트만 `총괄(기기 별명)`으로 표기한다. 다른 기기 총괄을 Mac 음성 창에서 선택해 실제 명령을 보내는 기능은 위 실행 경로가 검증된 뒤에 노출한다.
