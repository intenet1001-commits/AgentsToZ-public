## 관찰한 문제와 벤치마크 근거

  시작한 뒤 메인 창의 작은 터미널 탭으로 이동했다. OPS·음성·터미널 내부의 진입은
  이미 `openWorkroomPopout`을 사용하므로 같은 기능의 진입 경로가 달랐다.
- `nhdesign-usher`의 로컬 저장소 `/Users/cs-work/forcs/nhdesign-usher`를 읽었다.
  현재 미커밋 변경과 별도로 `098b93f`에도 980×720 전용 창, 프로젝트·AI·권한 모드가
  같은 실행 세션 재사용, `flex:1; min-height:0` 터미널 배치가 존재한다.
- Usher는 Rust PTY → raw Tauri Channel → xterm Uint8Array로 출력한다.
  AgentsToZ는 sidecar의 수명·원격 transport·현재 화면 snapshot·headless CPR/DA
  응답을 함께 관리한다. 이 계약을 바꾸지 않은 채 창과 목록부터 개선한다.
  현재의 120ms 로컬 adaptive polling과 native push의 지연·CPU 비교 수치는 없다.
- ChatGPT/Codex 계열의 프로젝트별 목록과 최근순 관리를 참고한다. 실제 공식

  pinnedIndex와 프로젝트 그룹/최근 갱신 정렬 설정을 확인했다. 앱 직접 화면 읽기는
  도구 정책으로 거부됐으므로 실제 화면을 관찰한 근거로 표현하지 않는다.

## 사용자 흐름

1. 프로젝트의 `대화 창에서 작업`은 선택한 AI·프로젝트의 실행 세션을
   재사용하거나 시작한 후 큰 별도 창을 연다. 새 창 실패 시 같은 sessionId로
   메인 화면의 큰 dialog를 연다. 창 실패 때문에 CLI를 다시 시작하지 않는다.
   이어 여는 기존 세션의 권한은 그대로 유지하며, 선택한 권한 옵션은 새 실행에만 적용한다.
2. 메인 `대화 세션`은 현재 단말과 커뮤니티 단말을 함께 보여 준다. 기기·프로젝트
   그룹, 검색, 실행/종료 필터, 최근 시작 순서로 찾고 정확한 세션을 연다.
3. 로컬 세션은 별도 창으로, 원격 세션은 기존 community transport를 유지하는
   큰 내부 dialog로 연다. 원격 인증 정보나 프롬프트·로컬 경로를 URL로 옮기지 않는다.
4. 새 대화의 프로젝트·AI 선택은 기존 패널을 재사용한다. 목록 진입·행 선택은
   `start`나 입력을 자동 전송하지 않는다. 종료된 세션은 마지막 화면을 읽는다.
5. 대화창의 닫기는 보기만 닫는다. 실제 세션 종료·저장은 기존 SessionFooter의
   명시적인 동작과 확인 절차가 담당한다.
6. 닫힌 대화창의 미전송 입력은 `대화 창 다시 보기`로 복원한다. 다른 기기나 공통
   기억에서 새 요청이 들어와도 작성 중인 창을 교체하지 않는다. 새 요청은 최대 8개
   대기 초안으로 보관하며, 기존 내용을 전송하거나 비운 뒤 사용자가 선택해 연다.
   초기 요청·터미널 입력·이미지가 남았는지는 정확한 현재 창에서 판정한다.
   커뮤니티에서 단말이 사라져도 열린 창의 초안을 보존하고 입력 전송을 멈춘다.
   내부 탭으로 고른 실제 세션을 기억해 목록의 다른 행이 그 초안을 덮지 않게 한다.

## 데이터와 경계

- 목록 정체성은 `endpointId + sessionId`, 프로젝트 그룹은 해당 기기의
  `projectTargetId`다. 이름이 같거나 sessionId가 같아도 다른 기기의 행을 합치지 않는다.
- 각 기기의 기존 프로젝트/터미널 `list` DTO만 집계한다. 목록 때문에 terminal
  `read`나 원문 대화 수집을 수행하지 않는다. 표시하는 시각은 `최근 시작`이며
  DTO에 없는 마지막 발언 시각·제목·읽지 않음을 추정하지 않는다.
- 기존 live/retained CLI 목록은 호스트당 최대 24개이며 호스트 재시작 뒤 전체
  영속 대화 보관함을 제공하지 않는다. 별도 SQLite conversation 런타임이나
  `내가 한 말`의 기기 간 기록을 실행 가능한 세션처럼 섞지 않는다.
- 최대 32개 기기·동시 4개 조회, 기기별 stable requester와 single-flight 조회를
  사용한다. 조회 실패는 이전 목록과 확인 불가 상태를 함께 남긴다. 성공한 기기
  목록에서 사라진 대상의 목록만 제거하며 열린 초안과 대기 요청은 보존한다.
  같은 endpoint의 deviceId가 바뀌면 오래된 대기 조회와 입력을 거절한다. 화면이 숨거나 해제되면 목록 조회를 멈춘다.
- 행을 여는 시점에는 대상 기기의 목록을 재확인한다. 권한·프로젝트 확인 실패를
  다른 기기의 동명 프로젝트나 새 CLI 실행으로 해결하지 않는다.
- popup route는 기존 opaque local IDs만 받는다. 새 popup의 local route가 opener의
  원격 기기 선택값을 물려받아 다른 Mac에 실행되는 일이 없게 초기 소유를 명시한다.
- PTY 크기는 마지막으로 전면에 온 창이 주장하는 기존 계약과 headless CPR 중복
  응답 제거를 유지한다. 작은 모니터/DPI/화면 밖 좌표에 창 크기와 위치를 맞춘다.

## 확인 범위

프로젝트 quick profile, TypeScript/Bun/Rust 검사와 격리 synthetic API의 실제
Chromium 렌더·조작을 사용한다. 기기별 같은 ID, 느린/실패한 단말, stale 응답,
popup 실패 후 같은 세션, 창 닫기 후 실행 유지, 로컬 route 소유, 작은 창과
긴 텍스트를 회귀 대상으로 삼는다. 실제 1호·2호·3호의 연결 및 설치본 검증은
격리 테스트 결과와 구분하여 실행 기록에 남긴다.
