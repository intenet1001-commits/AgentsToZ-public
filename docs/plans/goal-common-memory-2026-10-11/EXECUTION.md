# 목표별 공통기억과 SDK 관리 구현 기록

2026-10-11. 앱 소스·MCP·기존 SDK 프로젝트에 구현했고 운영 Supabase에 공통기억 스키마를 적용했다. 설치 앱·다른 실제 Mac의 업그레이드는 완료로 표시하지 않는다. GitHub 반영은 아래 전달 기록에서 별도로 확인한다.

## 구현한 흐름

- 기존 `memoryId`로 원본을 N:N 연결한다. A+B 운전게임, B+C 아이폰 앱이 B에서 각각 다른 항목을 사용한다. 원본 기억·ID·계보를 합병하거나 역으로 쓰지 않는다.
- 이름·목표·포함/제외·조건·검사 기준·SDK 모듈을 설정한다. 출처와 목표 관련성을 검토해 규칙을 게시한다. 목표·연결 변경은 목표 버전을 올리고 재검토를 요구한다.
- 원본 head와 항목 내용 버전을 비교한다. 변경된 근거는 재검토하며, 변경되지 않은 항목은 새 원본 리비전에 연결해 재게시할 수 있다. 원본 합병·보관 상태는 표시하고 연결을 수정할 수 있다.
- 게시본은 불변 이력으로 보존한다. 이전 게시본은 현재 목표에서 재검토할 후보로 복구한다. 작업은 선택한 게시본에 고정한다.
- 프로젝트 생성의 “무엇을 만들까요?” 입력으로 후보·조건·관련 SDK를 표시한다. 선택은 사용자가 한다. 목표 변경은 선택을 해제하고, 생성 직전에 선택한 게시 ID·목표 버전을 확인한다. 중간 갱신은 재선택을 요구한다.
- MCP는 목록·상세·추천·회상·관리·게시 이력·프로젝트 연결·적용 기록과 SDK 상태·준비·추천을 제공한다. 계약은 1.32.0이다.
- 실제 사용한 항목과 결과·근거를 기록한다. 실패·미적용은 현재 게시본의 검토 신호로 표시한다. `passed`는 검사 ID와 근거가 필요한 **보고된 결과**이며 서버가 검사 실행을 인증한 결과가 아니다. 회상은 검증으로 계산하지 않는다.

## 호환성·권한·수명

기존 curated 항목의 `entryId`와 32자리 `contentVersionHash`를 유지한다. 전체 문서는 64자리 SHA-256으로 확인한다. 본문의 들여쓰기·공백을 보존하며 기존 notes에서 합쳐 백업한 Markdown을 그대로 읽는다. 원본 최신 백업 리비전이 입력이며, 아직 Push되지 않은 로컬 편집은 입력으로 간주하지 않는다.

공통기억은 전용 6개 테이블을 사용하며 기기 ID를 소유 키로 쓰지 않는다. 기존 멤버 인증으로 읽고 localhost sidecar의 서버 권한으로 쓴다. 익명 읽기·브라우저 쓰기·기존 게시본 수정/삭제를 허용하지 않는다. 게시·처리 위치·요청 영수증은 한 트랜잭션으로 저장한다. 버전 CAS, 기존 기억의 원본 lock/head 확인, 요청 ID 재시도를 적용한다.

조회·변경 한 번은 같은 클라우드 클라이언트로 처리한다. 추천·연결에는 클라우드 scope hash를 전달하며 동일한 ID가 다른 클라우드에 있어도 기존 선택·회상·수정에 사용하지 않는다. 새 클라이언트는 저장된 scopeId를 함께 전달한다.

원본 16개, 항목 500개, 규칙 12KB, 그룹 1MB, 원본 스캔 2MB, 회상 16KB의 상한이 있다. 목록과 MCP 발췌를 제한하며 부분 추천·원본 확인 실패를 빈 결과와 구분한다. 대규모 의미 선별·자동 AI 게시·정기 AI 평가를 활성화하지 않았다. 기본 운영은 명시적 검토·게시·실제 근거를 통한 개선이다.

프로젝트 원본 CORE는 보존한다. 선택 사본·연결 메타데이터·프로젝트 목표는 별도 파일로 저장하고 Git에서 제외한다. 중단된 다중 파일 연결은 로컬 transaction 기록으로 재개하며 외부 편집과 symlink를 덮어쓰지 않는다. 현재 관리 UI는 앱/local sidecar 경로를 사용한다. 배포된 웹 포털용 원격 쓰기 서버를 추가한 상태는 아니다.

## 기존 SDK 프로젝트

대상은 기존 `SDK` 프로젝트와 같은 GitHub 저장소다. 기억 ID는 `eb2aaff2-3641-486f-a2d8-f8d51ac248ca`를 유지한다. 다른 Mac은 같은 저장소를 Clone/Pull해 등록한다. 상대 경로의 `.agentstoz/sdk-project.json`과 `scripts/sdk.ts`로 그 Mac의 도구·설치 결과를 관리한다.

앱은 등록된 SDK 설정의 변경을 60초마다 확인하고 workspace lease 아래 자동 준비한다. 같은 실패 입력은 반복 실행하지 않는다. 준비 명령은 60초 제한과 종료/프로세스 정리를 적용하며 sidecar 비밀 환경을 넘기지 않는다. Git 성공과 모듈 준비 결과는 별개다.

현재 자동 준비 대상은 `common-memory-sdk`다. 기존 6개 플랫폼 SDK는 카탈로그와 각 README로 관리하며 `manual-module` 상태로 표시한다. 이 결과를 전체 플랫폼 SDK 설치 완료로 해석하지 않는다. 앱 정본의 도메인·클라이언트를 그대로 내보내고 source commit/hash를 기록한다. 이전 내보내기와 다른 로컬 수정·삭제·symlink는 보존하고 갱신을 중단한다. Git 커밋·Push·배포는 내보내기가 수행하지 않는다.

SDK 로컬에서 새 모듈의 실제 빌드·검사가 통과했다. 다른 경로에 실제 Git Clone한 테스트에서도 같은 기억 ID를 유지하고 준비 결과를 새로 생성했다. 실제 두 번째 Mac의 설치 완료 증거는 아니다.

## GitHub 전달과 아이폰 점검 범위

- 최신 원격 main의 독립 로컬 메타 공통 기억과 아이폰 관리 경로를 보존하며 합쳤다. 로컬 메타 기억의 SQLite·후보·연결·권한을 이 클라우드 그룹으로 자동 변환하거나 삭제하지 않는다. 두 저장소의 범위는 UI와 MCP 도구 이름으로 구분한다. 기존 메타 기억의 자동 클라우드 이관은 구현하지 않았다.
- MCP 계약은 이미 원격에 반영된 메타 기억 1.32.0을 보존하고 1.33.0으로 확장한다(기존 62 + 신규 11 = 73 tools).
- 아이폰의 기존 `기록 → 공통 기억`은 선택한 Mac의 로컬 메타 기억이며 별도의 기기 관리 동의가 필요하다. 목표별 클라우드 그룹의 모바일 관리·추천은 아직 그 원격 프로토콜에 연결하지 않았다. 공개 웹에서도 사용할 수 없는 관리 버튼은 비활성화하고 Mac 관리 안내를 표시한다.
- GitHub 소스 반영은 설치 Mac/아이폰 업데이트를 대신하지 않는다. 앱 설치본, 내장 포털/TestFlight 또는 개인 웹 포털의 실제 버전을 확인한 뒤 각 기능의 점검 범위를 정한다.
- 기존 개발 폴더의 다른 변경·기억과 SDK의 독립 `Cdp` 저장소는 게시 범위에 포함하지 않는다. SDK 카탈로그와 새 모듈을 별도 깨끗한 체크아웃에서 quick 검사할 수 있다.
