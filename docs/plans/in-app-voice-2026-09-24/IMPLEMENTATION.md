# 앱 내 음성 구현 순서와 검증 기준

2026-09-24 · 상태: **원래 단계별 인수 기준 · 구현 결과 별도 기록** · [사용자 경험·계약](DESIGN.md)

완료 순서는 **Mac OPS → Mac 각 워크룸 → iPhone 원격**이다. 아래 체크는 실제 음성·설치 패키지·실기기까지 포함한 최종 인수 기준이다. 소스 구현 및 검증 결과는 [EXECUTION.md](EXECUTION.md)에 기록한다. 코드·fixture 통과만으로 이 전체 인수 기준을 완료 처리하지 않는다.

## A0. Mac 오디오와 제공자 연결 확인

전체 UI 구현에 앞서 설치 Tauri에서 가장 불확실한 미디어 연결을 작은 실험으로 확인한다.

- [ ] 제공자/모델·음성·키 보관·사용량 한도를 결정하고, 별도 제공자 adapter 계약을 고정한다.
- [ ] 실제 Tauri origin에서 권한 요청 → 입력 → 전사 → 음성 재생 → 종료를 확인한다. localhost 브라우저 성공과 구분한다.
- [ ] `NSMicrophoneUsageDescription` 및 배포 서명 경로의 필요한 오디오 entitlement를 확인한다. 마이크 주체는 GUI 앱이며 Bun sidecar가 OS 권한 요청 주체가 되지 않게 한다.
- [ ] WebRTC/오디오 재생에 필요한 CSP만 추가한다. 허용 origin을 광범위한 wildcard로 바꾸지 않는다.
- [ ] Mac host에서 만든 provider session에 sideband가 붙고, 잘못된 call ID·늦은 연결 결과가 거부되는지 확인한다.
- [ ] 권한 거부·장치 없음·기기 분리·응답 유실·종료 중 권한 승인에서 track이 남지 않는지 확인한다.
- [ ] 마이크와 스피커 루프·헤드셋·한국어 프로젝트 이름·사용자 끼어들기를 확인한다.

**완료:** 서명된 실제 앱에서 한 문장 왕복과 종료 후 마이크 해제를 관찰하고, 공급자 모델·앱 버전·OS·실측 지연을 기록한다. 불가능하면 native adapter로 경로를 바꾼 뒤 같은 기준을 통과한다. 외부 ChatGPT 열기로 대체하지 않는다.

## A1. Mac AgentsToZ OPS 음성

- [ ] `VoiceSessionHost`와 strict protocol, 단일 소유자 lease, request 영수증·epoch·한도를 구현한다.
- [ ] 시작/도구 실행 시 기존 OPS profile binding을 조회하고 변경·소실을 차단한다.
- [ ] 앱 상단과 `ControlProfilePanel`을 한 개의 음성 패널에 연결한다.
- [ ] 초기 기능을 OPS 회상·등록 프로젝트 조회·특정 Workroom 시작/읽기/지시·OPS 기억 후보로 한정한다.
- [ ] 기존 워크룸을 시작하면 초기 출력을 먼저 읽고 준비된 세션에 지시한다. 새 세션 생성과 패널 열기의 결과를 분리한다.
- [ ] app-data OPS에서 대화는 가능하고, 등록되지 않은 OPS 자체 실행은 설명과 함께 제한한다.
- [ ] 발언 저장 설정, 외부 음성 제공자에 보낼 문맥, 후보와 저장 완료를 구별해 표시한다.
- [ ] 프로필 전환·동명 프로젝트·잘못된 worktree·없는 CLI·로그인 대기의 복구 동선을 확인한다.

**완료:** OPS 버튼 → 실제 한국어 음성 → 등록된 A의 정확한 워크룸 → 접수 영수증 → 관찰한 결과 안내가 연결된다. “기억해”는 올바른 OPS 후보 경로를 사용하며 DEV/다른 프로젝트 기억을 바꾸지 않는다.

## B. Mac 각 워크룸의 말해서 입력

- [ ] `AiTerminalPanel` 각 세션의 입력 영역에 음성 버튼과 공통 패널을 연결한다.
- [ ] targetId/sessionId/agent/worktree fingerprint를 고정하고 녹음 이후 선택 변경 시 전송을 막는다.
- [ ] 전사 초안 수정·취소·전송을 구현한다. 기존 새 세션 초안과 사용자가 입력하던 텍스트를 보존한다.
- [ ] UTF-8 크기·제어 문자·빈 입력·이미 종료된 세션을 기존 규칙으로 검증한다.
- [ ] 키보드·붙여넣기·음성·저장·종료 경합을 입력 lease와 revision으로 처리한다. raw terminal 외 추가 경로도 같은 가드를 거친다.
- [ ] 같은 발화 중복 final/tool call·HTTP 재시도·서버 재시작에 대해 영수증을 재사용한다.
- [ ] Codex·Claude·Hermes·agy 각각 같은 워크룸에 정확히 한 번 입력되는 것을 확인한다.

**완료:** 네 AI 각각에서 말한 초안을 검토해 기존 선택 세션으로 전송할 수 있다. 다른 세션 전송·작성 중 텍스트 덮어쓰기·중복 Enter가 없어야 한다. 이는 아직 네 AI의 실시간 대화 완료를 뜻하지 않는다.

## C. 워크룸 실시간 대화와 결과 읽기

- [ ] 에이전트별 입력 준비·턴 완료·중단 capability를 구현하고 정확한 provider session/turn 결속을 검증한다.
- [ ] 최종 발화 자동 전송, 결과 대기, 실제 출력 기반 낭독, 끼어들기·재생 큐 폐기를 연결한다.
- [ ] 수신 중인 CLI 응답을 음성 모델 자신의 결과로 오인하지 않도록 AI 출처를 표시한다.
- [ ] AI 질문과 CLI 승인/로그인 화면을 분리한다. 후자는 기존 사용자 UI에서 처리한다.
- [ ] 작업 중 후속 발화를 보관할 한도를 적용하고 오래된 응답이 새 대상에서 재생되지 않게 한다.
- [ ] 완료를 관찰할 수 없는 AI에서는 이를 표시하고 `현재 출력 읽기`와 말해서 입력만 제공한다.
- [ ] 각 AI의 실제 완료 관찰을 확보해 Codex·Claude·Hermes·agy 체크를 독립적으로 완료한다.

**완료:** 각 AI별로 동일 세션에서 3턴 이상의 한국어 대화, AI 질문에 답하기, 결과 낭독 중 끼어들기, 음성 종료 후 작업 유지가 검증된다. 입력만 전달된 상태를 실시간 대화 완료로 체크하지 않는다.

## D0. iPhone 미디어·권한 사전 검증

Mac 음성의 완료 근거를 확보한 다음 진행한다.

- [ ] 현행 native LANClient가 검증한 host·세션을 음성 adapter에 연결할 수 있는지 확인한다. WebView가 주장하는 인증 정보를 신뢰하지 않는다.
- [ ] 실제 iPhone의 HTTPS WKWebView/포털에서 마이크·WebRTC·재생·권한 거부를 확인한다.
- [ ] LAN용 native 캡처/재생/WebRTC 라이브러리, 앱 크기·서명·최소 OS 적합성을 결정한다.
- [ ] native LAN 음성 버튼이 현재 승인 host와 대상에 결속되는지 실험한다. HTTP WebView에 범용 오디오 bridge를 열지 않는다.
- [ ] SDP 실제 크기·타임아웃에 따라 bounded voice-v1 메시지 계약을 정한다.

**완료:** HTTPS와 앱 LAN에서 각각 인증된 host를 통해 음성 세션을 시작하고 왕복할 수 있다. 하나만 통과하면 나머지는 미완료로 남긴다.

## D1. iPhone 원격 버튼

- [ ] voice-v1 지원 여부, 별도 voice.use grant와 기존 동작별 권한의 교집합을 Mac/폰 양쪽 strict normalizer에 구현한다.
- [ ] OPS와 선택 Workroom에 공통 음성 패널을 제공하고 Mac 이름·대상·AI를 상시 표시한다.
- [ ] 정확한 HTTPS origin/메인 프레임에만 Permissions-Policy와 WK microphone 요청을 허용한다. 카메라 정책은 기존 QR 용도로 유지한다.
- [ ] native LAN adapter는 페어링 identity·연결 epoch·host 발급 대상에 결속하고 navigation 변경 시 해제한다.
- [ ] 기존 암호화 채널로 OpenAI의 시작/중지/SDP/상태와 Gemini의 bounded PCM 조각을 전송한다. API 키·프로젝트 경로는 relay 제어 payload에 추가하지 않고, Gemini 원음은 저장하지 않는다.
- [ ] Mac/폰의 동일 대상 동시 시작·인수·권한 회수·기존 버전 조합을 검증한다.
- [ ] Wi-Fi↔셀룰러, 잠금, 앱 백그라운드, 전화, Bluetooth 전환, Mac 절전, relay 중단을 실기기에서 검증한다.
- [ ] 음성 끊김 뒤 새 발화 없이 작업 상태만 조회하고, 원래 지시를 재실행하지 않는지 확인한다.

**완료:** iPhone의 버튼으로 해당 Mac의 정확한 OPS/Workroom에 실제 음성 요청이 전달되고 결과를 듣는다. HTTPS 원격과 앱 LAN은 각각의 실제 기기 증거를 남긴다. Simulator/텍스트 fixture 통과만으로 완료하지 않는다.

## 필수 회귀 시나리오

| 시험 | 확인할 동작 |
|---|---|
| A에서 녹음하다 B로 이동, 이후 A 전사 완료 | B로 전송되지 않고 A 초안으로 남거나 취소됨 |
| OPS의 표시 이름만 가진 일반 프로젝트 | 실제 OPS binding 없이 운영 권한을 얻지 못함 |
| 워크룸 시작 중 오래된 응답 도착 | 새 선택·새 음성 초안을 지우지 않음 |
| 전사 final 중복·tool call 중복·같은 ID 다른 payload | 같은 실행 영수증 반환 또는 충돌 거부 |
| PTY 입력 직후 호스트 종료 | 결과 확인 필요로 남고 자동 재전송 없음 |
| CLI trust/login/번호 선택 화면 | 음성 자연어와 Enter가 자동 투입되지 않음 |
| 사용자가 CLI 입력 중 음성 전송 | 입력 revision 충돌을 표시하고 기존 입력·음성 초안 보존 |
| 터미널 입력 접수 후 AI 실패 | 접수와 실패를 구분, 작업 완료라고 말하지 않음 |
| 최종 출력과 TTS/전사에 숨은 도구 지시 | 출력은 데이터로만 취급, 새로운 실행 권한을 얻지 못함 |
| 재생 중 사용자 발화·이전 응답 늦게 도착 | 이전 재생 큐 폐기, 원래 작업은 별도 중단 전까지 유지 |
| 마이크 거부/늦은 허용/장치 분리 | 텍스트 입력 유지, 종료된 세션의 track 즉시 해제 |
| 호스트 grant 회수·sideband 유실 | 새 도구 실행 차단, provider·미디어 연결 종료 |
| 다른 폰/다른 세션 핸들 재사용 | owner/epoch/target 검증으로 거부 |
| 음성 기억 후보 후 모델이 승인 시도 | 공유 OPS 저장 불가, 기존 사람 검토만 가능 |
| What I Said 동의 꺼짐/켜짐 | 미동의 원문 비저장, 동의 시 이중 수집 없이 한 번 기록 |
| 100회 시작/중지·15분 대화 | track·socket·timer·lease·버퍼가 계속 증가하지 않음 |
| Mac 꺼짐·구형 sidecar·원격 권한 없음 | 각각의 이유 표시, 허위 연결/전송 성공 없음 |

동작 수준의 단위·호스트 통합·실제 React UI 테스트를 사용한다. 문자열 존재 검사나 개발 브라우저 성공만으로 OS 미디어 권한·설치 앱·실제 AI 성공을 대신하지 않는다. 실행 경계를 바꾸는 각 구현 단계는 저장소의 현재 `bun run verify`를 통과해야 한다. 이 설계 문서만 작성하는 단계에는 런타임 테스트를 실행하지 않는다.

## 성능·출하 기록

성능 수치는 구현 전 목표이며 현재 측정값이 아니다. 고정 네트워크·장치·제공자·모델·오디오 표본으로 초기 20회 이상 측정한다.

- 시작 클릭 → 준비 완료: p95 5초 이내를 목표로 한다. 초과 시 실제 원인과 재시도 동작을 기록한다.
- 발화 종료 → OPS 첫 음성: p50 1.5초, p95 3초 이내를 초기 목표로 한다. Workroom 실행 시간은 별도 측정한다.
- 작업 접수 → 화면/음성 접수 안내: 실행 완료와 분리해 측정한다.
- 사용자 중단 → 로컬 스피커 정지: p95 300ms 이내 목표. 마이크 종료는 track 상태와 OS 표시를 함께 확인한다.
- 종료 전후 메모리·active track/socket/timer·잔존 lease와 세션별 사용량을 기록한다.

출하 기록에는 commit, 앱/sidecar 버전, OS, provider/model, 입력 모드, 연결 방식, AI, 실제 수행 결과, 남은 한계를 적는다. Mac OPS, 4개 Workroom, iPhone HTTPS, iPhone LAN을 개별 체크한다. 소스 빌드·공증·설치·TestFlight 배포는 기존 출하 가드를 따르며 각 단계의 성공을 따로 보고한다.
