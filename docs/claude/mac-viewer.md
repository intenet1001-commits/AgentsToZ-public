# Mac Viewer와 Screen — 구현 및 출시 관문

정본 설계는 [Mac 간 화면 제어 v2.1](../design/mac-to-mac-2026-11-01/DESIGN.md)이다. 이 기능은 사람이 Mac A의 AgentsToZ Viewer에서 Mac B의 AgentsToZ Screen을 보는 경로다. AI·MCP·스크립트가 사람의 화면 세션을 시작하거나 조작하는 경로를 만들지 않는다(SR-23). Viewer와 Screen은 별도 앱이며 사람 입력과 세션 승인은 실제 기기에서 확인해야 한다.

## 등록과 연결

- A와 B를 직접 등록한다(D-1). 등록 시 두 Mac에서 6자리 코드를 확인하고 B에서 하드웨어 입력과 생체 인증으로 권한을 정한다. Viewer는 A에서 연결마다 생체 인증을 거친다. 연결 때마다 확인을 완화할지 사용자가 검토를 요청했으나 새 방식은 정해지지 않았다.
- B의 `ScreenControllers` 저장소는 컨트롤러별 키·이름·권한·등록과 만료를 관리한다. 폰 등록부와 구분하며 한 키를 양쪽에서 동시에 허용하지 않는다. 보기·조작 권한을 B에서 정하고 하향·해제는 해당 세션을 끝낸다.
- 사람의 화면 세션은 Mac 간 프로토콜 5를 사용한다. 폰은 4에 고정하며 기존 골든 벡터를 보존한다(SR-36). 중계 리스너는 폰만 수락한다. 등록 전 안내는 인증된 세션의 권한을 주지 않는다.
- 보기 세션의 한도는 60분, 조작 세션은 입력 유휴 60분·최대 8시간이다. 자동 재연결은 없다. 실제 경로 및 상태는 `ScreenSessionRules.swift`, `ScreenControllers.swift`, `ScreenTargetRoute.swift`와 테스트로 확인한다.

## 조작·켜 두기와 잠금

- 조작은 S-M3 실측을 통과한 보정과 빌드 플래그, `pushLive` 관문이 모두 필요하다. 현 소스의 보정은 미측정이므로 Mac 컨트롤러 조작은 기본적으로 닫혀 있다. 푸시 연결·원격 차단이 확인되지 않은 비결속 등록도 허용하지 않는다.
- 재시작 후 켜 두기는 기본 꺼짐이며 B에서 인증해 승인한 네트워크와 푸시 관문에 묶인다(D-2). 잠긴 B의 입력은 조작 권한과 별도 플래그 등 조건이 맞을 때만 열 수 있다(D-3). 잠긴 B의 보안 입력칸에 대한 종단 간 입력은 아직 실기로 확인되지 않았고, 기존 입력 주입기가 Secure Event Input을 거절하는 경로도 확인해야 한다. 설정이나 코드가 있다는 사실만으로 운영 배포 또는 실기 검증이 끝났다고 말하지 않는다.
- Viewer는 실행 중인 세션 동안 A를 깨워 둔다. 보기의 최대 60분 또는 조작의 유휴 60분·최대 8시간 동안 자리를 비운 A가 자동 잠기지 않을 수 있다. 실제 절전·화면 보호기 동작은 실기 확인이 남았다.

## 대상 Mac의 세션 바

폰과 Mac 세션은 같은 `ScreenMacHold`를 쓴다. B에서 「직접 하기」나 「보기만」을 누르면 이후 다른 기기가 다시 연결해도 원격 입력이 일시 정지된다. 「보기만」은 현재 세션의 권한을 낮춘다. 보류 해제는 B에서 인증해 다시 켜거나, 해당 버튼 안의 새로운 단일 하드웨어 클릭으로 「다시 넘기기」를 누를 때만 가능하다. 접근성 누르기·원격에서 주입한 클릭·다른 프로세스의 클릭은 거절한다. pid 0 규칙의 가상 HID 판별은 S-M3 실측 전 가정이다.

## 검증과 남은 사람 단계

`bun run test:screen-control`은 프로토콜·호스트·세션 바 모델과 오프스크린 렌더를 검증하며 `bun run test:ios`는 폰 경로를 별도로 검사한다. 실제 창의 레벨·끌기·하드웨어 입력, 등록 시트, 두 Mac 간 연결 및 잠금 화면은 이들 검사만으로 증명되지 않는다. S-M3, Mac App Attest(S-K2), WARP 간 경로(S-N2), screen-push 배포(H10), 두 Mac 실기 점검 및 생체·SAS 승인은 사람이 수행한다. H1 전용 프로필 발급과 로컬 QA 서명은 2026-11-02 확인했으며, 공증·설치와 운영 배포는 각각의 승인과 결과 확인이 필요하다.

S-M3의 사람 실행용 `AgentsToZInputProbe`는 자기 창의 시험 영역에서 PID·키보드 타입·소스 상태만 제한된 크기로 집계한다.
컴파일만으로 창을 열지 않고, 진단기는 원격 세션·입력 주입·TCC 요청·키체인 접근을 하지 않는다.
출처 라벨은 사람의 주장이고 보고서는 `certifiesCalibration:false`다. 누락·충돌·초과를 판독하는 [실측 절차](../design/mac-to-mac-2026-11-01/SPIKES.md)를 따른다.
이 실행 대상은 배포 번들에 넣지 않으며 `ScreenInputCalibration.current`나 조작 관문을 변경하지 않는다.

## Viewer 포장 경로 (2026-11-02)

`bun scripts/build-viewer-app.ts --sign <Developer-ID-지문> --bundle-version 1.2.3 --output /절대경로/AgentsToZViewer.app`
은 독립 Viewer 앱을 만든다. 기존 출력은 덮어쓰지 않는다. 기본 프로필은
`native/screen-control/App/AgentsToZ_Viewer_Developer_ID.provisionprofile`이며 `--profile`로 명시할 수도 있다.
컴파일 전에 전용 App ID·팀·배포 프로필·만료·공개 인증서 지문 소속을 확인한다. H1 프로필이 없으면 즉시 실패하며
Screen 프로필·ad-hoc 서명으로 대체하거나 프로필을 생성하지 않는다. secure timestamp가 필수다.

메인 앱 빌드의 `--developer-id --with-viewer`는 같은 버전의 Viewer를 `Contents/Helpers/AgentsToZ Viewer.app`에 넣는다.
이 이름은 Rust 설치·상태 조회의 `app_name`과 같아야 한다. 이름이 다르면 `bundled:false`가 되어 버튼도 숨겨진다.
이름 일치 회귀는 `tests/viewer-bundle.test.ts`가 확인한다. 독립 QA 빌더의 출력명 `AgentsToZViewer.app`과 배포 payload 이름은 구분한다.
`--with-viewer` 없는 기존 빌드 동작은 유지한다. GUI 서명 파이프라인은 Viewer의 독립 서명과 정확한 키체인 그룹을 검증·보존하고,
외부 번들 공증 후 Viewer 자체에도 티켓을 스테이플한다. 기존 Rust 설치 경로가 이 고정 경로의 앱을 독립 설치한다.
빌더는 세션 시작·앱 실행·설치를 하지 않는다. 2026-11-02 전용 Viewer 프로필로 `0.0.0` 로컬 QA 서명·secure timestamp·strict 검증을 통과했다.
프로필과 QA 앱은 원본 저장소의 gitignored 검증 산출물에 보존했다. 기본 프로필 경로도 기기별 빌드 입력으로 Git에서 제외한다.
발급된 프로필에는 App Attest entitlement가 없다. Apple 공식 `isSupported` 문서와 설치 SDK는 Mac에서 false라고 명시한다.
S-K2는 문서상 미지원이며 런타임 실측·PASS가 아니다. 미결속 등록의 푸시 관문을 유지한다.
후속 QA Viewer 0.0.2의 공증·양쪽 Gatekeeper는 통과했으며, 메인 설치본 갱신과 두 Mac 실제 세션은 미완료다.
최신 범위는 [커뮤니티 Viewer 기록](../handoff/2026-11-01-codex/COMMUNITY-VIEWER-2026-11-02.md)을 따른다.
[상세 영수증과 검증 범위](../handoff/2026-11-01-codex/VIEWER-READINESS-2026-11-02.md)를 따른다.
후속 포장 이름 수정·설치본 진단·최신 verify 실패는 [버튼 점검 기록](../handoff/2026-11-01-codex/VIEWER-BUTTON-2026-11-02.md)을 먼저 확인한다.

Viewer와 모바일은 생체 승인, 근거리/사설망/중계 경로 열기, Mac 인증, 첫 화면을 구분한다.
Viewer에서 취소된 연결은 다른 경로를 시도하거나 인증 메시지를 보내지 않는다. 모바일도 사라진 시도의 키 교환을 시작하지 않는다.
승인 후 인증 실패에 따른 다른 경로 재시도나 자동 재연결은 추가하지 않았다.

## 커뮤니티 발견과 추가 안내 (2026-11-02)

사용자가 Jump Desktop에서 「Mac 추가…」가 반응하지 않는다고 보고했다. 안내를 여는 동작까지 물리 입력으로
제한했던 것을 분리해, 목록 새로 고침과 등록 안내를 일반 AppKit 버튼으로 연다. 안내 닫기·취소·다시 찾기도
같은 경로로 처리해 원격에서 연 안내를 원격에서 닫을 수 있다. 이 처리기는 `HumanProof`를
만들지 않는다. 등록 상대 선택·키 생성·코드·등록 저장·연결 시작과 생체 인증은 기존 관문을 그대로 사용한다.

사이드카의 기존 community-status 결과를 재사용해 `viewer-community.json`에 발견용 정보만 원자적으로 쓴다.
`AgentDialogueHostDependencies.communityDirectory` 콜백은 선택적이며 실패가 우편함을 중단하지 않는다.
계정 전환·회원 캐시 무효화는 목록을 지우고 이전 계정의 늦은 응답은 내보내지 않는다. 새 RPC·타이머는 없다.
Viewer는 소유자 전용 정규 파일·최대 32KiB·최대 64기기·90초 유효기간·엄격한 형식을 확인한다.
기기 이름·불투명 참조·최근 응답 시각만 전달하며 주소·키·권한·명령·credential은 금지한다.

목록의 「화면 등록 안내…」는 해당 이름을 참고 문구로만 보여 준다. 같은 이름으로 기존 Mac 키에 결속하지 않고
기존 등록부를 수정하지 않는다. 가입은 화면 제어 승인이 아니며 최근 응답은 현재 연결 가능성의 증명이 아니다.
최초 등록은 아직 Bonjour/AWDL 근거리 방식이고, 인터넷 최초 등록·Mac 조작 관문·상호 실기 확인은 별도 미완료다.
이 변경을 설치하지 않은 기존 메인 앱은 힌트 파일을 만들지 않으므로 Viewer만 갱신하면 목록 안내가 표시된다.

사용자 실기 스크린샷에서 목록과 선택한 기기의 등록 안내 표시를 확인했다. 0.0.3 QA에서는 안내를 열자마자
검색하지 않고, 상대 Screen 준비 → 명시적인 「등록 창 찾기」 → 최대12초 검색 → 결과/복구 안내로 진행한다.
끝나거나 닫힌 검색은 브라우저와 마감 작업을 취소하고 이전 검색의 늦은 결과를 버린다. 인터넷 최초 등록
미지원과 상대 Screen 업데이트 필요를 안내에 표시한다. 제품 문구의 A/B 표현을 상대 Mac으로 바꾸고,
발견 목록의 OPS 접미사와 날짜 표시는 표시용으로만 정리한다. 원래 이름과 등록 키는 바꾸지 않는다.
