# 아젠투지 텍스트 대화

Mac과 모바일의 아젠투지 호출 도크에서 **텍스트로만**을 선택할 수 있다. 기기별로 마지막 대화 방식을 기억한다. 접힌 도크에서도 전용 시작 버튼으로 입력칸을 펼칠 수 있으며, 연결 전 입력한 초안은 동의·설정 화면을 열어도 유지한다. 연결 전 글 보내기는 텍스트 대화를 준비하고, 준비가 끝난 경우에만 그 요청을 보낸다. 동의가 필요하면 초안을 남기고 사용자가 다시 보내도록 한다.

텍스트 전용 시작은 `getUserMedia`·마이크 감시기·재생용 오디오 요소를 만들지 않는다. Gemini도 AudioContext 없이 응답 읽기를 시작한다. 기존 음성 대화를 텍스트로 바꾸면 마이크 트랙과 재생을 즉시 끄고 세션 ID·상대·지시 초안을 유지한다. 다시 음성으로 바꿀 때는 별도의 음성 동의를 확인한 뒤 마이크를 요청한다. 허용되지 않으면 기존 텍스트 대화를 유지한다. 다음 대화의 제공자를 바꿨더라도 현재 대화의 제공자에게만 동의한다.

음성 동의는 기존처럼 텍스트 입력도 포함한다. 새 텍스트 동의는 마이크 동의를 부여하지 않으며, 제공자·입출력 방식별 편집 상태를 서로 재사용하지 않는다. 기록은 기존 ‘내가 한 말’ 저장 선택과 대상별 기록 경계를 따른다.

이 설정은 기기의 입력·표시 방식이다. 선택한 OpenAI/Gemini 연결 설정과 기존 실시간 제공자 프로토콜을 사용한다. OpenAI의 RTC 오디오 채널 협상과 제공자의 응답 전사는 유지되며, Gemini의 서버 음성 청크도 수신 후 재생하지 않는다. 텍스트 전용 모델이나 별도 API로 전환하는 설정은 아니다. 제공자 키와 연결은 여전히 필요하다.

텍스트 모드에서는 자막 설정이 꺼져 있어도 요청과 답변을 표시한다. 전체 화면에서도 같은 작성기로 입력하고 초안을 이어간다. `@` 호출과 `#` 참고는 기존의 정확한 프로젝트 ID·받는 곳·참고 범위 계약을 사용한다. 한글 조합 확정과 빠른 중복 제출은 요청을 두 번 보내지 않는다. 실패한 요청을 자동 재전송하지 않는다.

검증은 `tests/voice-preferences.test.ts`, `tests/voice-media-client.test.ts`, `tests/gemini-pcm-client.test.ts`, `tests/voice-text-only.e2e.mjs`와 기존 도크 검사로 수행한다. 화면 검사는 합성 호스트·RTC로 실제 React 도크·설정 패널·클라이언트를 실행하며 Mac 1280px, 모바일 390·320px의 Chromium/WebKit을 확인한다. 실제 제공자 연결이나 iPhone Appium 통과를 대신하지 않는다.
