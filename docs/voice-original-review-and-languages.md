# 원음 재검증과 앱 언어

## 음성 입력

통역사 앱의 `AudioReview.swift`와 `OpenAIClient.reviewAudio`에서 확인한 방법 중, 같은 발화 원음을 다시 전사하는 방식과 숫자·부정 표현·누락 방지 원칙을 적용했습니다. 통역사 실험에서 높은 증폭값은 일부 문장을 악화시켰으므로 증폭값, 온도 변경, 번역 fan-out은 가져오지 않았습니다.

OpenAI 연결은 기존 near-field 잡음 제거와 semantic VAD를 유지합니다. 선택한 앱 언어와 영어, 제품·AI 이름을 ASR 힌트로 전달합니다. 완료된 발화는 호스트의 기존 sideband에서 정확한 item ID의 처리된 PCM16/24 kHz/mono 원음을 `conversation.item.retrieve`로 가져와 `gpt-transcribe`로 재검증합니다. 원문 전사를 재검증 프롬프트로 넣지 않습니다. 추가 장기 원음 파일은 저장하지 않으며 기존 녹음 동의나 기록 저장 여부를 변경하지 않습니다.

재검증은 추가 ASR 요청과 지연을 발생시킵니다. 최대 32초 원음, 동시에 2개, 연결당 60회, 1분당 12회이며 원음 조회 2.5초·전사 8초를 넘기지 않습니다. 실패·원음 누락·길이 초과·한도 도달 시 기존 전사를 보존합니다. 늦게 도착한 결과는 종료된 연결이나 다른 발화로 적용하지 않습니다. 완료된 문장은 순서대로 전달하고 중복 이벤트를 제거합니다.

워크룸 담당자에게 전달하는 말에서 숫자·부정·짧은 답이 달라지거나 큰 구간이 누락되면 자동 입력하지 않고 같은 워크룸에 결속한 확인 초안을 만듭니다. 사용자가 전송하기 전에 내용을 수정할 수 있습니다. 받아쓰기는 기존처럼 확인 초안을 사용합니다. OPS Realtime의 음성 이해·응답은 원래 오디오를 통해 작동하므로 자막 재전사가 이미 실행된 모델의 음성 이해를 소급해서 바꾼다고 주장하지 않습니다. Gemini 음성을 OpenAI로 보내지 않습니다. Gemini에는 선택한 답변 언어만 적용하며 원음 재검증은 OpenAI 경로의 기능입니다.

고정된 음성 샘플의 실제 제공자 비교와 물리 기기의 마이크 테스트 결과를 구분합니다. 단위·화면 테스트 통과만으로 인식률 향상을 수치로 주장하지 않습니다.

공식 계약: [Realtime item retrieved](https://developers.openai.com/api/reference/resources/realtime/server-events#conversation.item.retrieved), [File transcription](https://developers.openai.com/api/docs/guides/speech-to-text).

## 앱 언어

첫 실행은 브라우저·OS 언어와 무관하게 한국어입니다. 메뉴의 언어 선택에서 한국어, English, 日本語, 简体中文, Español, Français, Deutsch를 선택합니다. 메뉴·주요 탐색·기기 기억·기본 음성 설정을 해당 언어로 표시하며 기기에 저장하고 같은 저장소를 사용하는 창 사이에 반영합니다. 유효하지 않은 저장값은 한국어로 복귀합니다. 사용자가 작성한 내용과 기억, 프로젝트명, 경로, AI 도구명은 번역하지 않습니다.

음성 연결을 새로 시작하면 그때 선택한 언어로 답변하도록 요청합니다. 진행 중인 음성 연결은 자동 재연결하지 않습니다. 한↔영 통역 자막은 기존 별도 기능이므로 일본어 등으로 메뉴를 바꾸어도 임의로 통역 언어를 변경하지 않습니다. 상세 관리 패널 일부는 기존 한국어·영어 설명을 유지합니다. 이 메뉴 지원 범위를 전체 전문 문구와 네이티브 연결 안내의 번역으로 확대 해석하지 않습니다.
