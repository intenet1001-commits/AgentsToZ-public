# AI 작업과 AI 터미널

- **AI 작업**: 앱의 Runtime SDK로 구조화된 작업을 실행한다. `AgentRuntimeQuickLabels`는 Codex의 도구 없는 읽기 전용 실행으로 프로젝트 메타데이터를 분석한다. 결과의 프로젝트 ID·개수·이름 길이를 검증한 뒤 미리보기에서 사용자가 적용한다. 동시에 한 작업, 2분 제한, 취소를 지원한다. 기존 관리형 파일 쓰기 작업의 출하 게이트는 유지한다.
- **AI 터미널**: 등록 프로젝트·Git 워크트리에서 설치된 Codex CLI, Claude Code, Hermes, agy를 Bun PTY와 xterm으로 실행한다. CLI 자체 로그인·설정·권한을 사용하며 임의 shell command/path/env를 API에 받지 않는다. Codex와 Claude에는 검토한 프롬프트를 단일 argv로 전달할 수 있다. CLI는 일반 개발 터미널의 권한으로 동작한다. 관리형 작업의 격리 보장을 뜻하지 않는다.

Git 머지·싱크, 브랜치 정리, 폴더명 변경, 공개 저장소 업데이트에서 내부 AI 터미널의 요청 확인 화면으로 진입할 수 있다. 기존 복사 기능도 유지한다. 이름 추천은 별도 SDK 작업이며 결과를 앱에 적용한다.

## 수명과 한도

터미널은 화면을 전환해도 API 프로세스가 살아 있는 동안 유지한다. 최대 12개 동시 실행, 종료 포함 24개 목록, 세션별 약 100만 문자 출력 버퍼를 유지한다. 요청 ID로 시작·입력을 중복 방지하고 세션별 입력·크기 변경·종료를 직렬화한다. 출력 커서는 재생 범위를 벗어나면 `truncated`를 알린다. PTY EOF까지 읽고 종료 상태를 표시한다. 프로젝트 경로가 바뀌면 새 입력은 거부하며 로컬 종료는 계속 가능하다.

현재 PTY 호스트는 macOS·Linux를 대상으로 하며 이 변경의 실행 검증은 macOS에서 수행했다. Windows의 앱 내부 AI 터미널은 명시적으로 미지원 오류를 표시한다. 기존 외부 터미널 기능은 계속 이용할 수 있다.

## 원격 접근

AI 터미널 접근은 기존 QR 프로젝트 제어·Codex 작업·지속형 대화 권한과 별도다. 연결 후 **Mac의 AI 터미널 → 원격 연결의 터미널 접근**에서 해당 연결을 허용한다. 기본은 거부이며 앱 재시작 후 다시 허용해야 한다. 터미널에 표시되는 경로·계정 정보도 전송될 수 있다. 허용된 연결끼리는 현재 접근 가능한 등록 프로젝트의 터미널을 공유한다.

LAN은 기존 동일 출처 WebSocket을 사용하고, 인터넷은 기존 SAS 승인 및 E2EE envelope를 사용한다. 세션별 임시 controlId를 매번 실제 등록 대상으로 해석한다. 권한 해제·연결 해제·프로젝트 제거 이후에는 새 원격 입력을 거부한다. 출력과 입력은 암호화 릴레이의 11,000-byte 본문 제한 안으로 나눈다. 인터넷 페이지의 주기적인 갱신과 터미널 요청은 같은 relay cursor를 동시에 읽지 않는다.

LAN WebSocket이 닫히면 기존 정책대로 QR 세션은 폐기된다. 새 QR로 연결하고 접근을 다시 허용하면 Mac에서 계속 실행 중인 터미널을 목록에서 선택할 수 있다. 인터넷 컨트롤러는 암호화 세션 복원 후 같은 터미널에 다시 접근한다. LAN은 신뢰 가능한 개인 Wi-Fi 전용이다.

## 로컬 API

모두 POST이며 설치 앱은 기존 `agent_runtime_request` Tauri command 및 전용 capability를 사용한다. 원격 브라우저에 이 capability를 전달하지 않는다.

| 경로 | 작업 |
|---|---|
| `/api/agent-runtime/terminals` | `list`, `start`, `read`, `input`, `resize`, `close` |
| `/api/agent-runtime/terminals/access` | 활성 연결 목록, 연결별 `owner`·`enabled` 설정 |
| `/api/agent-runtime/quick-labels` | `start`·`read`·`cancel`; 검증된 제안만 반환 |

LAN 정적 자산에는 번들에 포함한 `/remote/xterm.js`·`xterm.css`가 추가된다. xterm이 글꼴·행·테마 stylesheet를 생성하므로 CSS의 inline style을 허용한다. script-src는 계속 self-only이며 외부 CDN·임의 실행 API는 열지 않는다.

## Workroom (워크룸): embedded CLI workspace

워크룸은 실행 옵션의 `internal` 표면이다. 프로젝트 상세와 메인/연결 워크트리에서
Claude Code·Codex CLI·Hermes·Antigravity를 선택해 실행한다. 브랜치 이름만으로
대상을 추정하지 않고 등록 ID 또는 경로에 연결된 opaque runtime ID를 재검증한다.
기존 외부 앱, 터미널, Git 동작은 별도 그룹으로 유지한다. 내부 CLI에는 외부
터미널의 tmux/Claude --bg/권한 우회 플래그를 적용하지 않는다.

작업 세션 목록은 창 폭에 따라 옆 또는 위에 배치한다. 원격 호스트를 바꿀 때는
호스트별 선택 세션 ID만 sessionStorage에 저장하며, 본문과 인증 권한은 저장하지 않는다.
기존 QR pairing, SAS 승인, 연결별 terminal consent, E2EE와 revoke 경계를 유지한다.
복수 호스트 격리 회귀 검증은 실제 암호화 controller/host를 메모리 relay로 연결한다.
이는 실제 휴대폰·배포 relay를 통한 종단간 검증과는 별도의 증거다.

실행 세션이 없을 때는 프로젝트·워크트리와 AI 선택, 작업 요청 입력을 표시하며
빈 xterm과 비활성 키 바는 생성하지 않는다. 세션 목록이 늦게 도착해도 선택 세션을
확인한 뒤 xterm을 생성한다. 현재 세션과 새 터미널의 대상이 다르면 둘을 표시한다.
입력한 요청은 실패·접기·AI 변경에서 보존하고, 지원하지 않는 AI를 고르면 자동
전달 제한을 안내한다. 요청 자동 전달은 Codex CLI·Claude Code에서 지원하며
Hermes·Antigravity는 요청을 비운 상태에서 CLI를 열어 직접 입력한다.
`node tests/workroom-usability.e2e.mjs`는 실제 앱 CSS·사이드바·125% 배율에서
빈 화면, 요청 전달, 저장 상태, 좁은 레이아웃을 격리된 API로 검증한다.
실제 앱의 높이가 제한된 flex 부모도 재현하여 터미널 버튼과 저장 영역의 겹침,
버튼 중앙의 클릭 차단, 짧은 창의 스크롤과 요청·이력 펼침을 확인한다.
터미널 workspace와 body는 콘텐츠의 최소 높이를 유지하고, 데스크톱의 세로
스크롤은 `top-level-terminal-panel`이 맡는다. 터미널 버튼까지 포함한 높이를
확보하여 다음 저장 영역이 버튼을 덮지 않게 한다.

종료된 세션은 기본 작업 목록에서 숨기고 `종료된 세션 보기`에서 읽기 전용으로
확인한다. 선택한 세션이 종료되면 다른 실행 세션으로 전환하며, 선택하지 않은
세션의 종료도 목록 갱신에 반영한다. 숨기기는 출력 보관이나 종료 후 기억 저장을
삭제하지 않는다. 종료된 세션에는 키 입력·크기 변경·종료 요청을 보내지 않는다.

한글 조합은 xterm의 IME 처리를 사용하며 확정된 입력만 순서대로 전달한다.
로컬 출력 조회는 입력의 경로 검증을 기다리지 않고, 쌓인 출력은 xterm 적용 완료
뒤 즉시 이어 읽는다. 입력마다 현재 등록 파일과 체크아웃의 파일 시스템 근거를
확인하되, 근거가 같으면 전체 프로젝트 Git 탐색을 반복하지 않는다. 근거가 바뀌면
등록·Git 검증을 다시 수행하며 경로 교체와 원격 권한 해제는 계속 거부한다.
입력 검증에서 Git 디렉터리는 경로·장치·inode·파일 종류와 권한으로 식별한다.
`git status`의 임시 index lock이 바꾸는 디렉터리 수정 시각은 입력 권한의
변경으로 취급하지 않으며, HEAD·ref·config·워크트리 연결 파일 검사는 유지한다.
프로젝트 탐색 캐시는 기존의 수정 시각 기반 무효화도 유지한다.
원격은 140ms 요청 간격 안에서 입력 순서를 유지하고 출력 조회에도 실행 기회를 준다.
`node tests/workroom-input-lifecycle.e2e.mjs`는 Vite 9000에서 실제 React·xterm의
한글 IME 이벤트, 긴 입력, 출력 누적, 세션 전환·종료를 격리된 API로 검증한다.
macOS 입력기와 실제 설치본은 별도로 확인해야 한다.

장기기억 충돌의 병합 검토 버튼은 Claude/Codex에 짧은 검토 요청을 전달한다.
`POST /api/project-memory/preview-revision`은 현재 프로젝트 계보, 1MB 본문 한도,
SHA-256을 검증한 리비전 본문만 반환하며 복원·동기화·schema repair를 수행하지 않는다.
병합 초안 실행은 원본 적용이나 세션 기억 완료가 아니다.

V2 자동 기억 정리는 기본적으로 **이 프로젝트만 시험** 범위로 활성화한다. 서버가
등록 대상에서 확인한 `memoryId`를 정책에 고정하며 요청 본문으로 경로·memoryId를
받지 않는다. 다른 프로젝트와 나중에 등록한 프로젝트에는 자동으로 확대하지 않는다.
전체 등록 프로젝트 사용은 별도 범위 선택과 동의가 필요하다. 범위 변경은 먼저 끈 뒤
다시 동의해야 하며, 새 동의 이전의 완료 턴을 소급 처리하지 않는다.

프로젝트 시험에서는 다른 프로젝트의 기존 체크포인트 설정을 유지한다. V2 담당
프로젝트의 기존 체크포인트와 워크룸 종료 저장은 저장 완료로 표시하지 않고 대기한다.
프로젝트 제외도 기존 AI 저장으로 우회하지 않는다. 활성화는 workspace → app-data
순서의 lease와 같은 dispatcher를 거쳐 진행 중인 같은 프로젝트 저장과 겹치지 않는다.
전체 범위 활성화에서만 기존 체크포인트를 끈다. 끄기는 진행 중인 모델의 종료를 기다리지 않는다.

저장 DB schema 7은 범위를 이해하지 못하는 구버전이 데이터베이스를 열어 전체 저장으로
오인하지 못하게 한다. 기존 schema 6의 전역 동의·quota·완료 영수증은 그대로 보존한다.
등록 대상 ID는 순회할 프로젝트와 연결 worktree를 좁히는 힌트일 뿐이며, 실제 실행은
매번 memoryId·경로·등록 상태를 재검증한다. 대상이 삭제되거나 다른 기억으로 바뀌면
자동으로 다른 프로젝트를 선택하지 않는다.

자동 체크포인트는 기존 opt-in과 50/75/90% 정책을 유지한다. Codex rollout 기록과
Claude statusLine 실측값 + 같은 세션의 `end_turn`을 관찰하므로 어느 터미널 앱에서
실행했는지에 의존하지 않는다. 도중의 사용자 입력·tool_use·불완전 기록·subagent·
등록되지 않은 프로젝트는 저장 근거가 아니다. Claude는 상태 표시줄 capture가 필요하며
실측 사용률과 완료 신호를 제공하지 않는 Hermes·Antigravity에는 아직 적용하지 않는다.

자동 세션 기억 opt-in은 워크룸 종료에도 적용한다. 명시적 세션 종료, CLI의 자연 종료,
정상 앱 종료에서 세션 ID·등록 대상·cwd·AI만 0600 로컬 대기열에 남긴다. 출력 원문은
저장하지 않는다. CLI 종료 후 등록 경로와 canonical 기억 루트를 재검증하고 workspace
lease 아래 미저장 활동만 저장한다. Claude는 Claude로, 다른 CLI는 Codex로 기억을 갱신한다.
실패는 반복 호출하지 않고 로컬 워크룸에 표시한다. 원격 터미널 wire DTO에는 필드를
추가하지 않아 기존 포털과 호환되며 상세 저장 상태 API는 로컬 capability 전용이다.
완료·변경 없음 이력은 접힌 목록에서 확인하고, 대기·진행·실패·백업 대기·초기화
필요 항목은 별도로 표시한다. 화면 정리를 위해 원본 저장 작업을 삭제하지 않는다.
조회 실패는 이전 상태와 함께 명시하며 숨긴 화면의 늦은 응답은 적용하지 않는다.
CLI 종료가 지연되는 pending 작업은 대기열 뒤로 보내 다른 종료 세션의 저장이
막히지 않도록 한다. 한 번에 한 작업만 저장하고 실패 작업은 자동 재실행하지 않는다.
앱 완전 종료 중 대기·진행 중이던 저장은 다음 실행에서 재확인한다. 창 숨기기나 탭
이동은 종료로 취급하지 않으며, 강제 종료·전원 차단 직전 기록은 보장하지 않는다.
저장 실패와 Git 충돌·분기에는 워크룸 검토 연결을 제공하며 실제 적용을 자동 승인하지 않는다.
