# CS 대직: 선택한 자료로 프로젝트 질문 응답

설치된 macOS 앱의 프로젝트 상세에서 **CS 대직 · 질문 응답 설정**을 연다.
이 Mac에 로그인한 대직용 카카오톡 프로필 이름을 직접 확인해 적고, 채팅방 목록에서
대상을 선택한다. 공개 응답에 사용해도 되는 안내 자료와 FAQ를 작성하여 저장한다.
선택한 채팅방을 카카오톡에 열어 두고 실제 자동 전송 동의를 확인한 뒤 ON을 누른다.

- 켠 뒤 새로 들어온 `/cs 질문`, `#별칭 질문`, `/cs #별칭 질문`을 처리한다. 켜기 전 대화는 기준점으로만 사용한다.
- 직접 FAQ와 검토 승인된 자동 FAQ는 질문의 앞뒤 공백을 제거한 완전 일치로 응답하며 AI 토큰을 사용하지 않는다.
- FAQ에 없는 질문은 기본적으로 안내 자료에서 확인하지 못했다는 고정 응답을 보낸다.
- 답변 담당 AI와 세부 모델을 명시적으로 저장한다. Claude Code·Codex·Antigravity 선택 항목을 제공하며, 현재 자동 응답 연결은 Claude만 구현되었다. Codex·Antigravity는 연결 검증 전 ON을 막는다. 선택 후보 목록은 계정별 사용 가능 여부나 가격 보장이 아니다. Claude는 선택 모델과 low로 실행하며 다른 모델로 자동 대체하지 않는다.
  AI는 토큰을 사용한다. 최근 24시간 AI 호출 한도는 프로젝트당 1~20회, 모든 답변 시도는 100회다.
  실패·취소·전송 결과 불명확도 한도를 반환하지 않는다. 설정 변경이나 재시작으로 초기화하지 않는다.
- 저장은 대직을 끈다. 앱 재시작도 OFF다. 창을 닫거나 다른 프로젝트를 선택하는 것은 OFF가 아니다.
- OFF는 대기 작업과 실행 중인 자식 프로세스를 중단한다. 이미 전송된 메시지는 회수하지 않는다.

## 같은 채팅방에 여러 프로젝트 연결

각 프로젝트에서 같은 카카오톡 채팅방을 고르고 **프로젝트 호출 별칭**을 서로 다르게 저장한다.
별칭은 한글·영문·숫자·하이픈 1~30자이며 `#`는 입력해도 되고 생략해도 된다. 영문은 소문자로 정규화한다.
실제 카카오톡 사람 멘션과 무관한 텍스트 호출이며 장기기억의 공유 alias 레지스트리와는 별도인 대직용 설정이다.
방당 최대 8개 연결, 동시에 ON인 프로젝트는 이 Mac 전체에서 최대 8개다. 같은 방은 동일한 대직 프로필 이름을 사용한다.
기존 별칭 없는 설정은 유지되며, 여러 프로젝트를 함께 켜기 전에 각 별칭을 저장해야 한다.

- `#포털 이용 방법 알려줘`: `/cs` 없이 포털 프로젝트만 답한다.
- `/cs #포털 이용 방법 알려줘`: 위와 동일하다.
- `/cs 질문`: 연결된 프로젝트가 하나면 그 프로젝트가 답한다. 여러 개면 “프로젝트 2개가 연결되어 있습니다. 어느 프로젝트에 문의하시나요?”와 별칭 목록을 한 번 안내한다.
- `/cs`만 보내거나 잘못된 별칭을 부르면 질문 형식을 안내한다. `#포털`만 보내면 질문도 함께 보내 달라고 안내한다.
- 선택 안내 뒤에는 `#포털 질문 내용`으로 다시 보낸다. 이전 질문이나 프로젝트 선택을 사람 간에 공유하거나 추측하지 않는다.
- OFF/일시 중지인 프로젝트는 다른 프로젝트가 대신 답하지 않는다. 하나만 ON이어도 연결된 프로젝트가 여러 개면 별칭을 요구한다. 모두 OFF이면 안내도 전송하지 않는다.

방마다 한 번 읽은 새 메시지를 프로젝트별 ON 기준점과 대조하여 담당 프로젝트 하나에 배정한다.
검색 자료·FAQ·AI 호출 한도는 프로젝트별로 분리한다. 선택 안내는 AI를 쓰지 않고 답변 시도 한도에 포함된다.
전송 시도 전에 방의 다른 프로젝트를 포함한 중복 기록을 확인하고 저장한다. 처리 중 연결·별칭·ON 상태가 바뀌면 전송을 중단한다.

## 검색 자료 만들기 · 장기기억 선택 공유

설정을 저장한 뒤 **2단계 · 검색 자료(RAG) 만들기**에서 시작한다.

1. **자료 선택하기**으로 문서를 확인한다. **장기기억 항목도 선택**을 켜면 정본 기억의
   항목도 함께 표시한다. 파일·기억은 처음에 미선택이며 세션 일지·원문 대화는 포함하지 않는다.
2. 문서 파일과 기억 항목을 선택하고 **본문**을 확인한다. 현재 목록 전체 선택은 그 시점의 ID만
   선택하며 나중에 추가된 파일·기억이 자동 공유되지는 않는다. 개발 지침은 경고와 함께 표시한다.
3. **선택한 자료로 검색 자료 만들기**가 선택한 자료의 후보 사본과 로컬 SQLite FTS 색인을 만든다.
   생성·검색에는 AI를 호출하지 않는다. 생성 작업은 창을 닫아도 서버에서 계속되며 취소할 수 있다.
4. 후보에 포함된 본문을 검토하고 공유 확인란을 체크한 뒤 **이 자료를 답변에 사용**을 누른다.
   이 채팅방에 90일 동안 사용할 정확한 사본을 승인한다. 적용하면 자동 응답은 OFF가 된다.
5. **검색만 시험**은 검색 근거를, **AI 답변 시험**은 예상 답변을 표시한다. 시험은 카톡에 전송하지
   않는다. 실제 AI를 호출한 시험은 기존 최근 24시간 호출 한도에 합산한다.
6. **3단계 · 자동 답변 켜기**에서 전송 동의 후 ON한다. 선택 원본이 바뀌었으면 자료를 업데이트하거나
   **기존 승인 자료로 켜기**를 선택한다. 읽기 실패를 변경 없음으로 처리하지 않는다.

**원본 변경 확인 → 목록 확인 → 검색 자료 업데이트 → 후보 검토 → 적용**으로 갱신한다.
갱신 시 선택된 원본의 본문 hash를 다시 확인하고, 내용이 같은 자료는 기존 검색 구간을 재사용한다.
원본 전체는 질문마다 읽지 않는다. 후보 실패·취소는 기존 승인판에 영향을 주지 않는다.
새 파일은 자동 선택하지 않고, 기억의 안정 ID가 없는 항목이 바뀌면 다시 선택해야 한다.

**검색 자료 관리 → 검색 자료 공유 해제 → 공유 해제하기**는 승인 자료를 즉시 사용 금지하고 진행 중 답변을 취소한다.
이미 전송을 시작한 메시지는 도착 여부가 불명확할 수 있으며 자동 재전송하지 않는다.
자료 만료·방 변경·프로젝트 identity 변경도 검색·전송 전에 검사한다. 새 자료 적용과 철회는
기존 자료에서 만든 자동 FAQ의 재사용도 막는다. 원본 문서·장기기억 파일은 수정하지 않는다.

검색은 승인 집합만 대상으로 한국어 단어와 2글자 조각을 사용하고, 최대 6개 구간·본문 합계 16KiB를
모델에 전달한다. Claude의 구조화 출력에서 근거 ID를 검사하고 공유용 제목을 답변에 붙인다.
근거 ID 검증은 답변의 의미적 정확성 보증이 아니며, 관련 근거가 없으면 확인 불가로 답한다.
PDF는 macOS 기본 PDFKit으로 텍스트를 추출한다. 파일 50MiB·300쪽, 추출 텍스트 200KB까지이며 페이지 번호를 근거 본문에 보존한다. 암호화·손상·텍스트 없는 페이지는 이유를 표시하고 제외한다. 스캔·이미지 PDF는 OCR 처리 후 선택해야 하며, 텍스트를 읽지 못한 페이지를 조용히 누락하지 않는다. DOCX·OCR·외부 임베딩과 Codex/Antigravity 실행 연결은 이번 기능에 포함하지 않는다.

자료는 `cs-duty/knowledge.sqlite`에 저장한다. 설정과 승인판은 앱 재시작 후에도 남지만 자동 전송은 OFF다.
검색 색인 일부가 사라지면 승인판의 저장된 구간으로 복구하며, 최신 원본을 승인 없이 가져오지 않는다.
미승인 후보는 재시작 뒤 폐기하고 다시 만들도록 한다. 알 수 없는 DB schema는 초기화하지 않고 거부한다.

## 설정 창을 닫고 다시 열기

설정값과 자동 답변 실행 상태는 별개다. **설정 저장**(실행 중에는 **저장하고 대직 중지**)가 성공한 설정은
창을 다시 열거나 앱을 재시작해도 프로젝트별로 유지된다. 앱 재시작 후에는 자동 답변만
OFF이며, 다시 ON하려면 저장된 프로필·채팅방과 전송 동의를 확인한다.

- 미저장 입력이 있을 때 닫기 또는 Escape를 누르면 **저장하고 닫기 / 저장하지 않고 닫기 /
  계속 편집**을 표시한다. 저장 실패 시 입력과 창을 유지하고 실패 사유를 보여준다.
- 처음 열 때 저장값 조회가 완료되어야 편집할 수 있다. 조회 실패를 초기화된 설정으로
  표시하지 않으며 **설정 다시 확인**으로 재시도할 수 있다.
- 편집하지 않은 화면은 자동 FAQ를 포함한 최신 설정을 반영한다. 편집 중이라면 입력을
  보존하고 저장 revision 충돌을 표시한다. 다시 불러오기도 입력을 버리기 전에 확인한다.
- 이전 창이나 저장 이전에 시작한 조회 응답은 현재 화면을 덮어쓰지 않는다. OFF는 진행 중인
  ON보다 우선하고, OFF 응답을 기다리는 동안 중복 중지와 상태 조회를 보내지 않는다.

화면 회귀는 실제 전송을 차단한 fixture에서 다음과 같이 실행한다. 별도 터미널에서
`./node_modules/.bin/vite --host 127.0.0.1 --port 9421 --strictPort`를 먼저 실행한다.

```sh
node tests/cs-duty-ui.mjs
node tests/cs-duty-lifecycle-ui.mjs
DUTY_BROWSER=webkit node tests/cs-duty-lifecycle-ui.mjs
bun test ./tests/csDuty.test.ts ./tests/csDutyHost.test.ts
```

WebKit 실행에는 Playwright의 해당 브라우저가 설치되어 있어야 한다. 생명주기 회귀는
닫기·재열기·프로젝트 전환·빈 설정·조회/저장 실패·지연 응답·자동 FAQ·ON/OFF 경합과
StrictMode를 검사한다. 저장소 회귀는 임시 디렉터리에 실제 저장 후 새 컨트롤러에서 설정과
FAQ를 복원하고, 재시작 후 자동 답변은 OFF인지 검사한다. 이 검증은 설치 앱 교체나
실제 카카오톡 전송 검증을 뜻하지 않는다.

## 권한과 경계

카톡 프로필 이름은 운영자가 확인한 표시값이며 **보낸 사람 또는 승인자 인증이 아니다**.
현재 버전은 누구의 질문이든 동일한 질문 응답 권한만 제공한다. 파일 변경, 임의 명령,
주문·서비스 변경, 개발 워크룸 실행, 프로젝트 파일·장기기억을 임의로 읽는 기능이 없다. 운영자가 선택·승인한 자료 사본만 검색한다.
따라서 카톡으로 “승인”하거나 지시해도 수정 권한을 얻을 수 없다.

모델에는 저장된 직접 안내·사용 가능한 FAQ·승인한 검색 자료의 관련 구간과 질문만 전달한다. **「프로젝트 문서 불러오기」는 공유 범위를 넓히지 않는다** —
프로젝트의 보이는 `.md`·`.txt`를 골라 그 본문을 안내 자료 칸에 **채워 넣을 뿐**이고, 운영자가 화면에서 확인해
저장해야 실제로 쓰인다. 답변 시점에는 여전히 파일을 읽지 않는다. `.git`·`.agent-memory`·`.claude`·`.codex`처럼
점으로 시작하는 폴더와 그 안의 설정·자격증명은 목록에 나오지 않으며, 요청 경로는 검증된 프로젝트 루트에서 다시
파생해 탈출을 막는다(깊이 3, 파일 200개, 개당 200KB, 삽입 12KB 상한).
⚠️ 자료 칸에 「All」처럼 **권한을 뜻하는 말을 적어도 아무것도 열리지 않는다.** 그 칸은 권한이 아니라 본문이다.
직접 자료가 짧고 사용할 FAQ·검색 자료도 없으면 켜기 전에 보충 안내를 표시한다. 근거가 부족한 질문에는
확인할 수 없다고 답한다. 전용 앱 데이터 작업 디렉터리에서
파일 도구, MCP, 슬래시 명령, 설정 소스, 대화 영구 저장을 끄고 한 턴만 실행한다.
프로젝트 루트에서 모델을 실행하지 않는다. 자료에 비밀을 넣으면 응답으로 노출될 수 있으므로
공유 허용한 자료만 입력해야 한다. 승인자 계정 연결이나 강한 계정 인증은 이번 범위가 아니다.

로컬 API는 기존 Agent Runtime의 Tauri origin 및 별도 capability 검증을 사용한다.
QR·외부 포털에 이 경로를 공개하지 않는다. 설치 Mac의 등록 프로젝트 ID만 받고
작업 전 실제 프로젝트 경로/디렉터리 identity를 다시 확인한다.

## 카카오톡 어댑터와 한계

설치된 외부 `kmsg 1.260729.0` CLI를 사용한다. 앱에 MCP 전체를 복사하거나 자동 설치하지 않는다.
버전이 바뀌면 재검증 전 활성화하지 않는다. CLI는 카카오톡 공식 서버 API가 아닌
macOS 접근성 기반 UI 자동화이므로 접근성 권한, 로그인된 카카오톡, 노출된 대상 대화창이 필요하다.
읽기는 `--background-safe`, 전송은 정확한 로컬 chat ID로 dry-run 확인 후 한 번만 실행한다.
목록 확인과 전송은 카카오톡 창을 앞으로 이동시킬 수 있다.

로컬 chat ID는 카카오 서버의 계정 인증값이 아니다. 동명 채팅방을 거부하고
채팅방 레지스트리, 실행 파일, 카카오톡 PID/시작 시각 변경을 확인한다.
같은 프로세스 안의 계정 전환을 완전히 검출할 수 없으므로 계정 전환 전에 OFF해야 한다.
본인으로 표시되거나 작성자를 확인하지 못한 메시지, 첨부 메시지는 응답 대상에서 제외한다.
히스토리 연속성이나 전송 결과를 확인하지 못하면 일시 중지하며 자동 재시도하지 않는다.

## 저장·자원

앱 데이터 `cs-duty/settings.json`(0600), 디렉터리 0700에 설정·사용량만 원자적으로 저장한다.
원문 대화 로그는 저장하지 않는다. 자동 FAQ를 켜면 채택한 질문·답변을 FAQ로 저장한다. 중복 판별은 메시지 SHA-256이며 암호화는 아니다.
설정 최대 64개, 동시 ON 최대 8개, 프로젝트 자료/FAQ 합계 40KB, 최근 메시지 50개,
사용량 최대 6,400개다. 전역 5초 tick이 프로젝트를 하나씩 순환하므로 8개가 켜지면
기본 확인 간격은 약 40초에 작업 시간이 추가된다. 읽기/답변/전송은 전역 직렬 실행이다.
CLI 출력 상한은 256KB, AI 실행 120초, 한 tick 180초, 켜기 확인 60초로 제한한다.
종료 시 자식 작업의 취소·종료를 기다린다. 개발 API에서는 실행을 지원하지 않는다.

## 왜 아무 일도 일어나지 않는가 — 연결 진단

대직이 멈추는 원인은 여러 가지인데 예전에는 전부 «연결하지 못했습니다» 한 줄로 합쳐졌다.
그래서 운영자가 무엇을 고쳐야 하는지 알 수 없었다. 이제 실패 사유는 그대로 화면에 남고,
「연결 진단」 버튼이 전제 조건을 **하나씩 따로** 검사해 어느 단계가 막혔는지 보여준다.
한 검사가 실패해도 멈추지 않고 나머지를 계속 검사한다.

| 검사 | 실패하면 |
|---|---|
| kmsg CLI 설치 | 설치 경로에 실행 파일이 없다 |
| kmsg 검증 버전 1.260729.0 | 설치된 버전을 함께 알려준다 |
| 카카오톡 실행 중 | PID를 찾지 못했다 |
| 채팅방을 하나로 구별 | 동명 채팅방이거나 레지스트리에 없다 |
| 채팅방 창이 열려 있어 읽기 가능 | **이 채팅방을 별도 창으로 열어 두어야 한다** |
| 답변 AI 실행 경로 | Claude 외 provider는 아직 검증 중이다 |
| Claude CLI 설치 | 실행 파일이 없다 |

⚠️ **가장 흔한 원인은 마지막에서 두 번째다.** 읽기는 `--background-safe`라 카카오톡 창을
**대신 열지 않는다.** 채팅방을 목록에서 선택만 해 둔 상태는 «노출»이 아니라서 kmsg가
`BACKGROUND_SAFE_BLOCKED`로 거절한다. 실측(2026-09-09): 창을 닫아 둔 상태에서 read가 exit 1,
같은 방을 창으로 열자 즉시 성공했다. 진단의 이 항목이 그 차이를 문장으로 알려준다.

⚠️ 그리고 대직은 **`/cs `로 시작하는 새 메시지에만** 답한다. 그냥 말을 걸면 설계상 무시하며,
**켜기 전에 이미 있던 메시지도 답하지 않는다**(기준점). ON 상태 표시가 기준점 건수를 함께
보여주는 이유다 — 이 규칙이 화면에 없을 때 «켰는데 아무 반응이 없다»로 읽혔다.

실패 문구는 패널에 그대로 나가므로 **경로·stderr·비밀을 담지 않는다.** 명령 실패는 어떤
명령이었는지와 종료 코드까지만 밝히고, 알 수 없는 오류는 일반 문구로 떨어뜨린 뒤 진단을 권한다.

## 자동 FAQ

자동 적재를 켜면 성공적으로 전송한 AI 답변을 **검토 대기 FAQ**로 보존한다. 정상 전송은 정답 검증이
아니다. 운영자가 확인하고 재사용을 승인한 답변만 동일 질문에 사용한다. 기존 버전의 자동 FAQ도
검토 승인값이 없으면 재사용하지 않고 보존한다. 알려진 불확실성 표현은 후보 수집에서도 제외한다.

후보에는 직접 안내·직접 FAQ·승인 자료 버전의 지문을 기록한다. 자료를 바꾸거나 공유를 해제하면
이전 지문은 재사용하지 않는다. 문구 수정은 검토 승인을 해제하되 출처 지문은 유지한다.
후보 저장도 설정 revision을 전진시키므로 오래된 화면은 최신 내용을 덮어쓰지 못한다.
최대 30개·직접 자료 포함 40KB이며 가득 차면 기존 항목을 삭제하지 않고 추가 수집을 멈춘다.

## 다른 단말·다음 AI 작업 인계

이 기능은 아직 실험용이다. 어댑터 전 경로는 동의한 테스트 채팅방 하나에서 실제로 실행해 확인했으나(위 표),
감시 루프를 켠 채 여러 사람이 오가는 실제 운영 방에서 장시간 돌린 적은 없다.
다른 단말에서는 원격 기본 브랜치를 안전하게 Pull하고 이 저장소의 `bun run verify`, `bun run test:smoke` 절차를 따른다.
설정 화면 단독 테스트는 격리된 Vite 서버의 `tests/fixtures/cs-duty.html`과 `TARGET=http://127.0.0.1:<port> node tests/cs-duty-ui.mjs`를 사용한다.
이 fixture는 전송을 가짜 응답으로 대체한다. 실제 감시·응답은 공식 macOS 빌드와 안전 설치를 마친 설치 앱에서만 가능하다.
각 Mac에서 자신의 카카오톡·Claude 로그인과 접근성 권한, 프로필·방·전송 동의를 새로 설정한다. Git Pull은 카톡 계정이나 대직 설정을 복사하지 않는다.

다음 구현 순서:

1. Codex의 기존 `codexAgentRuntime.ts` 도구 없는 read-only 대화 경로와 실제 모델 목록을 검토해 대직 어댑터를 연결한다. 단순 read-only 파일 권한만으로 도구 격리를 대신하지 않는다. 대직 호출의 보관 기록·취소·종료 수명도 제한한다.
2. Antigravity는 설치 `agy models`에서 모델을 조회할 수 있지만 `--mode plan --sandbox`만으로 모든 파일/MCP 변경을 막는다고 가정하지 않는다. 실제 질문 전용 실행 경계를 검증한 뒤 ON 제한을 해제한다.
3. 현재 세부 모델은 선택 후보 프리셋이다. 계정별 실시간 모델 목록과 지원하는 낮은 추론 등급을 연결하고, 선택 모델 사용 불가 시 다른 모델로 자동 전환하지 않는다.
4. 선택한 문서·curated 기억의 승인 사본 검색과 업데이트는 위 흐름으로 구현했다. 다음 확장은 문서 구간 선택·공유용 편집본·DOCX 등 추가 형식이다.
5. 별도 동의한 테스트방에서 Codex → Antigravity 순서로 실제 수신·응답·OFF·오류 후 중복 방지를 검증한다.
   Claude 경로의 개별 어댑터 호출(진단·목록·읽기·답변·전송)은 실제로 실행해 확인했다. 남은 것은
   **ON 상태의 감시 루프가 타인의 새 `/cs` 메시지를 받아 답하는 왕복**이다 — 그 방의 메시지가 전부
   본인 계정으로 보이는 단말에서는 설계상 검증할 수 없으므로, 대직 계정과 질문자 계정이 다른 두 단말이 필요하다.

## v430 운영 중 확인한 보완

- 12.5MiB 실제 PDF가 기존 10MiB 제한으로 숨겨진 문제를 고쳤다. PDF 입력 상한은 50MiB이며 추출 텍스트 200KB·300쪽 제한은 유지한다. 읽을 수 없는 자료도 목록에서 사라지지 않고 비활성 항목과 이유로 표시한다.
- 기존 별칭 없는 설정은 프로젝트명에서 별칭을 제안하고 저장 필요를 표시한다. 별칭 저장 전에는 그 별칭으로 호출할 수 없다.
- `kmsg read --background-safe --trace-ax`의 행 집계에서 unique와 filtered가 다르면 최신 대화가 제외된 불완전한 읽기로 처리한다. 진단 집계가 없거나 모순돼도 정상 대기로 표시하지 않는다. 원문이 섞인 trace는 메모리에서 집계만 검사하고 로그·DB에 보관하지 않는다.
- **채팅창 다시 열기**는 같은 방의 대직을 모두 OFF로 만들고, 정확한 저장 chat ID에 대한 기존 kmsg 읽기 명령으로 창만 앞으로 연다. 키 입력이나 메시지를 보내지 않으며, 사용자가 맨 아래 대화를 확인하고 다시 ON한다. 백그라운드 tick은 창을 강제로 활성화하지 않는다.
- 2026-09-10 해당 단말에서 창을 앞으로 열기 전후 kmsg의 읽기 결과가 12건→18건으로 달라졌고, 누락됐던 `/cs`와 `#9월1일테스트`가 읽기 결과에 나타남을 확인했다. 이 확인은 자동 답변 전송 테스트와 별개다.

## N:N connections and isolated KakaoTalk transport (v431)

A registered project may have up to eight room connections; a room may contain up to eight projects. The host still limits active connections to eight and saved connections to 64. The legacy `targetId` remains its first connection ID. Extra `duty_<uuid>` IDs carry immutable `projectTargetId`; all registered-path resolution uses that project while knowledge, consent, budgets, FAQ, baselines and OFF remain connection-scoped. Creating another connection copies only connection/model preferences, clears all knowledge and FAQ, disables AI and starts OFF. Existing approved sources never become available in another room implicitly. One project cannot be connected twice to the same room.

`vendor/kmsg` is a MIT-licensed, pinned-source app-private transport (`1.260910.1`); the user's global `kmsg` is unchanged. Build-sidecar compiles it into the app resource directory on macOS. Reads and sends require exact AX window ancestry (or AXWindow identity), positive writable-composer evidence and exact unique window titles. Read caches and focused-input fast paths may not supply another window's composer or transcript. This fixes the observed 20-message CS room being read as the 45-message investment room while JSON still carried the requested title. Sending refuses cross-window or changed focus and removes forced typing and ambiguous Enter retry. Chat discovery refuses a conversation window lacking the Chats navigation control, preventing message dates/authors from becoming fake chat registry entries. Actual message sends are distinct from read-only two-window verification.

### v432: 비활성 창의 새 질문 누락 수정

카카오톡이 비활성 채팅창에 새 메시지를 추가하면 해당 행의 화면 좌표가 입력창 아래로
계산될 수 있다. v431의 좌표 필터는 이 행을 제외했고 완전성 검사가 대직을 중지했다.
내장 도구 1.260910.2는 검증된 대화 영역의 유일한 표에서 AX 자식 행 순서를 그대로
읽는다. 화면 좌표로 행을 제외하거나 정렬하지 않으며 복수 표·10,000행 초과는 거부한다.
방 소유권·고유 제목 검사, 최근 자료 상한, 전송 전 재검증은 유지한다.
실제 비활성 CS 창의 19:15 질문은 기존 도구에서 누락됐고 수정 도구에서 인식됐다.
