# 앱 완성도 개선 단계

2026-10-20 최초 평가는 **65/100점**, v1137 설치 뒤 잠정 평가는 **70/100점**,
v1139의 Mac·물리 iPhone 검증을 마친 현재 평가는 **75/100점**이다.
1차 목표는 **90점**이다. 현재 평가는 이번 점검에 근거한 주관적 실사용 평가이며,
테스트 개수나 관측 기록을 합산해 자동 승급하지 않는다. 설치본·실제 입력·실제 AI·외부망의 근거를
각각 확인한다. 최신 소스와 다른 결과나 격리 응답을 실제 대화 성공으로 계산하지 않는다.

| 목표 | 사용자에게 보장할 동작 | 승급에 필요한 근거 |
|---|---|---|
| 75 · 핵심 흐름 | 첫 업무 작성·전송·응답 확인·지난 대화 재개를 설명 없이 완료한다. 비활성 버튼은 연결·프로젝트·권한·처리 중 이유를 보여 준다. 탭 이동 뒤 늦은 응답은 현재 화면을 바꾸지 않는다. | Mac 및 iPhone 13 계열의 실제 입력, 동일 소스 설치본, 실제 AI 답변과 같은 대화 재개. 이 중 미확인이 있으면 승급 보류. |
| 85 · 중단 후 복구 | 네트워크 단절·기기 잠금·앱 재시작 뒤 초안과 선택 대화를 찾고 요청을 중복 실행하지 않는다. 권한 해제 후에는 과거 응답으로 다른 프로젝트를 열지 않는다. | 각 기기에서 중단 전후의 동일 요청·세션 영수증 비교. LAN·외부망은 각각 수행하며, 외부망 미수행을 LAN 통과로 대체하지 않는다. |
| 90 · 주요 기능과 반복 안정성 | 프로젝트 찾기·첫 업무·대화 재개·기록과 기억 저장·설정과 권한 확인을 처음 쓰는 사람도 이어 수행한다. 업무·대화·워크룸의 이름과 다음 행동이 일관되고, 작은 화면에서 입력·버튼·결과가 가려지지 않는다. | 같은 설치 버전에서 기기별 핵심 여정 10회, 두 기기의 재시작, 48시간 자원 관측과 기존 페르소나·관련 회귀 결과. 처음 쓰는 사람의 설명 없는 수행을 별도 확인한다. 치명적 기능 실패·데이터 유실·중복 실행은 0건이어야 한다. |

90점이 안정되면 실제 사용 중의 재발률·지원 요청·지연을 근거로 95점을 검토한다.
48시간 관측과 실제 사용자 확인은 이후 실행할 조건이며, 이 계획을 저장한 것으로 완료되거나 예약되지 않는다.

## 단계별 실행 순서

1. **75점: 핵심 여정부터 마친다.** 설치한 Mac 앱에서 첫 업무 작성·전송·실제 응답·같은 대화 재개를
   확인한다. 실제 iPhone 13 계열에서 키보드·한글 입력·전송을 확인한다. 실패가 나오면 바로 재현 검사와
   수정을 붙이고 같은 기기에서 다시 확인한다. 현재 연결된 실기는 iPhone 13 Pro Max이며,
   일반 iPhone 13의 화면 크기에 대한 브라우저 검사를 같은 물리 기기 검사로 표시하지 않는다.
2. **85점: 끊겼다가 돌아오는 경우를 마친다.** 전송 직전·응답 대기 중·재개 직후 각각 네트워크를
   끊고 복구한다. 기기 잠금·앱 종료와 재실행·권한 해제·기기 및 프로젝트 전환 뒤 초안·대화·영수증을
   비교한다. LAN과 외부망 결과를 따로 남기며, 불확실한 실행은 상태 조회로 확인한다.
3. **90점: 앱의 주요 흐름으로 넓힌다.** 처음 쓰는 사용자, 기존 프로젝트 작업자, 외부에서 이어가는
   사용자, 중단 후 돌아오는 사용자와 큰 글씨를 쓰는 관점을 기존 페르소나와 대조한다. 실제 검사에
   없는 여정은 후보로만 남긴다. 같은 설치 버전에서 위 표의 반복·자원·실제 사용자 조건을 확인한다.

한 단계에서 재현 가능한 핵심 결함이 남으면 그 단계를 완료로 표시하지 않는다.
새 기능을 추가하기 전에 해당 단계에서 사용자가 막힌 여정을 먼저 수정한다.

## v1139의 75점 완료와 85점 검증

- 정식 서명·공증한 v1139에서 Mac의 첫 입력·실제 답변·저장 대화 재개와 물리 iPhone 13 Pro Max의
  한글 자모 조합·키보드를 연 채 첫 업무 전송·실제 답변·같은 제공자 대화 재개를 확인했다.
- 사용자 승인으로 현재 아이폰에 기록 조회·재개 및 검증 프로젝트만 추가 허용했다.
  기존 허용 대상·다른 기기 권한·만료일을 보존했다.
- 일반 Codex 실행이 호스트의 전역 권한 우회 설정을 상속하던 문제를 수정했다. 양 기기의 새 실행과
  재개에서 `on-request`·`workspace-write`를 확인했고, 호스트 전역 설정은 바꾸지 않았다.
- 같은 v1139의 Mac 호스트를 정상 종료·재시작한 뒤 자동 실행은 0건이었다. 아이폰에서 검증 세션
  하나만 명시적으로 재개했고, 원래 대화와 미전송 초안을 찾았다. 다른 세션은 재개하지 않았다.
- 재연결 후 검증 프로젝트를 목록에서 다시 찾는 데 혼선이 있었다. 첫 페이지와 전체 프로젝트 로드,
  워크룸 대상 목록의 관계를 후속 검증한다. 이름으로 다른 프로젝트를 대신 선택하지 않는다.
- 85점의 네트워크 전환·잠금 검증은 별도 사용자 응답을 기다린다. 90점의 같은 버전 기기별 10회,
  48시간 관측·처음 쓰는 사람의 수행은 아직 완료하지 않았다. 예약된 시간별 관측도 승급 판정은 아니다.

다음 수정 묶음은 큰 사용자 지침 때문에 테스트 관리 상태가 열리지 않는 문제와, 같은 제목·분의 저장
대화를 구분하기 어려운 문제를 다룬다. 지침 원문과 경로 보호를 유지하고 공통 러너는 새 버전으로
배포한다. 대화의 구분은 기존 허용된 시각 정보로 하며 제공자 ID나 로컬 경로를 휴대폰에 추가하지 않는다.
수정 소스의 회귀 통과와 설치본 실기 재확인은 각각 기록한다.

## v1137까지 확보한 근거와 남은 확인

- 첫 업무 진입·안전한 요청 ID·화면 전환 후 늦은 재개 응답을 수정하고 Chromium·WebKit 회귀를 통과했다.
- 실제 Codex의 첫 답변·후속 답변·같은 제공자 대화 재개를 확인했다. 설치 화면 전체 왕복과는 별도 근거다.
- Developer ID 서명·앱 및 DMG 공증·Gatekeeper 검사를 거친 v1137을 이 Mac에 설치·실행했다.
  프로젝트 143개와 기억·설정 비교 파일 58개의 보존, 설치된 관리 API의 개선 기록 저장·재조회를 확인했다.
- 설치된 Mac 화면에서 한국어 붙여넣기 → Enter 전송 → 실제 답변 → 종료 → 저장된 대화 이어 열기 →
  이전 식별자 회상을 확인했다. Mac의 한글 자판 조합 입력은 이 결과에 포함하지 않는다.
- 물리 iPhone 13 Pro Max에서 실제 키보드를 열고 자음·모음 키를 터치해 `한글` 조합과 초안 유지를
  확인했다. WDA는 Xcode의 기존 서명된 테스트 러너로 실행해 초기화 문제를 해결했다.
  TestFlight 껍데기는 1135이며 실제 웹 화면에는 1137 / `64e3e05`가 표시됐다.
- iPhone의 지난 대화는 현재 연결의 기록 조회 권한이 꺼져 있어 차단됐다. 조회·이어 열기 및 검증
  프로젝트 권한 확대는 사용자 확인을 받았다. 기존에 허용된 프로젝트에서는 실제 한글 키 입력·업무
  전송·실제 Codex 답변을 확인했다. 지난 대화의 실제 재개와 수정 배포 후 재확인은 남아 있다.
  이 상태에서 75점으로 올리지 않는다.
- 로컬 전체 검증은 통과했으나 GitHub Actions는 계정 결제·사용 한도 문제로 실행되지 못했다.

## 75점 단계의 첫 수정 묶음

- **재현:** 재개 요청 뒤 다른 탭으로 이동하는 실제 구조는 컴포넌트를 해제하지 않고 `visible=false`로
  숨긴다. 화면 해제만 막던 이전 구현에서 늦은 성공 응답이 숨겨진 화면의 세션 선택을 실행했다.
- **수정:** 표시 여부·기능 사용 가능 여부·연결 상태를 요청의 화면 결속에 포함한다. 서버에 보낸 요청은
  정리하되 현재 화면을 열지 않는다. 영수증으로 결과 확인을 계속할 수 있게 한다.
- **혼동 제거:** 조회·재개·결과 확인의 진행 문구를 구분한다. 연결 끊김과 프로젝트 미허용을 설명하고,
  오프라인 상태에서는 조회를 보내지 않는다. 권한 오류는 조회·재개의 실제 권한 이름과 재조회 동작을 안내한다.
- **회귀:** `phone-workroom-history-screen`은 Chromium·WebKit의 실제 React 화면에서 화면 숨김·기능 해제·
  연결 끊김·오프라인 조회 금지·빈 프로젝트·권한 확인 후 재조회를 검증한다.
- **추가 실기 결함:** 아이폰 키보드를 열면 사용 중이 아닌 하단 OPS 입력창이 업무 전송 버튼을 가렸다.
  업무 작성·선택 대화에서는 해당 창만 보이지 않게 하고, 소유자와 초안은 마운트한 채 보존한다.
  실제 통화 중의 조작 버튼과 다른 화면에서의 입력창은 유지한다. Chromium·WebKit의 짧은 화면에서
  전송 버튼의 터치 수신·화면 복귀·초안 보존을 회귀로 확인한다.
- **Mac 검색:** Cmd/Ctrl+F가 현재 프로젝트 검색칸을 가리키지 않던 ref 누락을 수정했다.
  실제 App을 그린 Chromium·WebKit에서 검색 포커스·한글 필터·Escape 두 단계 복귀를 검증한다.
- **권한 저장:** 기존 기기 허용 목록에 일시적으로 조회되지 않는 워크트리가 남아 있으면 새 검증
  프로젝트 하나를 추가해도 저장 전체가 거절됐다. 같은 기기·호스트의 유효한 기존 허용 항목은
  보존할 수 있게 하고, 새 항목은 현재 등록 목록에 있어야만 저장한다. 만료·철회·다른 기기의
  기존 항목을 재사용할 수 없고, 실제 요청 시 프로젝트 재해석과 권한 검사는 유지한다.
- **실제 CLI 권한:** v1138에서 두 기기의 첫 업무·실제 응답·같은 대화 재개는 성공했다. 그러나
  원격 재개 화면의 「권한 우회 없음」과 달리 Codex `/status`는 Full Access를 보였다. 우회 인자를
  생략하면 호스트의 `approval_policy=never`, `sandbox_mode=danger-full-access`를 상속하기 때문이다.
  일반 Codex 실행·재개에는 `on-request`·`workspace-write`, Claude에는 `default`를 명시한다.
  전역 설정과 명시적으로 선택한 우회 실행·제한 실행은 유지한다. 이 수정의 정식 설치본에서 실제
  권한과 대화 재개를 다시 확인하기 전에는 75점 승급을 보류한다.

## 반복 실행과 이력

### 프로젝트 목록 자동 업로드의 로컬 잠금 안내

v1143의 기존 앱 오류 로그에서 `portal.json` 저장 잠금을 3초 안에 얻지 못해 초기 로드와
자동 업로드를 중단한 기록을 확인했다. 이 오류는 일반적인 원인 미확인 안내로 표시됐다.
Rust의 문자열 오류와 sidecar의 `Error`·중첩 오류를 모두 로컬 저장 잠금으로 분류하고,
관련 작업이 끝난 뒤 앱을 다시 열어 원격 상태를 확인하도록 안내한다.
자동 업로드 허용 조건이나 잠금 수명·복구·재실행 동작은 이 안내 수정으로 바뀌지 않는다.
상단 알림은 기존 도구 안내만 열며 Push·Pull을 실행하지 않는다.

회귀 검사는 `port-auto-upload-status.test.ts`의 실제 두 런타임 오류 형식을 사용한다.
기존 `cautious-sync-user` 페르소나가 같은 검사를 실행한다. 과거 잠금의 소유 프로세스는
확인되지 않았으므로 이후의 검증용 작업공간 잠금 탓으로 단정하지 않는다.

### 기존 기억의 클라우드 상태 재확인

v1141에서 기존 로컬 기억이 있는 카드에 `Supabase 확인 실패`만 남고 원인과 재확인 버튼이
보이지 않는 상황을 관측했다. 별도의 읽기 전용 조회와 설치 sidecar의 정상 상태 경로에서는
동일한 로컬·원격 해시를 확인했다. 직접 소유한 작업공간 잠금으로도 실패 경로를 재현했지만,
그 잠금이 앞선 관측의 원인이었다고 단정하지 않는다.

기존 기억 카드에도 실패 이유와 `Supabase 다시 확인`을 표시한다. 이 버튼은 상태만 다시
조회하며 백업·복원을 실행하지 않는다. 조회 중 중복 클릭을 막고 성공하면 이전 실패 안내를
지운다. 실패 상태의 배지는 주의 색으로 표시한다. 로컬 상태만 갱신하는 포커스·주기 조회는
클라우드 성공으로 표시하지 않는다.

관련 검사는 기존 `workroom-improvement` 프로필의 `memory-status-contracts`·`memory-status-screen`이다.
격리한 실제 React 화면에서 기존 기억·오류 이유·재확인·중복 클릭·변경 요청 0건을 확인한다.
데스크톱·모바일 크기 검사는 물리 iPhone 검증과 구분한다.

`python3 scripts/agentstoz-maintainer.py run --root . --profile workroom-improvement`를 실행하고,
변경한 여정에 해당하는 구성된 페르소나를 `personas run --persona <id>`로 실행한다.
전체 교차 검증은 `personas run --root .`으로 한다. 같은 근거 검사는 중복 실행하지 않는다.

관측·수정·재확인은 기존 `.agentstoz/maintainer/improvements.json`에 같은 상황으로 누적한다.
각 항목에는 기기·환경·확인 버전과 근거를 남긴다. 최초 관측과 누적 횟수는 유지하고 최근 상세 기록은
6개로 제한한다. 미확인 상태와 자동 검사 실패를 구분하며, 실패한 단계를 완료로 바꾸지 않는다.

진행 근거는 `.agentstoz/maintainer/quality-progress.json`과 해당 회귀·실기 증거에 둔다.
정식 설치·배포는 clean source와 실제 원격 기본 브랜치 HEAD 일치를 확인하는 기존 출하 가드를 따른다.
출하 가드를 우회한 로컬 검증물을 기존 정식 설치 앱으로 교체하지 않는다.

실제 제공자 대화의 별도 검증은 `bun scripts/check-workroom-live-codex.ts --live-codex`로 명시적으로
실행한다. 자동 검사 프로필에는 포함하지 않는다. 기존 Codex 계정과 모델을 사용하고, 읽기 전용의 빈
임시 Git 프로젝트에서 최대 3개 요청으로 첫 답변·후속 답변·같은 대화 재개를 확인한다. 응답 문자열과
제공자 transcript의 턴 완료를 함께 확인하며, 재개 후 입력 준비가 확인되어야 후속 요청을 보낸다.
네이티브 신뢰 확인이 필요하면 중단한다. `--trust-empty-fixture`를 추가한 경우에만 경로와 빈 폴더를
검증한 자신의 임시 프로젝트 신뢰 확인을 한 번 진행한다. 일반 프로젝트의 권한 정책은 바꾸지 않는다.
실제 제공자 사용에는 추론 비용이 발생할 수 있으며, 이 결과도 설치 앱의 전체 UI 검증과 구분한다.
