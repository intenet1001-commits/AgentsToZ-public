# 아젠투지별 기기 운영기억

프로젝트 지식은 프로젝트 전용 기억과 클라우드 공통기억에 둡니다. 단말 환경과 운영 습관은 해당 아젠투지의 기기 운영기억에 둡니다. 별도 ‘Mac 공통기억’을 새로 만들지 않습니다.

기존 OPS 운영 폴더는 여러 기기가 공유하는 부모 기억입니다. 이를 바꾸거나 분리하지 않고 `profileId + deviceId`에서 결정되는 자식 memoryId를 사용합니다. 표시 이름을 바꿔도 기억은 바뀌지 않습니다. 로컬 원본은 앱 데이터의 `device-operating-memory/<profileId>/<deviceId>` 아래이며 기존 장기기억 revision 백업으로 클라우드에 별도로 보관합니다. GitHub 계보가 없는 자식 기억에 프로젝트나 OPS 저장소의 계보를 부여하지 않습니다.

Mac의 아젠투지 설정과 모바일 기록의 ‘아젠투지별 기억’에서 조회·저장·백업 재시도를 합니다. 모바일은 연결한 호스트의 기억을 다루며 `ops-memory.manage`를 별도로 허용해야 합니다. 기존 공통기억·프로젝트 터미널 권한으로 자동 허용하지 않습니다. 다른 기기로 중계하지 않고 관리할 기기에 직접 연결합니다. 읽기에는 디렉터리 생성, AI 호출, 키 준비 또는 클라우드 쓰기가 없습니다.

OPS 회상에는 현재 기기 자식 기억과 기존 공유 운영기억이 함께 들어가며 출처를 구분합니다. 한 번에 4개 기기 항목, 전체 8개 항목/16 KiB를 넘기지 않습니다. 공유 OPS의 AI 제안·사람 승인 절차는 그대로 유지합니다.

모바일의 이전 로컬 기억 조회·이관은 기존 `meta-memory.manage` 권한도 함께 요구합니다. 새 기기 기억 권한만으로 기존 공통기억 내용을 노출하지 않습니다.

이전 로컬 기억은 항목별로 출처·리비전·대상 기억을 검토합니다. 후보·충돌·보관 항목과 이미 클라우드 공통기억으로 이관된 그룹은 기기 기억으로 이동할 수 없습니다. 새 기기 기억의 로컬 저장과 클라우드 백업이 성공해야 이전 항목을 `superseded`로 바꾸며 원문·이력을 보존합니다. 그 사이 출처가 바뀌면 적용을 중지하지 않고 다시 검토하도록 알립니다.

모든 쓰기는 호스트가 확인한 기기 식별자, 문서 해시와 요청 UUID에 결속됩니다. 같은 요청에 다른 내용을 넣으면 거부합니다. 응답이 끊기거나 클라우드 백업이 실패하면 입력·동일 요청을 유지하고 사람이 재확인합니다. 백업 실패가 로컬 저장을 취소하지 않습니다. 심볼릭 링크, 다른 기기, 예전 리비전으로 덮어쓰지 않습니다.
