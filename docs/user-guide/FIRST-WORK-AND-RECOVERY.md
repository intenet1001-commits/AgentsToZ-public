# 첫 업무부터 기억 저장까지

프로젝트는 일할 폴더입니다. 폴더 등록에는 서비스 계정이 필요 없습니다. AI 작업에는 사용할 AI의 설치·인증이 필요하며, 클라우드 백업과 다른 기기 연결은 별도로 준비합니다.

1. **프로젝트·폴더 → 새 프로젝트 만들기** 또는 **가지고 있는 폴더 열기**로 일할 폴더를 등록합니다.
2. 프로젝트에서 **워크룸**을 열고 사용할 AI 하나를 연결합니다. 작은 작업을 맡기고 실제 결과와 검사 내용을 확인합니다.
3. 프로젝트의 **기억 저장 상태**에서 기억 파일과 새 활동을 확인합니다. 기억이 없으면 먼저 준비하고, 새 활동이 있으면 **세션 기억하기**를 실행합니다.
4. 저장 결과에서 **로컬 저장**과 **클라우드 사본**을 각각 확인합니다. 클라우드 백업을 사용하지 않으면 이 기기의 기억으로 계속 일할 수 있습니다.

OPS 운영 프로필은 여러 프로젝트의 운영 방식이 필요할 때 준비합니다. 첫 프로젝트 등록의 필수 조건은 아닙니다. Mac 헬프데스크의 **로컬 프로젝트부터 시작**으로도 프로젝트 화면에 갈 수 있습니다. 클라우드 설정을 선택하면 기존 GitHub·Supabase 인증과 전용 저장소 연결 검사를 마쳐야 합니다.

## 상태별 다음 행동

| 표시 | 의미 | 다음 행동 |
|---|---|---|
| 기억 파일 준비됨 | 이 폴더에서 기억 파일을 확인했습니다 | 워크룸에서 작업한 뒤 새 활동을 확인합니다 |
| 새로 저장할 활동 없음 | 현재 감지한 범위에서 추가 저장할 활동이 없습니다 | 다음 작업을 이어갑니다. AI 작업 성공이나 첫 세션 저장의 증명은 아닙니다 |
| 활동 상태 확인 필요 | 활동 확인을 완료하지 못했습니다 | **기억 상태 다시 확인**을 누릅니다 |
| 로컬 저장 완료 · Supabase 백업 확인 필요 | 기억은 이 기기에 있고 백업을 확인해야 합니다 | **장기기억에서 백업 확인**으로 해당 프로젝트를 엽니다. 같은 대화를 다시 저장하지 않습니다 |
| 연결 상태 확인 필요 | 현재 클라우드 상태를 확인하지 못했습니다 | **Supabase 다시 확인**으로 조회합니다. 조회만으로 기억을 올리거나 내려받지 않습니다 |
| 백업 필요 | 로컬 기억을 클라우드에 반영해야 합니다 | **Supabase 동기화**를 누르고 결과를 확인합니다 |
| 양쪽 변경 검토 필요 | 로컬과 클라우드의 변경을 비교해야 합니다 | **동기화 충돌 검토**에서 양쪽 내용을 읽고 적용할 내용을 검토합니다 |
| 중단된 저장 결과 확인 필요 | 이전 작업의 저장 결과가 확정되지 않았습니다 | **저장 상태·복구 확인**으로 같은 작업의 복구 화면을 엽니다 |

충돌은 백업 재시도만으로 해결되지 않습니다. 검토한 병합본이나 복원 방향을 확인한 뒤 적용하며, 이전 로컬 기억과 원격 리비전은 보존합니다. 충돌을 풀었다고 미실행 세션 저장이 자동으로 실행되지는 않습니다.

조회가 실패하면 마지막으로 확인한 기억을 계속 표시하고, 새 조회가 성공할 때까지 쓰기를 보류합니다. 표시된 내용이 최신이라고 판단하지 마세요. 복구 화면을 여는 동작은 새 AI 실행과 다르며, 필요하면 별도로 **새 AI로 원인 조사 요청**을 선택할 수 있습니다.
