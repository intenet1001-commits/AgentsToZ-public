# AgentsToZ: 업무가 경험으로 남는 방법

AgentsToZ는 여러 프로젝트와 AI를 함께 운영하는 작업 공간입니다. **업무 스레드에서 일을 맡기고, 프로젝트 워크룸에서 실제로 처리하며, 다음에 쓸 경험을 프로젝트 기억에 남깁니다.** 프로젝트·포트·북마크 관리도 이 흐름을 돕습니다.

## 네 곳의 역할만 먼저 알아두세요

| 공간 | 쉬운 뜻 | 예시 |
|---|---|---|
| 사용자 운영 프로필 · AgentsToZ OPS 기억 | 나의 프로젝트 관계와 공통 운영 결정을 아는 운영 담당자 | “쇼핑몰은 판매 사이트 프로젝트의 별칭이다” |
| 업무 스레드 | 한 업무의 지시·질문·결과를 모으는 업무방 | “가입 버튼 오류를 고치고 검사해 줘” |
| 프로젝트 워크룸 | 해당 프로젝트 폴더에서 AI가 실제로 일하는 작업실 | 파일 수정, 명령 실행, 검사, 추가 승인 |
| 프로젝트 기억 | 다음 담당자에게 넘길 압축된 실무 경험 | 오류의 원인·수정 이유·검사 결과·다시 확인할 조건 |

OPS는 중간 운영 담당자입니다. 모든 일을 OPS를 거칠 필요는 없습니다. 프로젝트 워크룸에 직접 요청해도, 그 프로젝트에서 얻은 실무 지식은 해당 프로젝트 기억에 남기는 것이 기본입니다.

![업무 스레드에서 지시하고 프로젝트 워크룸에서 실행하며 프로젝트 기억을 다음 업무에 다시 쓰는 흐름](../images/work-and-memory-flow.svg)

## 첫 업무: 홈페이지 가입 오류 고치기

1. 앱에 `홈페이지` 프로젝트 폴더를 등록하고 사용할 Codex·Claude·Hermes·Antigravity 도구와 로그인을 준비합니다. 프로그램 준비와 AI 서비스 인증은 별도입니다.
2. **대화 세션 → 커뮤니티 · 업무 스레드**에서 실행할 기기 채널과 `@홈페이지`를 선택합니다. “가입 버튼 오류를 고치고 같은 문제가 안 생기게 검사해 줘”라고 업무를 맡깁니다.
3. 연결된 프로젝트 워크룸에서 AI가 실제 폴더를 확인하고 작업합니다. 추가 질문이나 승인 요청에 답합니다. 작업 정책과 프로젝트 권한이 그대로 적용됩니다.
4. 스레드의 프로젝트별 답변과 연결 워크룸에서 실제 변경·검증 결과를 확인합니다. **접수됨, 창 열림, 업무 완료는 서로 다른 상태**입니다.
5. 다음에도 필요한 원인·해결 방법·검사 결과를 프로젝트 기억에 저장합니다. 직접 **세션 기억하기**를 사용하거나, 별도로 동의해 켠 자동 저장을 사용합니다. 업무 종료 표시만으로 기억이 저장되지는 않습니다.
6. 다음 요청에서 “지난번 가입 오류 때의 방식을 참고해 줘”라고 합니다. 담당 AI는 프로젝트 기억을 회상하고 현재 코드와 맞는지 확인한 뒤 사용합니다.

Codex·Claude의 공개 완료 답변은 호스트가 관찰한 완료 기록에서 스레드로 수집합니다. Hermes·Antigravity는 명시적 결과 게시 경로를 사용합니다. 모든 터미널 출력이 스레드로 복사되는 것은 아니며, 긴 답변의 전체 내용은 연결 워크룸에서 확인합니다. [결과 수집 범위](../workroom-thread-results.md)

## 대화 기록과 메모리는 다릅니다

**대화 기록**은 당시 질문·답변을 다시 보거나, 확인된 같은 AI 대화를 이어 여는 자료입니다. **프로젝트 기억**은 설계 이유, 반복 문제, 사용자의 정정과 검증 결과처럼 다음 작업에 필요한 지식을 골라 정리한 자료입니다. 저장된 대화가 있다고 프로젝트 기억까지 완성된 것은 아닙니다.

‘실무처리자 메모리’는 특정 AI 계정 안에만 남는 기억을 뜻하지 않습니다. 프로젝트 로컬 파일이 정본이고, Codex·Claude 등 연결된 담당 AI가 이를 읽고 이어 쓰는 구조입니다. 저장소를 clone하는 일과 기억 리비전을 동기화하는 일도 구분합니다. 다른 기기에서는 같은 기억의 연결과 최신 상태를 확인해야 합니다.

| 기억 종류 | 남길 내용 | 관리 범위 |
|---|---|---|
| OPS 운영 기억 | 프로젝트 별칭·관계·공통 운영 결정 | 현재 사용자당 기본 프로필 하나. 공유 운영 폴더의 저장 후보는 사용자가 검토 |
| 프로젝트 기억 | 그 프로젝트의 설계·변경·검증·반복 문제 | 프로젝트별 분리. 세부 작업의 정본 |
| 공통 기억 | 여러 프로젝트가 함께 참고할 지식 | 독립된 기억 그룹을 필요한 프로젝트에 연결 |

현재 OPS 운영 기억을 모든 직접 프로젝트 지시까지 아우르는 CEO 기억으로 안내하지 않습니다. **CEO 업무 색인·추가 사용자 프로필은 설계 검토 단계**입니다. Mac의 **아젠투지 헬프데스크**는 프로그램 일괄 준비 → Codex·Claude 공식 인증 → 설치 마무리와 사용 질문을 연결하는 지원 창입니다. 실제 업무 실행과 실무 기억은 해당 프로젝트 워크룸에 둡니다. 기억은 AI 모델 자체를 재학습시키거나 모든 지식을 자동 합치는 기능도 아닙니다.

## 커뮤니티: 내 기기들이 모이는 작은 업무 공간

집과 사무실의 Mac을 같은 OPS에 연결하면, 승인된 기기별 채널에서 프로젝트를 골라 일을 맡길 수 있습니다. 공개 SNS가 아니라 **내 운영 프로필에 참여한 기기들의 업무 커뮤니티**입니다.

- `#사무실Mac`은 **실행할 기기**입니다.
- `@홈페이지`는 **실제로 일할 프로젝트**입니다.
- 본문의 `#프로젝트이름`은 참고 표시이며, 다른 프로젝트를 자동으로 실행하지 않습니다.
- 한 업무에 여러 프로젝트를 선택하면 프로젝트마다 독립 워크룸을 열고 질문·진행·결과를 같은 부모 스레드에서 확인합니다. 후속 답변을 보낼 프로젝트도 선택합니다.
- 일반 **아젠투지 단톡방** 대화는 AI에게 자동 전송되지 않습니다. 업무 대상을 선택하고 명시적으로 맡겨야 실행됩니다.

업무방에 참여했다고 모든 프로젝트의 파일·대화 기록에 접근할 수 있는 것은 아닙니다. 기존 기기·프로젝트별 권한과 작업 승인이 적용됩니다. [커뮤니티 사용 흐름](../community-workspace.md) · [다른 기기 OPS에 작업 맡기기](../cross-device-ops.md)

## 원격제어: 손에는 iPhone, 실제 작업은 Mac에서

iPhone에서 요청하고 질문에 답해도 파일 수정과 AI 실행은 연결된 Mac에서 이루어집니다. **Mac과 AgentsToZ 앱이 켜져 있어야 합니다.** 휴대폰에 개발 환경 전체를 다시 설치할 필요가 없습니다.

Mac의 원격제어에서 연결 방식을 선택한 뒤 iPhone 앱으로 QR을 읽고 로그인·기기 승인·프로젝트 허용 범위를 확인합니다. iPhone 앱의 QR·이메일 코드 연결과, Google 로그인·개인 웹 포털을 사용하는 브라우저 경로는 별도입니다. 공개 온라인 설명서는 읽기 전용 안내 페이지입니다.

같은 개인 Wi-Fi의 LAN 연결과 외부 인터넷 연결은 준비 방식이 다릅니다. 셀룰러 없는 iPhone도 Wi-Fi로 사용할 수 있지만, Wi-Fi를 끄면 인터넷 단절 검사일 뿐 외부망 전환이 아닙니다. 허용된 연결과 프로젝트 범위 안에서 사용하고 연결을 해제할 수 있습니다. [원격제어와 워크룸 계약](../runtime-execution.md)

## 필요한 기능부터 넓혀 가세요

처음에는 **프로젝트 하나 등록 → AI 하나 연결 → 업무 하나 완료 → 기억 저장**으로 시작하세요. 이후 프로젝트·포트·브라우저 미리보기, 기기 간 협업, 공통 기억, 선택형 음성, 북마크와 동기화를 추가할 수 있습니다. 로컬 앱 설치에 GitHub·Supabase·Vercel 계정이 모두 필요한 것은 아닙니다.

Mac은 [v1157 설치 안내](MAC-INSTALL.md), Windows는 [공식 설치 파일](https://github.com/intenet1001-commits/AgentsToZ-public/releases/latest)에서 시작합니다. 최신 공개 소스에 있는 기능과 플랫폼별 설치 파일의 제공 범위는 릴리스 안내를 확인하세요. [설치·연결 상세 안내](GUIDE.md) · [온라인 설명서](https://agentstoz-guide.vercel.app)
