# 통합 버전의 90점 품질 게이트

사용자 요구: 설정 개선, 사용자 프로필·사용자 지시 기억, 외부 에이전트의 자동저장 개선을 모두 포함한 버전으로 실기·페르소나 검증을 하고 성능·안정성·편의성을 개선한다.

이 표는 이번 프로젝트의 검증 기준이다. 각 항목은 아래 근거가 모두 있을 때만 배점하며, 미검증은 보류한다. 이전 설치본, 소스 fixture, 새 설치본의 결과를 합쳐 통합 버전 점수로 만들지 않는다. 총점 90점 이상이고 필수 게이트를 모두 만족해야 완료다.

## 필수 게이트

1. Mac 호스트·iPhone 네이티브·실제 웹 자산 각각의 버전/소스 지문과 지원 계약을 기록한다. 필요한 개선이 어느 구성요소에 들어 있는지 확인한다.
2. 실행한 체크·기기·제공자·페르소나·시작 상태·결과·측정 방법을 같은 영수증에 결속한다. UI 없는 소스 검사나 fixture 결과는 실기 통과가 아니다.
3. 데이터 유실, 권한/프로필 혼동, 중복 실행, 가짜 저장 성공, 핵심 여정 차단 문제가 남아 있으면 총점과 무관하게 보류한다.
4. Antigravity에 없는 공식 PreCompact 신호, Windows/Linux의 미지원 키 수명 등 실제 지원 한계를 성공으로 계산하지 않는다. 별도 동의를 자동 부여하지 않는다.
5. 실제 로그인·기기 grant·제공자 인증이 필요한 검사는 그 상태에서 실행한다. 테스트용 원본·프로필은 개인 원본과 격리한다.

## 개선 루프와 측정

기준 버전 측정 → 재현과 원인 확인 → 수정 → 관련 계약/화면 검사 → 통합 설치본의 같은 여정 재검증 순서를 반복한다. 검사 기준을 낮추거나 테스트를 삭제해 점수를 올리지 않는다. 새 실패가 없고 관련 검사가 통과하면 의미 없는 전체 재실행을 반복하지 않는다.

기기 성능은 워밍업/표본 수/네트워크/시작 상태를 기록한다. 반복 상호작용은 20회 이상 측정하고 p50/p95/최댓값을 남긴다. Appium 명령 왕복·XCTest idle·전체 AX snapshot을 포함한 시간은 별도 진단 지표다. 이를 순수 렌더링 지연으로 계산하거나 임의로 보정하지 않는다. 같은 실제 기기의 앱 내부 계측 또는 화면 기반 측정이 없으면 해당 성능 항목은 보류한다.

합성 회귀 지표는 실제 AI/기기 지연과 분리한다. 예를 들어 같은 실패 턴의 dispatch 2→1은 그 재현에서의 중복 제거를 뜻하며 전체 비용 50% 절감을 뜻하지 않는다.

## 현재 판정

Mac 1209에서 Hermes의 시작 오류 수정과 실제 응답을 확인했다. 후속 요청은 40ms 뒤 Enter가 CLI의 50ms 붙여넣기·음성 입력 보호 구간에 들어가 입력칸에 남는 추가 결함을 재현했다. 후속 소스는 Hermes만 150ms 정착 후 Enter 한 번을 보내며, 요청이나 Enter를 자동 재전송하지 않는다. 이 수정의 설치본 후속 요청·압축 전 복구 검증 전에는 통과로 계산하지 않는다.

같은 실기에서 Hermes의 첫 주기 저장에 사용자 행만 포함되고 120초 제한 때문에 직후 완료 응답이 빠지는 공백을 확인했다. v32는 같은 세션의 assistant 행이 없으면 주기 요청을 보내지 않고, SQLite 영속화 뒤 성공·비중단이 명시된 완료 훅에서 첫 응답을 보존한다. 기존 주기 제한·동의·원본 검증을 유지하며, session ID 없는 턴 밖 수동 압축을 안전한 신호로 추정하지 않는다. Antigravity는 실제 완료 답변의 자동 암호화·UI readback을 확인했으나 정확한 사용률/PreCompact 보장은 여전히 없다.

Mac 1207(공개 소스 9d3f2c8b)을 공식 서명·공증·설치한 뒤 Claude의 실제 약 834KiB 로그에서 자동 암호화 영수증과 화면의 원문 읽기로 테스트 답변 복원을 확인했다. 수동 `/compact` 뒤에도 같은 영수증을 재사용했고 CORE는 바뀌지 않았다. 새 Hermes 실기에서는 사용자 TUI 기본값이 시작 `--reasoning`을 거절하는 실행 호환성 결함을 발견해 후속 소스에서 해당 실행만 classic CLI로 지정한다. 이 수정의 설치본 검증과 iPhone TestFlight 1205 업데이트 실기 전에는 통합 90점으로 판정하지 않는다.

Mac 1205는 공개 소스 613f9039에서 서명·공증·설치 후 144개 프로젝트, 같은 운영 프로필과 기억 원본 보존을 확인했다. 실제 관리 계정으로 Google Provider·iPhone 복귀 주소의 기존 등록과 변경 없는 검토도 확인했고 iOS 1205는 기존 TestFlight 내부 그룹에 등록했다. Claude 실기에서 약 1.1MiB 기록의 훅 로그가 256KiB 탐색 범위를 넘는 추가 실패를 확인해, 후속 소스는 Claude 탐색을 2MiB로 제한하고 압축 요약·로컬 명령 출력을 제외한다. 이 수정의 설치본 암호화 readback과 iPhone 업데이트 실기는 아직 남았으며 1205를 통합 완료로 판정하지 않는다.

후속 통합 소스에서 저장 영수증에 근거한 70% 안내, 네 에이전트의 복구 조각 안내, Google Console 단계별 설정 및 Supabase Google Provider의 검토·동의·중복 방지 흐름을 검증 중이다. Mac 1203 실기에서는 Codex 압축 전 조각의 복원은 확인했으나 Claude 조각에 훅 로그가 대화를 밀어내는 결함을 재현했다. iPhone 1170에서는 데이터 연결로 전환한 뒤 기존 웹 제어 연결을 다시 고르기 어려운 문제도 확인했다. 두 수정은 아직 새 설치본의 재검증을 기다리므로 해결 완료·90점으로 계산하지 않는다. 소스 검증 도중 결함을 발견해 중단한 전체 검사는 통과로 집계하지 않는다.

Mac 1200은 공개 소스 a6353708에서 Developer ID 서명·공증·설치까지 완료했다. 실제 앱의 기기·프로젝트·프로필 연결을 보존했고, TestFlight 1170 내장 화면의 이메일 로그인과 Mac 선택도 유지됐다. 동일 iPhone의 로그인된 화면에서 20회 탭 지연 p50 44ms / p95 77ms, background 복귀 3회와 cold reopen 후 로그인·선택 Mac·QA 프로젝트 보존을 확인했다. 이 수치는 페이지 내부의 tap→두 animation frame 계측이며 AI 지연이나 전체 작업 여정의 INP가 아니다. cold reopen의 FCP 130ms도 유효 프로젝트 목록 완료 시간을 뜻하지 않는다.

실제 Codex·Antigravity의 QA 응답은 확인했고, Claude 입력 예시 처리 오류는 후속 소스에서 수정했다. Hermes는 현재 선택된 Anthropic 자격 증명이 없어 실제 응답을 확인하지 못했다. 제공자 훅 허용·별도 원문 보관 동의, 실제 압축 전후 readback, 새 모바일 화면이 포함된 TestFlight 빌드는 남았다. 후속 Google 집중 온보딩·Claude 입력칸·원문 보존 어댑터 업데이트는 일반 20/20, 전체 Python 131·TypeScript 0 errors·Bun 7,918 pass/10 skip/0 fail·Rust 96 pass, 16개 페르소나의 중복 제거 검사 71/71을 통과했다. 공식 설치본 재검증을 이어간다. **통합 버전의 점수/90점 도달 판정은 보류**다. 실제 증거와 미검증 경계를 합쳐 통과로 계산하지 않는다.
