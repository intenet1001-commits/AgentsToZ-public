# 같은 프로젝트의 DEV·USE 실행 문맥

DEV는 제품 개발, USE는 준비된 제품 사용·운영, AgentsToZ OPS는 전체 관제다.
업무 스레드·워크룸·음성·MCP·Buzz·Hermes·Telegram은 연결 채널이다.
프로젝트 등록 `role`을 일괄 변경하거나 별도 USE 프로젝트·작업폴더를 만들지 않는다.

## 호출과 실행

`@프로젝트 DEV`, `@프로젝트 개발`, `@프로젝트 USE`, `@프로젝트 운영`은
공통 대상 해석기에서 `executionRole`을 돌려준다. 등록 역할과 실행 역할은 별개다.
기존 OPS/DEV 별칭과 정확한 프로젝트 이름은 우선 보존한다. 역할을 생략한 기존 호출과
기존 스레드는 DEV 계약을 유지한다. 동명 프로젝트와 모호한 서비스는 임의 선택하지 않는다.

업무 스레드는 최초 요청에 제한된 `use` 호출이 있을 때만 USE 문맥을 만든다.
후속 요청은 같은 서비스·원래 사용자의 같은 실행 결속을 유지하며, 기존 DEV 스레드를
USE로 바꾸는 요청은 거부한다. 역할을 바꾸려면 새 문맥을 만든다. 현재 USE 스레드는
제품 하나를 대상으로 하며 복수 프로젝트 공동 USE 업무는 지원하지 않는다.

`ServiceUseHost`의 결속은 프로젝트·serviceKey·USE memoryId·사용자·보관함·기기·설치·
운영 정의 revision·권한 revision·허용 도구를 포함한다. 실행 직전에 다시 확인한다.
프롬프트나 JSON 도구 목록은 어댑터 등록 권한이 아니다. 설치 호스트 코드가 제공한
검증된 앱 어댑터만 실행하며, 실제 앱도 같은 결속을 작업과 상태 조회·취소 시 원자적으로
검사해야 한다. 일반 앱 USE에 임의 셸이나 관제 MCP 전체를 주지 않는다.

현재 경로는 로컬 관리 API `/api/service-memory/execute`, 원래 ID 조회 `receipt`,
OPS MCP `agentstoz_use_service_operation`, 음성 `operate_product`, 업무 스레드다.
음성은 명시적인 USE 역할 선택이 필요하다. 역할 변경 시 기존 DEV 초안과 진행 중인
USE 호출의 권한 확인 함수가 무효가 된다. 채널이 프로젝트 grant를 확대하지 않는다.

앱 쓰기 전에 요청 의도를 암호화 SQLite에 저장한다. 같은 ID·같은 의도는 기존 영수증을
반환하며 다른 입력은 거부한다. 재시작·연결 유실·미확정 결과를 새 실행으로 추정하지 않는다.
자료 생성, 음성 준비, 전송, iPhone 수신 근거는 별도 필드다. 앱 작업 완료가 기억 저장을 뜻하지 않는다.

## 기억 정본과 복구

DEV의 `.agent-memory/config.json`, memoryId, sourcePath와 기억 계보는 보존한다.
USE는 `.agent-memory-use/<serviceKey>/config.json`과 `CORE.md`를 사용한다.
기존 `(DEV memoryId, serviceKey)` 기반 USE memoryId와 내용도 유지한다.
워크룸의 `USE 준비`에서 해당 프로젝트 DEV의 연결 구현 요청을 준비하고, 기억 화면의 `USE 활성화·준비`에서도 같은 흐름을 제공한다. Buzz는 프로젝트의 기존 앱 열기 흐름을
사용하며 별도 고급 설정 진입점을 만들지 않는다. 기존 연결과 기억은 보존한다.

`USE 활성화·준비`에서 명시적으로 기억 준비를 실행하면 다음 순서로 전환한다.

1. 등록 프로젝트·기억·경로·원본 파일을 확인하고 기존 registry 잠금을 잡는다.
2. 원본 hash와 전환 ID를 가진 `project-authority.v1.json`을 `prepared`로 저장한다.
3. 프로젝트 USE namespace의 파일을 준비하고 원본 hash를 다시 확인한다.
4. 기존 파일은 `.pre-project-v1` 복구 사본으로 보존하고, 구경로는 정본 파일의 호환 링크로 바꾼다.
5. registry의 정본을 바꾼 뒤 같은 전환 기록을 `committed`로 확정한다.

중단된 전환은 실행 준비 상태가 아니다. 같은 준비 동작이 같은 전환을 검증·재개한다.
기존 내용과 충돌하거나 등록되지 않은 namespace가 있으면 덮어쓰지 않는다.
DEV 파일을 가리키는 심볼릭 링크·하드링크, 변조된 호환 링크·복구 사본도 거부한다.
구버전 Buzz가 호환 링크 자체를 원자적 교체하면 준비 검사가 실패한다. 쓰기 전에 실제
정본 경로를 해석해야 하며 프롬프트 안내 자체를 OS 권한 격리로 간주하지 않는다.

현재 USE 내용은 단말 로컬이다. namespace 안의 `.gitignore`가 일반 소스 커밋에서 기억을
제외하며 기존 프로젝트의 Git 설정은 변경하지 않는다. 강제로 추적한 기억도 공개 snapshot에서
제외한다. 별도 원격 동기화나 사용자별 자료 격리는 완성되지 않았다.
현재 스레드의 DEV 세션 기억하기·DEV 자동 저장 동의는
USE에 적용하지 않는다. USE 자동 요약 저장·백업은 아직 연결하지 않았으며 완료로 표시하지 않는다.

## 제품 설치와 현재 한계

활성화, 기억 준비, 도구 검증, 환경·운영 권한, 실제 실행 준비를 각각 표시한다.
현 개발용 준비 경로는 등록 프로젝트의 DEV identity를 재사용한다. 일반 고객용 제품은
검증된 설치 identity와 앱 운영 정의에서 시작해야 하며 소스·Git·DEV 기억 생성이 전제여서는 안 된다.
이 변경은 고객용 설치 등록·공용 서비스 배포를 완성하거나 `managed execution=false`
제한을 해제하지 않는다. 공용 관리자 키를 전달하지 않는다.

ShadowLoop는 앱의 `AI 운영 연결`에서 발급한 프로필별 코드를 기존 `USE 활성화·준비`에
등록하면 설치 코드의 어댑터를 연결한다. 연결 전에는 계속 도구 초안으로 표시한다.
[앱 연결 계약과 확장 방법](service-use-integration.md)을 따른다. 연결 코드와 작업 영수증은
서로 다른 암호화 저장소이며, 연결·재시작·결과 조회는 앱 작업을 자동 재전송하지 않는다.
준비 UI나 격리된 SQLite·합성 화면 검사의 성공은 실제 설치 앱·물리 iPhone 수신 성공이 아니다.

## 검증

기존 `workroom-improvement` 정상 프로필에 타입 검사, USE·기억 전환·음성·MCP·Buzz 계약과
기존 업무 스레드 회귀·Chromium/WebKit 화면 검사를 연결했다.
`service-use-screen`은 실제 React·호스트·암호화 저장소와 합성 앱 어댑터를 쓴다.
실제 AI·ShadowLoop 엔진·물리 iPhone은 사용하지 않는다. USE 회귀는 기본 `quick`에도 포함한다.
기존 페르소나 카탈로그의 실행과 신규 역할 후보 검토는 별개다.
